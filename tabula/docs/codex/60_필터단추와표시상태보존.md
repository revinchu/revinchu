# 60. 필터 단추와 표시 상태 보존

기준: `5069846`. 이 문서는 필터 단추 표시와 필터 삭제를 분리한 변경, 표 요약행 보존, 관련 표시 옵션의 독립 감사 범위를 기록한다. 최종 번들 검증은 아래 통합 검증 표에 기록하며 배포 식별자는 `.local/filter-display-release.json`에 남긴다.

## 사용자 문제와 변경 범위

표 디자인의 **필터 단추**를 끄면 기존에는 `table.filter` 자체가 사라졌다. 단추만 감추려던 동작이 조건과 숨긴 행을 제거하는 결과를 냈다. 이제 `filter.hiddenButtons`에 시트의 절대 열 번호별 표시 상태를 저장하고, `criteria`·`hidden`·`sort`는 유지한다. 단추를 다시 켜면 같은 조건을 다시 사용할 수 있다.

표의 표시 서식과 단추 표시 변경은 계산 중립 이력으로 처리한다. 가져온 수식의 파일 저장값을 표시 변경만으로 버리지 않으며, Undo/Redo로 표시 상태를 복원한다. 표 범위를 늘리거나 줄일 때도 모든 단추를 숨긴 상태를 새 열 범위에 맞춘다.

**머리글 행 숨김**과 **필터 단추 숨김**은 별개다. 합성 Excel에서 `ShowHeaders=false`는 AutoFilter를 끄고 조건·숨긴 행을 해제했으며, 다시 켜도 조건을 되살리지 않았다. 따라서 머리글 숨김 경로의 필터 해제를 이번 결함과 혼동해 바꾸지 않는다. 필터 자체를 해제하는 명령도 단추 표시 변경과 구분한다.

주요 구현은 `src/filter-display.js`, `Workbook.setTableFilterButtons()`, `src/app.js`의 `toggleTableOption()` 및 격자 필터 단추 렌더링이다. XLSX의 표/일반 범위 필터는 `src/xlsx-filter.js`의 공통 읽기·쓰기 경로를 사용한다.

## 요약행 숨김과 복원

독립 감사에서 요약행을 껐다 켜면 사용자가 지정한 평균·사용자 수식·라벨이 기본 합계와 ‘요약’으로 바뀌는 별도 결함을 재현했다. 실제 Excel은 요약행이 숨겨진 동안에도 함수·라벨·사용자 수식을 기억했다.

`setTotals()`는 숨길 때 기존 `totalsFns`를 유지하고 `totalsCells`에 요약행의 `cellData`를 보관한다. 키는 시트의 절대 열 번호이며, 명시적으로 빈 칸도 `null`로 기록한다. 다시 켤 때 이 내용을 복원하고, 보관 내용이 없는 새 요약행에서만 기존 기본 합계를 만든다. 숨긴 자리에 사용자가 다른 내용을 입력했다면 행을 삽입해 그 내용을 보존한다. 각 표시 전환은 하나의 Undo 작업이다.

- 앱 내부 숨김/복원은 수식·문자·숫자 형식·직접 서식 등 `cellData`를 보존한다.
- 숨긴 동안 원본 값이 바뀌면 복원한 수식은 최신 값으로 계산한다.
- 행·열 삽입/삭제, 셀 이동 및 시트/표 이름 변경에서는 숨긴 수식과 열 키도 구조 변경을 따라간다. 문자 라벨을 수식으로 바꾸지 않도록 입력 자료형과 텍스트 서식·`fx`를 함께 구분한다.
- XLSX는 숨긴 요약행도 표준 `tableColumn`의 `totalsRowFunction`, `totalsRowFormula`, `totalsRowLabel`로 저장한다. 직접 덮어쓴 수식·라벨과 기존 함수 메타가 다를 때 실제 셀 내용을 우선한다. 빈 요약 칸과 `=`로 시작하는 문자 라벨도 구분한다.
- 숨긴 총계를 다시 켤 때 Excel이 기본 합계로 덮지 않도록 `totalsRowShown`의 사용 이력과 현재 `totalsRowCount`를 구분한다. 빈 총계도 이미 사용한 상태로 기억한다.
- XLSX는 `totalsRowDxfId`로 글꼴·채움·패턴·그라데이션·테두리·숫자 형식을 보존한다. 현재 DXF 쓰기 경로의 정렬·줄바꿈·보호와 숨긴 메모 보존은 이번 범위에 포함되지 않으며 앱 내부 전체 `cellData` 보존과 구분한다.

기본 `banded`가 생략된 표는 줄무늬가 켜진 상태로 표시된다. 이 상태의 첫 클릭이 다시 `true`를 쓰던 문제도 표시 기본값과 일치하도록 보완한다.

## 네이티브 Excel 확인

개인 문서와 기존 Excel 세션을 사용하지 않고, 별도로 생성한 합성 통합 문서를 새 숨김 COM 인스턴스에서 확인했다. 관측 버전은 Excel 16.0, 빌드 14334다.

- `ShowHeaders` OFF는 AutoFilter 및 조건·행 숨김을 해제하고 ON 시 복원하지 않았다.
- `ShowTotals` OFF/ON은 합계·평균, 두 필터 조건, 네 숨긴 행과 정렬을 유지했다.
- 사용자 요약행도 OFF 상태에서 `TotalsCalculation` 값 `[0,0,2,9]`를 유지했고, ON 후 라벨·평균 `SUBTOTAL(101,…)`·사용자 `SUM([Double])+7`을 복원했다.

기본 관측은 `D:/Codex/Temp/wixel-filter-display/native-results.json`, 사용자 요약행 관측은 `native-extra-results.json` 및 `totals-custom-before.xlsx`, `totals-custom-off.xlsx`, `totals-custom-on.xlsx`에 보관한다. 이는 위 속성과 합성 데이터의 실측이며 모든 Excel 버전·OS·표 구조를 검증한 것은 아니다.

## 남은 확인 경계

슬라이서 `hideNoData` 설정 자체는 이번 합성 감사에서 조건을 지우지 않았다. 다만 다른 열의 조건으로 항목 하나만 남은 상태에서 이후 그 항목을 클릭하면, `slicerPick()`이 표시용으로 좁혀진 항목 목록을 전체 집합으로 사용하여 자기 열 조건을 생략한다. `hideNoData=false`일 때 같은 항목을 클릭하면 명시 조건을 저장한다.

이 차이가 네이티브 Excel의 슬라이서 캐시 선택 의미와 다른지는 이번에 확인하지 않았다. 따라서 확정 결함 또는 설정 전환의 데이터 삭제로 단정하지 않는다. 후속 완료 기준은 동일한 교차 필터 합성 표/슬라이서를 Excel에서 만들고, 한 항목 선택 전후 캐시 선택과 다른 조건 해제 후 결과를 비교하는 것이다. 이번 릴리즈에서 추측으로 선택 정책을 바꾸지 않는다.

일반 목록·공란, 숫자/텍스트 사용자 조건·AND/OR, 상위/하위·백분율·평균, 채움/글꼴색 필터와 정렬을 표준 XLSX로 저장한다. 날짜 그룹·아이콘·기타 동적 필터는 원형과 숨긴 행을 보존하고 미지원 조건이 남은 재적용·정렬을 안내와 함께 막는다. 이는 미지원 조건의 완전한 UI·재계산 구현을 뜻하지 않는다. 표준 표현이 없는 정규식 조건은 조건을 버린 파일을 만드는 대신 저장 시 명시 오류로 알린다.

행의 수동 숨김과 필터 숨김이 동시에 기록된 원본 XLSX는 해당 구분에 별도 메타가 없어 기존 가져오기 한계가 남는다. 실제 iPhone Bluetooth 장치는 이번 검증에 포함하지 않았다.

## 회귀 도구와 실행

`tools/table-totals-preservation.mjs`는 새 격리 브라우저에서 합성 문서만 사용하며 외부/API/쓰기 요청을 차단한다. 실제 파일 선택기 입력에는 합성 XLSX 바이트만 넣는다.

```powershell
$env:WIXEL_URL='http://127.0.0.1:5191/'
$env:WIXEL_BROWSER='chromium'
$env:WIXEL_TOTALS_OUT='D:/Codex/Temp/wixel-table-totals/source'
node tools/table-totals-preservation.mjs
```

`WIXEL_BROWSER=webkit`도 지원한다. `WIXEL_TOTALS_FILTER`는 시나리오 이름 일부로 검사를 제한한다. Playwright 모듈/브라우저 캐시는 기존 프로젝트 실행 환경을 사용하며 의존성을 추가하지 않는다.

소스 최초 검증은 **8/8 시나리오·52검사**, 페이지 오류·원격 쓰기 0이었다. 평균/사용자 수식/라벨/직접 서식, 명시 빈 칸, 이전 `totalsFns`만 있는 파일, 새 요약행 기본값, 숨긴 동안의 값 변경, 복원 위치에 입력한 사용자 내용, 보호, Undo/Redo, 숨긴 XLSX 저장 후 실제 다시 열기를 포함한다. XLSX 생성은 도구가 import한 로컬 `src/xlsx.js`를 사용하며, `WIXEL_URL`의 앱으로 다시 연다. 번들 검증 시에도 이 구분을 유지한다.
