# 56. iPhone 마우스 손바닥 이동

2026-10-03. 기준 커밋 `8b620c58613bdd7fcf6605a31db94db5ddfea14a`.

## 재현과 수정

기존 구현은 `mousedown`에서만 두 버튼 조합을 시작하고 `mousemove`에서만 이동했다. 첫 이벤트의 `buttons=3`도 명시적으로 제외했다. Pointer Events에서는 두 번째 버튼이 추가 `pointerdown` 대신 `pointermove`로 전달될 수 있고, 호환 Mouse Events를 받는다는 보장이 없으므로 이 경로에서 이동이 시작되지 않았다. 정지 상태 첫 버튼을 300ms 누른 뒤 두 번째 버튼을 누르는 것은 기존에도 작동했으며 시간 제한 결함으로 기록하지 않는다.

- 첫 `pointerdown`부터 후보를 관리하고, `pointermove.buttons=3`, 첫 이벤트 `buttons=3`, 기존 Mouse Events를 같은 상태에 연결했다. 같은 좌표의 호환 이벤트는 추가 이동량이 0이다.
- 셀 클릭/체크박스/그리기보다 조합 여부를 먼저 판정한다. 두 버튼 이동 중 선택, 서식, 값, 실행 취소 이력은 바꾸지 않는다.
- 조기 우클릭 메뉴 뒤 두 버튼이 전달되는 경로도 메뉴를 닫고 이동하며, 캐시한 이벤트는 동일 시트에서만 사용한다.
- 상단 `☰` 옆 **손바닥 이동** 버튼을 추가했다. 모바일 모드에서 켜고 왼쪽 버튼만 누른 채 끌면 두 축으로 이동한다. 터치로 변환된 입력과 Touch Events 경로도 지원한다. 버튼 재클릭·Escape로 해제하고, 모바일 모드를 끄면 해제·숨김 처리한다. 이 상태는 통합 문서에 저장하지 않는다.
- 시스템 포인터가 CSS `cursor` 모양을 반영하지 않더라도 이동 상태를 볼 수 있도록 실제 SVG 손 아이콘을 화면에 표시한다. 아이콘은 클릭을 가로채지 않는다.
- 한 버튼 해제, pointercancel/touchcancel, 창 포커스 이탈, 시트 변경 시 진행 중 이동을 중단한다. 다음 클릭/터치/키보드 조작은 정상 경로로 복귀한다.
- 이미 일반 범위 선택/그리기 드래그로 넘긴 제스처를 도중에 손 이동으로 바꾸지는 않는다. 두 버튼을 먼저 누르거나 손바닥 버튼을 켠 다음 끈다. 진행 중인 개체 편집/선택 확정과의 충돌을 피하기 위한 경계다.

## 플랫폼 근거와 범위

[W3C Pointer Events의 버튼 조합 규칙](https://www.w3.org/TR/pointerevents3/#chorded-button-interactions)과 [호환 Mouse Events 규칙](https://www.w3.org/TR/pointerevents3/#compatibility-mapping-with-mouse-events)을 따른다. [Apple의 AssistiveTouch 포인터 기기 문서](https://support.apple.com/en-ie/111775)는 마우스 버튼에 OS 동작을 지정할 수 있음을 설명한다. OS가 보조 버튼을 웹에 전달하지 않는 경우 페이지 코드로 이를 감지할 수는 없으므로, 같은 손 이동을 한 버튼으로 실행하는 명시적 모드를 제공한다.

실제 사용자의 iPhone/Bluetooth 이벤트 스트림을 이 환경에서 수집하지 않았다. Chromium 및 데스크톱 WebKit의 입력/화면 모의와 실제 기기 검증은 구분한다. 브라우저별 검사 결과는 아래에 기록한다.

## 검증 도구

`tools/mobile-hand-pan.mjs`는 원격/API 쓰기를 차단한 합성 문서에서 Pointer-only 조합, 호환 Mouse 중복, 조기 contextmenu, 직접 buttons3, 지연 조합, 양버튼 해제/취소/시트 전환, 가상 셀 교체, 명시 손 도구와 SVG 표시, 일반 선택 유지 등을 검사한다. `WIXEL_URL`은 로컬 소스/번들 서버, `WIXEL_HAND_PAN_OUT`은 D: 출력 경로를 지정한다. 키보드로 버튼을 실행하면 기존 앱 명령 계약대로 격자로 초점이 돌아오므로, 다음 키보드 버튼 실행은 그 버튼에 초점을 다시 둔 상태에서 검사한다.

검사 산출물은 `D:/Codex/Temp/wixel-mobile-hand-pan/`, `D:/Codex/Temp/wixel-iphone-hand-pan/` 및 무시되는 `.local/`에 두며 합성 자료만 사용한다. 스크롤 값 비교는 브라우저 프레임 반영 후의 정착 위치를 기준으로 삼는다. WebKit 소스 중간 검사 1건에서는 네이티브 스크롤 반올림이 반영되기 전 값을 읽어 화면 1px 차이가 발생했으며 최종 번들 전체 24개 검사에서는 통과했다.
