# 29. 홈 화면 아이콘

## 원인과 변경

기존 HTML에는 data SVG 파비콘만 있고 Apple touch icon, web app manifest, 실제 앱 PNG/ICO 파일이 없었습니다. 생성 이미지로 전용 WIXEL 아이콘을 만들고 홈 화면 등록 정보와 연결했습니다.

- `icons/wixel-192.png`, `icons/wixel-512.png`: 안드로이드·일반 앱 아이콘.
- `icons/wixel-maskable-512.png`: 둥근 사각형·원형 마스크에 잘리지 않도록 중앙에 표시한 W 마크.
- `apple-touch-icon.png`: 아이폰·아이패드용 180×180 PNG.
- `favicon-32x32.png`, `favicon.ico`: 브라우저 탭 및 북마크. ICO는 16/32/48 크기를 포함합니다.
- `manifest.webmanifest`: 앱 이름, 시작 경로, 독립 실행 화면, 테마 색, 아이콘 선언. 서비스 워커나 오프라인 캐시는 추가하지 않습니다.

모든 아이콘은 불투명한 초록색 바탕입니다. 이미지 생성 결과의 구도는 변경하지 않고 플랫폼별 규격으로 크기와 파일 형식만 내보냈습니다. 런타임 의존성은 추가하지 않았습니다.

## 생성 기록

내장 `image_gen` 사용. 초록색 바탕, 큰 흰색 W, 민트색 셀 포인트, 모서리를 시스템이 자를 수 있는 여백, 작은 크기에서도 읽히는 단순한 형태로 요청했습니다. 전체 생성 프롬프트는 `assets/branding/home-icon-prompt.txt`에 기록합니다. 최종 배포용 원본은 `icons/wixel-512.png`이며 고해상도 생성본은 로컬 `.local/wixel-home-icon-master.png`에 별도 보관합니다.

## 검증과 사용

소스 및 두 빌드의 링크·manifest·파일 복사·크기·MIME를 확인하고 공개 자산과 검증된 로컬 파일 해시를 대조합니다. 브라우저의 앱 manifest 분석과 이미지 디코딩을 확인합니다. 실제 iOS/Android 기기의 홈 화면 등록 화면 확인은 별도입니다.

업데이트 후 사이트를 새로고침하여 홈 화면에 추가합니다. 이미 등록한 바로가기에 예전 아이콘이 남으면 작업을 파일로 저장한 뒤 바로가기만 삭제하고 다시 등록합니다. 사이트 데이터 삭제는 필요하지 않습니다.

참고: [Apple 홈 화면 아이콘](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html), [웹 앱 manifest](https://web.dev/articles/add-manifest), [아이콘 마스크](https://developer.chrome.com/docs/lighthouse/pwa/maskable-icon-audit).


최종 검증: Node 652/652, 명령 스모크 324개 오류 0, `tools/home-icons.mjs` 소스/배포 번들 각각 11/11 통과. manifest 파싱 및 설치 가능성 오류 0, PNG 크기·불투명도·ICO 16/32/48 프레임·SHA256 동일성 확인. 원형 마스크의 중심 반지름40% 안전 영역 안에 흰색/민트 전경이 모두 들어가는지 픽셀 검사했습니다. 실제 OS 설치 화면 검증과는 구분합니다.
