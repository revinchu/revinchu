# 슬라이서 리본과 배치

2026-10-03. 슬라이서 전용 리본의 캡션·스타일·배치·치수 조작과 표준 XLSX 그룹 보존을 보강했다. 기존 표/피벗 필터, 보고서 연결, 사용자 지정 스타일을 계속 사용한다.

## 리본과 선택

- 캡션, 슬라이서 설정, 보고서 연결, 미리 보기가 있는 스타일 갤러리와 전체 갤러리를 제공한다. 여러 슬라이서에 같은 스타일과 치수를 한 번에 적용하며, 서로 다른 치수는 입력 칸을 빈 값으로 표시한다. 보고서 연결과 캡션처럼 한 대상이 필요한 조작은 다중 선택에서 비활성화한다.
- 앞/뒤 및 맨 앞/뒤 순서, 선택 창, 수평·수직 6방향 맞춤, 가로·세로 간격 배분, 눈금·도형 맞춤, 눈금선 보기를 연결한다. 맞춤은 2개, 간격 배분은 3개 이상의 개체 또는 그룹을 대상으로 한다.
- 순수 슬라이서 그룹은 함께 선택·이동·크기 조절·정렬·복사·삭제한다. 복사본에는 새 개체 ID와 새 그룹 ID를 부여한다. 그룹 해제는 기존 슬라이서와 필터 원본 연결을 유지한다. 드래그 초안은 Escape로 취소하며 완료한 변경은 한 번의 Undo로 복원한다.
- 입력 대상인 통합 문서·시트·선택이 바뀌면 오래된 리본 입력을 적용하지 않는다. 읽기 전용·보호·이동 금지 상태를 적용할 때 다시 확인한다.

## 치수 모델과 단위

저장 모델의 `x/y/w/h/buttonHeight/gap`은 CSS px이며, 리본의 단추 높이·너비 및 전체 높이·너비는 cm다. 변환은 `cm = px × 2.54 / 96`, Excel COM의 point는 `px × 72 / 96`을 사용한다. 화면 배율은 이 저장 치수를 바꾸지 않는다.

`src/slicer-properties.js`의 `slicerDimensions(sl)`은 현재 표시 치수를 반환하고, `slicerDimensionPatch(sl, kind, value)`는 입력을 검증한 변경분을 반환한다. `kind`는 `columns/buttonHeight/buttonWidth/w/h`이며 `columns` 외의 입력은 cm다. 원본 개체를 직접 변경하지 않고 유효하지 않은 값은 오류로 거부한다.

- 열 수는 1~20,000의 정수다. 열 수 변경은 전체 너비를 유지하고 각 단추 너비를 다시 계산한다.
- 단추 너비 변경은 열 수를 유지하고 전체 너비를 늘리거나 줄인다. 기본 간격 3px에서 `전체 너비 = 단추 너비 × 열 수 + 3 × (열 수 − 1) + 18`이다. 18px는 좌우 여백·테두리 12px와 스크롤 공간 6px다. 이 관계는 합성 파일의 실제 Excel 측정과 대조했다.
- 단추 높이는 전체 높이와 독립적이다. 기본 단추 높이는 24px이며 XLSX `rowHeight`는 1px당 9,525 EMU로 저장한다. 소수 치수는 EMU 정밀도로 보존한다.
- 전체 최소 크기는 80×56px, 치수 입력의 상한은 20,000px다. 그룹 전체 크기 변경은 각 구성원의 위치·크기를 비례 조정하고, 어느 구성원도 최소 크기 아래로 줄이지 않는다.
- cm 표시값은 소수 둘째 자리로 반올림하지만, 같은 표시값을 다시 확정하는 것만으로 원래 정밀도를 잃지 않는다. 이전 문서의 명시적 `buttonWidth`는 유지하다가 사용자가 관련 너비나 열 수를 바꾸면 새 계산 규칙으로 전환한다.

## XLSX 그룹 보존

모델은 `sheet.slicers`의 평면 목록을 유지하고 같은 문자열 `objectGroup`으로 구성원을 연결한다. XLSX는 한 `xdr:grpSp` 아래에 표준 슬라이서 `graphicFrame`들을 기록한다. 그룹의 `off/ext/chOff/chExt`와 자식 좌표를 읽어 각 슬라이서의 시트 좌표로 복원한다. 따라서 그룹 안에서도 표/피벗 원본, 캡션, 스타일, 단추 높이, 대체 텍스트와 매크로 이름을 유지한다. 매크로 이름 보존은 VBA 실행 지원을 의미하지 않는다.

숨긴 구성원과 그룹의 숨김 상태를 읽으며, 표준 그룹이 없는 단일 슬라이서와 그룹 해제 후에는 기존 개별 앵커를 사용한다. 그룹에 한 구성원만 남았으면 단일 슬라이서로 저장한다.

이번 지원은 **슬라이서끼리의 그룹**이다. 일반 도형·그림과 슬라이서를 섞은 그룹 편집은 제공하지 않는다. 중첩된 순수 슬라이서 그룹은 하나의 평면 그룹으로 복원한다. 슬라이서 회전은 실제 Excel에서 거부되는 것을 확인하여 리본에서 비활성화한다.

그룹은 하나의 DrawingML 앵커를 공유하므로 위치 속성(`placement`), 시트 잠금 연동(`locked`), 인쇄 제외(`noPrint`)도 공통으로 사용하는 것이 보존 가능한 범위다. 서로 다른 값의 그룹을 저장할 때 위치 속성은 첫 구성원, 잠금 해제·인쇄 제외는 모든 구성원이 해당할 때만 그룹 앵커에 기록한다. 혼합된 개별 앵커 속성을 완전히 보존한다고 보장하지 않는다. 시간 표시 막대와 외부 OLAP 슬라이서 전체의 동등성을 이번 검증 범위에 포함하지 않는다.

## 확인한 검증

- 치수·원본 불변·잘못된 입력·20,000열 경계·소수 EMU 왕복·그룹 좌표·숨김·대체 텍스트·매크로·단일 구성원 저장 회귀를 추가했다. `slicer-dimensions.test.js`와 기존 `slicer-properties.test.js`는 16/16, 파일 충실도·SmartArt 그룹 회귀를 합친 관련 검사 43/43이 통과했다.
- 별도의 숨긴 Excel 16.0 build 14334 인스턴스에서 합성 XLSX 5개를 정상 열기·재저장했다. 단추 높이 10/24/25.3/26.125/40.5px, 열 수 1~5, 단추 너비 96px, 전체 크기를 각각 대조했다. Excel의 25개 속성 대조와 재저장본의 WIXEL 25개 대조가 통과했고, OpenXML SDK의 슬라이서 스키마 오류는 0건이었다.
- Excel이 만든 슬라이서 2개 그룹을 WIXEL에서 읽고 다시 저장한 뒤 Excel에서 열었다. 그룹 1개·구성원 2개와 각 위치·크기·필터 원본을 유지했다. Excel 재저장본을 다시 WIXEL로 읽어도 그룹과 치수를 유지했고 DrawingML 스키마 오류는 0건이었다.
- 브라우저 회귀 도구는 `tools/slicer-ribbon-parity.mjs`, `tools/slicer-arrange.mjs`, 기존 `tools/slicer-context-menu.mjs`다. 전체 Node 965/965, 최종 번들 명령 382개 `bad 0`, 소스 기본 UI 12/12와 WIXEL UI 10/10, 기존 도형/그림 그룹 회귀를 통과했다. 슬라이서 리본은 최종 번들에서 24/24(265 assertions), 그룹 배치는 소스/번들에서 17/17(122 assertions), 기존 슬라이서 우클릭은 최종 번들에서 12/12(104 assertions)가 통과했다. 브라우저 검사에서 페이지 오류·원격 쓰기는 0이었다.

- 실제 업무 파일 두 개도 `eb6162d`와 변경본을 비교했다. 익명 settlement 수식 8,545개, travel 수식 698개는 수식 불일치 0→0, 저장/다시 열기 문제 0→0이며 원본 SHA256도 같았다. `pvcmp`는 두 파일 모두 피벗 0개이므로 피벗 연산 검증으로 포함하지 않는다.
- 단독 슬라이서의 그룹화 메뉴는 비활성, 그룹/다중 선택일 때만 유효한 조작을 연다. 캡션 IME Enter는 조합을 먼저 확정하며 Escape는 입력 초안을 취소한다. 숨긴 구성원도 그룹 크기 경계에 포함하고 그룹 쌓임 순서는 하나의 단위로 유지한다.

치수·그룹 네이티브 Excel 검증은 합성 데이터만 사용했다. Excel 검사 원본은 읽기 전용으로 열었고 기존 Excel 인스턴스나 사용자 업무 파일은 수정하지 않았다. 임시 자료는 `D:/Codex/Temp/wixel-slicer-dimensions/`, 실행 로그는 무시 경로 `.local/`에 두며 저장소에 포함하지 않는다. 모든 Excel 파일·테마·플랫폼에서의 픽셀 단위 동등성을 입증한 것은 아니다.
