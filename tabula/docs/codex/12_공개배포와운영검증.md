## 인증과 저장 위치

인증된 사용자 승인 계정에서 account:read, user:read, workers_scripts:write와 Wrangler가 추가하는 offline_access 범위로 최초 배포에 성공했습니다. 별도의 KV·D1·R2·Pages·zone 쓰기 권한은 추가하지 않았습니다. 범위의 뜻과 공식 근거는 [Cloudflare README](../../cloudflare/README.md#배포-인증의-최소-범위)에 있습니다.

Wrangler 실행 시 XDG_CONFIG_HOME=D:\Codex\Config를 사용합니다. 해당 설정 아래 Wrangler의 암호화 default.enc 파일과 Windows OS 키체인을 사용하는 인증 저장이 정상 동작했습니다. 토큰·복구키·암호화 파일 내용·키체인 항목은 이 문서와 저장소에 기록하지 않습니다. 기존 인증은 whoami로 확인하며, 동일 환경에서 새 로그인이나 광범위 권한 부여를 반복하지 않습니다.

PowerShell의 저장소 tabula 폴더 기준 재현 명령입니다. 실제 배포는 승인된 계정과 wixel-3 프로젝트에서만 수행합니다.

~~~powershell
$env:TEMP = 'D:\Codex\Temp'
$env:TMP = 'D:\Codex\Temp'
$env:npm_config_cache = 'D:\Codex\Caches\npm'
$env:XDG_CONFIG_HOME = 'D:\Codex\Config'
$env:WRANGLER_SEND_METRICS = 'false'
$wrangler = 'D:\Codex\Temp\wixel3-tools\node_modules\wrangler\bin\wrangler.js'
node $wrangler whoami
node build.mjs --cloud
node $wrangler deploy --dry-run --outdir ..\.local\worker-build --config cloudflare/wrangler.jsonc
node $wrangler deploy --config cloudflare/wrangler.jsonc
~~~

## 공개 서버에서 확인한 범위

작은 합성 문서와 이번 검사에서 새로 만든 보관함 키만 사용했습니다. 사용자 업무 파일이나 기존 개인 보관함을 가져오지 않았습니다.

| 검사 | 최초 공개 배포 결과 |
| --- | --- |
| 작은 API 운영 검사 | 순차 20요청, 47검사 통과 |
| 상태·헤더 | health, 앱 CSP, nosniff, 무키 개인 API 401 확인 |
| 개인 문서 | 생성·읽기·수정, 이전 리비전 412, 충돌 후 원문 보존 |
| 보관함 격리 | 다른 합성 키의 목록 비어 있음, 문서 조회 404 |
| 백업 | 해당 합성 문서 1건의 내용 일치 |
| 공개 게시 | 인증 없이 게시 사본 읽기, 게시 취소 후 404 |
| 정리 | 합성 개인 문서 1개 삭제, 게시물 1개 취소, 두 목록 비어 있음 |
| 공개 브라우저 | 앱 시작, Ctrl+Space 열 선택, 셀 스타일 UI 확인; pageErrors 0 |

API 검사 결과는 로컬 .local/production-verification.log에 있습니다. 실행 스크립트 .local/verify-production.mjs는 작업 환경용 파일이며 Git과 전달용 소스 ZIP에 포함하지 않습니다. 15초 요청 제한, 최대 30회 순차 요청, 리디렉션 차단을 적용하며 키·본문·게시 ID를 stdout에 출력하지 않습니다. finally에서는 이 실행의 고유 표식을 가진 합성 게시와 합성 문서만 정리합니다. 네트워크나 서버 장애가 나면 정리 실패를 별도로 출력하고 성공으로 보고하지 않습니다.

스크립트가 있는 작업 환경의 저장소 루트에서 실행합니다. 정상 stdout은 성공 여부·요청 수·검사 수·정리 결과만 포함합니다.

~~~powershell
$env:WIXEL_WORKER_URL = 'https://wixel-3.adwizcompany.workers.dev'
node .local/verify-production.mjs
~~~

문서와 게시 내용의 삭제를 확인했으며, Durable Object의 내부 스키마·운영 메타데이터·게시 취소 표식까지 삭제됐다는 뜻은 아닙니다.

## 배포 전에 고친 DELETE 응답

실제 로컬 workerd에서 개인 문서 DELETE는 삭제를 실행했지만 HTTP 200의 JSON 본문이 비었습니다. 로그에는 RPC 응답 스트림이 조기에 끊긴 오류가 있었고, 기존 통합 검사는 상태 코드만 확인해 이를 놓쳤습니다.

Worker의 개인 문서 DELETE 라우트에서 작은 DO 응답 본문을 현재 요청 안에서 읽은 뒤 새 Response로 전달하도록 보완했습니다. 저장 트랜잭션·권한·버전 검사 규칙은 바꾸지 않았습니다. cloudflare/integration.mjs는 이제 삭제 성공의 JSON 본문이 {ok:true}인지도 확인합니다.

보완 후 로컬 백엔드 13/13, 실제 workerd 통합 검사 25개 HTTP 상태 확인(총 26요청, 3,500,012바이트 합성 문서 포함), 작은 운영 검사 20요청·47검사가 통과했습니다. Cloudflare 빌드와 Wrangler dry-run도 성공했습니다. 위 공개 서버의 같은 작은 검사에서도 삭제 JSON과 최종 정리를 확인했습니다.

## 남은 운영 검증

공개 환경에서는 작은 합성 문서를 검증했습니다. 문서 최대 크기 20MiB의 저장·다운로드와 초과 413은 이전 로컬 workerd 결과이며, 운영 계정의 1/5/20MiB CPU·메모리·무료 할당량까지 확인한 결과가 아닙니다. 큰 문서 검사는 실제 잔여 사용량과 Metrics의 1102/exceededCpu 등을 확인하면서 별도 수행해야 합니다. 유료 플랜으로 변경하거나 부하·반복 재시도 테스트를 실행하지 않았습니다.

API/IP 요청 제한은 전 세계 합계의 비용 상한이 아닙니다. 복구키 보관, 개인 문서/읽기 전용 게시의 차이, 백업과 한도는 [API 계약](../../cloudflare/API_CONTRACT.md)에 따릅니다. 실제 Excel 365 열기·복구 알림, 사용자 업무 파일 전후 비교, 비공개 Google Sheets OAuth, 실시간 공동 편집의 기존 미완료 범위는 공개 배포 성공만으로 완료 처리하지 않습니다.

## 공개 주소 변경

2026-10-01 사용자 요청으로 계정의 workers.dev 하위 도메인을 `adwizcompany`에서 `wizx`로 변경했습니다. 현재 공개 주소는 [WIXEL 3](https://wixel-3.wizx.workers.dev/)입니다. Cloudflare의 변경 완료 화면과 새 주소의 실제 앱 시작 화면을 확인했습니다. Worker 이름 `wixel-3`과 저장소 바인딩은 그대로입니다.

기존 `wixel-3.adwizcompany.workers.dev` 주소는 변경과 동시에 중단되며 자동 리디렉션되지 않습니다. 브라우저 보관함·자동 저장·개인 보관함 연결 설정은 웹 주소별로 분리되므로 자동 이전되지 않습니다. 변경 전에 사용자가 현재 문서를 파일로 저장했다고 확인했습니다. 새 주소에서는 저장한 파일을 열고, 온라인 보관함을 쓰던 기기라면 기존 복구키로 다시 연결합니다. 계정에는 변경 당시 Worker 한 개만 있었습니다.

주소 변경 직후의 HTTPS 인증서 반영 지연과 이후 실제 접속 성공을 구분했습니다. 위 최초 배포 표와 검사 명령의 이전 주소는 당시 이력입니다. 앞으로의 운영 검사는 새 주소를 사용합니다. 설정 절차의 근거는 [Cloudflare workers.dev 문서](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)입니다.
