# 피벗 필드를 목록으로 끌어 제거

2026-10-06. 수정 전 `3056fba`, 작업 브랜치 `codex/pivot-field-remove`.

## 동작과 적용

기존 필드 창은 행·열·값·필터 영역 사이 이동만 처리했다. 위쪽 전체 필드 목록은 drop 대상이 아니어서 배치 필드를 되돌려도 제거되지 않았다. 이제 `.pp-fields`에 배치 필드를 놓으면 해당 영역의 해당 슬롯만 제거한다. 원본 열과 데이터, 필드 목록 항목, 다른 영역과 같은 원본 필드의 다른 값 집계는 보존한다.

동작 기준은 [Microsoft 필드 목록으로 피벗 필드 배치·제거](https://support.microsoft.com/en-us/excel/get-started/use-the-field-list-to-arrange-fields-in-a-pivottable)이다. 이번 제거 대상은 위쪽 전체 필드 목록이며 기존 패널 밖 drop 취소 동작은 유지한다.

`pivotFieldRemovePatch`는 정의를 변경하지 않고 현재 이름·영역·인덱스가 일치하는 슬롯 한 개의 제거 패치를 만든다. 미배치 목록 항목·Σ 값 가상 필드·오래된 슬롯은 제거하지 않는다. 같은 값 필드의 여러 집계 중 하나를 제거해도 나머지 집계·이름·서식을 유지하며, 남은 배치가 있으면 목록 체크도 유지한다.

포인터와 HTML 드래그는 같은 `removePlacedField`와 기존 `apply`→`setPivotDef`를 사용한다. 문서·피벗·버전·권한 검사와 이전 변경의 범위 충돌 사전 검사를 거쳐 한 번의 Undo 단계로 적용한다. 제거 영역에는 테두리와 ‘필드 제거’ 안내가 나타나고 삽입 선은 숨긴다. Escape·권한/문서 변경·허용되지 않은 drop은 취소되며, 포인터 drop 뒤 뒤따르는 클릭이 체크박스를 다시 누르지 않도록 기존 차단 동작을 유지한다.

## Undo·Redo 선택

필터 영역의 마지막 필드를 제거하면 본문 위치가 유지되면서 이전 필터 행이 피벗 밖이 된다. 기존 Undo/Redo는 같은 이전 선택 메타데이터만 복원하여 Redo 후 선택이 없어진 필터 행에 남고 필드 창이 닫혔다. 값 열의 축소에도 같은 문제가 가능하다.

현재 선택한 피벗을 변경할 때만 Undo 메타데이터에 `pivotFocus`를 기록한다. 복원 시 시트·슬롯·이름이 같은 피벗의 유효 영역을 확인하고, 이전 활성 셀이 해당 범위 밖일 때만 시작 셀로 이동한다. 범위 안의 다중 선택·선택 종류와 일반 셀 작업의 기존 복원은 유지한다. 저장된 Undo 메타데이터를 수정하지 않으며 화면 스크롤은 보정한 활성 셀을 따른다.
