# 76. 슬라이서 입력 초점

2026-10-04. iPad에서 슬라이서를 선택할 때 화면 키보드가 나타나고 시트 아래쪽으로 이동한다는 보고에 대한 수정입니다.

## 확인한 원인

- 슬라이서 항목·다중 선택·필터 지우기·제목/테두리와 시간 표시 막대의 포인터 처리에서 개체를 선택하기 전에 `focusGrid()`를 호출했습니다.
- 모바일 최적화가 꺼져 있거나 외부 키보드 정책이면 이 함수가 숨은 `#cellEditor` textarea에 초점을 주었습니다. 편집기는 이전 활성 셀의 화면 좌표에 남아 있으므로, Safari가 입력기를 표시하거나 그 위치를 보이게 이동할 수 있는 직접 경로입니다.
- 메뉴 바깥을 누를 때 document capture에서 실행되는 메뉴 종료, 진행 중 셀 편집의 확정, 첫 물리 키에 따른 입력 정책 변경도 같은 편집기로 초점을 되돌렸습니다.
- 슬라이서 항목의 빠른 두 번 누르기도 일반 개체 편집으로 처리하여 캡션 입력이 있는 설정 창을 열 수 있었습니다.

## 구현

`app.js`에서 선택한 슬라이서·시간 표시 막대·차트·사진은 비입력 `#gridView`를 키보드 초점 대상으로 사용합니다. 기존 격자 키 처리기가 개체 이동·삭제·복사·설정 명령을 받습니다.

도형은 선택 상태에서 바로 한글 조합을 시작하는 기존 네이티브 편집기 경로를 보존합니다.

window capture에서 해당 개체 대상 pointerdown/mousedown을 추적하므로 document capture의 메뉴 닫기보다 먼저 보호가 시작됩니다. 이벤트의 `eventPhase`가 0이 되면 즉시 보호에서 제외하며 타이머가 참조를 해제합니다. 마우스 손바닥 이동 기능이 저장한 이벤트를 나중에 전달하는 경로는 `try/finally`로 처리 중 상태를 보호합니다.

편집 중인 셀은 정상적으로 확정한 다음 격자로 초점을 옮깁니다. 입력 검증이나 설정 대화상자, 사용자가 명시적으로 시작하는 셀·수식·도형 글자 편집은 기존 입력창을 사용합니다. Escape·삭제·잘라내기 뒤에는 일반 셀 입력 정책을 복원하고, 모바일 최적화가 꺼져 있어도 비입력 격자에서 붙여넣기 이벤트를 받습니다.

슬라이서/시간 표시 막대의 필터 버튼은 두 번 눌러도 설정을 열지 않습니다. 제목·테두리의 명시적 개체 편집 경로는 유지합니다.

## 검증

- 수정 전 WebKit, iPad UA·터치 포인터, 모바일 최적화 켜기/끄기 × 자동/외부/화면 키보드 × 터치/마우스 12조합 중 8조합에서 숨은 셀 편집기 초점을 재현했습니다. 이전 활성 셀은 250행에 두고 슬라이서는 시트 상단에서 눌렀습니다.
- `tools/slicer-input-focus.mjs`는 합성 표·피벗 슬라이서의 실제 필터 결과와 모든 `focus()` 호출, 마지막 활성 요소, 격자·페이지 스크롤을 검사합니다. 마지막 초점만 검사해 순간 입력기 호출을 놓치지 않도록 합니다.
- 기존 `tools/mobile-hardware-keyboard.mjs`의 WebKit 14개 시나리오·164개 확인 통과: 셀·수식·F2·취소·실행 취소·한글 조합 이벤트·모바일 전환 등.
- 전체 단위 검사 1,658개 통과, `tools/smoke.mjs` 리본 명령 387개 `bad 0`, 단일 HTML·Cloudflare 빌드 성공.

최종 슬라이서 회귀: 소스 WebKit, Cloudflare 빌드 Chromium·WebKit 각각 12/12조합·1,268개 확인 통과. 각 실행에서 슬라이서·시간 표시 막대 252회 전환의 초점/스크롤을 검사했으며 페이지 오류·원격 쓰기는 0건입니다. 도형은 12조합에서 기존 초점 정책을 확인했고, 네이티브 편집기를 사용하는 10조합에서 합성 한글 조합이 도형 글자·서식 창으로 전달됨을 확인했습니다. 화면 키보드를 명시적으로 선택한 모바일 모드는 기존처럼 F2로 편집을 시작합니다.

배포 빌드의 기존 셀 클립보드 회귀도 WebKit 34개 시나리오·243개 확인을 통과했습니다. OS 클립보드와 한글 조합 이벤트는 모의했으므로 실제 Bluetooth·iPadOS 검증과 구분합니다.

## 범위와 한계

사용자 업무 파일은 외부로 보내지 않았으며, 이 변경은 통합 문서 데이터·Excel 입출력 형식을 변경하지 않습니다. 데스크톱 WebKit에서는 실제 iPadOS 화면 키보드 UI가 나타나지 않아 OS 키보드와 그로 인한 화면 이동을 직접 측정할 수 없습니다. 검증한 것은 입력기 호출을 유발하던 잘못된 초점 경로 제거와 앱 기능·스크롤 유지입니다. 실제 iPad와 Bluetooth 장치의 최종 확인은 별도로 필요합니다.
