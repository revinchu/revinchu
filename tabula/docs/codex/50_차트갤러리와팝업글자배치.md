# 차트 갤러리와 팝업 글자 배치 (2026-10-03)

## 문제와 수정

차트 갤러리의 상시 접근키를 배치할 때 공통 UI가 SVG 안의 제목·축·빈 데이터 안내를 버튼의 이름으로 읽었다. 모든 차트에서는 첫 번째 미리보기 span에 접근키가 붙었고, 추천 차트에서는 HTML 이름 없이 `line-height: 0`인 SVG 버튼 아래에 접근키만 붙었다. 썸네일의 높이보다 차트 엔진 최소 높이가 커서 내용이 이름 영역을 침범하는 문제도 있었다.

- `ui.js`는 SVG·캔버스·이미지·숨긴 미리보기 하위 트리를 제외하고 실제 HTML 이름을 읽는다. 큰 SVG를 복제하지 않는 TreeWalker를 사용한다. 접근키 표시는 `data-access-caption-host`가 있는 이름을 우선하며, 이름 없는 그림 단추는 Alt 키팁과 접근 가능한 이름으로 탐색한다.
- 추천/전체 차트 카드에 이름 영역과 그림 영역을 따로 두었다. 긴 한글 이름은 줄바꿈하고 접근키도 같은 이름 영역에 표시한다. 선택 상태와 추천 목록의 방향키 탐색을 연결했다.
- 작은 견본은 차트 유형을 구별하는 예시 그림이다. 큰 미리보기는 실제 선택 데이터를 사용하고 숫자가 없는 선택만 명시적인 예시를 표시한다. 예시 데이터는 실제 셀이나 삽입 계열에 저장하지 않는다. 기존 실제 데이터 검증·삽입 정책은 유지한다.
- 차트 미리보기는 창 너비에 맞춰 다시 렌더링하고 SVG 내용의 실제 경계를 포함하여 긴 글자 잘림을 방지한다. 작은 화면에서는 탐색과 카드 목록을 재배치한다. 실제 차트의 저장 서식이나 수식 계산 규칙은 변경하지 않는다.
- 셀 스타일의 고정 높이·한 줄 생략을 제거하여 스타일 이름과 접근키를 함께 읽을 수 있게 했다. 표·SmartArt·아이콘·그림 스타일 갤러리도 함께 점검했다.

## 검증 범위

`tools/gallery-access-captions.mjs`는 SVG 텍스트가 이름 영역에 섞이지 않는지, 명시한 이름 영역·입력 레이블·일반 단추·비활성/동적 접근키와 관찰자 안정성을 320/390/1024/1440px에서 확인한다. `GALLERY_CAPTION_BASELINE=ad2dadc`로 이전 공통 UI만 격리 브라우저에 제공하면 네 화면 모두 이름 영역 검사에서 실패한다. 수정본은 4/4·64 검사 통과다. 기존 팝업 키보드 회귀도 12/12·83 검사 통과했다.

`tools/chart-gallery-layout.mjs`는 추천/전체 갤러리의 이름·접근키·실제 SVG 도형·텍스트 경계와 검색/키보드/실제 삽입/Undo를 확인한다. `WIXEL_CHART_GALLERY_OUT`은 D: 출력 폴더, `WIXEL_CHART_GALLERY_FILTER`는 시나리오 이름 일부다. 브라우저 확대는 CSS viewport/DPR 조합으로 모의하며 실제 OS의 확대 설정 검증으로 간주하지 않는다.

`tools/popup-gallery-layout.mjs`는 표·셀·SmartArt·아이콘·그림 스타일 5종을 320/390/1024px에서 검사하고 `WIXEL_POPUP_OUT`에 결과와 PNG를 저장한다.

`tools/dialog-layout.mjs`는 숨겨진 탭과 접힌 범주를 실제로 열어 입력을 검사하도록 보완했다. 그림 서식의 10개 탭도 확인하며 `WIXEL_DIALOG_EXCLUDE=차트`로 별도 검사하는 영역을 제외할 수 있다. 비차트 소스·최종 번들 각각 320/390/1024px의 27/27·2,350 검사와 주요 갤러리 5종×3크기 15조건이 통과했다. 미리보기 안 접근키·가로 넘침·셀 스타일 이름 잘림·페이지 오류·원격 쓰기 0이다.
