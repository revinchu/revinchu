# 85. 가져오기 수식 진단과 LET/LAMBDA 지역 함수

2026-10-05. 기반 커밋 `0bf073a8d2149e5795d0c3800fdd31e31acfbe72`, 브랜치 `codex/brainology-formula-support`.

## 원인과 기준

사용자가 제공한 주간 리포트 4개(B1·B2·B3 XLSB, B4 XLSX)의 경고를 조사했다. 세 XLSB의 동일 셀은 표준 Excel 함수가 아니라 검색어 문장이 수식으로 입력된 상태였고 원본 파일에도 `#NAME?`가 저장돼 있었다. 별도로 실행한 Excel의 읽기 전용 원본 사본에서 해당 수식과 화면 오류를 확인했다. 기존 사용자 Excel 인스턴스와 원본 파일은 변경하지 않았다.

기존 가져오기 진단은 미등록 함수 이름을 발견하면 원본 오류 여부와 무관하게 ‘지원하지 않는 함수’ 경고에 합산했다. 실제 정상 계산값을 위셀에서 재계산할 수 없는 경우와 원본에서도 실패했던 수식을 구별하지 못했다. 원문을 텍스트로 고치거나 검색어를 가짜 함수로 등록하지 않는다. 계산 엔진에서 실제로 이미 지원하는 LET/LAMBDA의 지역 함수 호출도 토큰 검사만으로는 미지원 함수로 오인할 수 있어 함께 보완한다.

## 구현

- `hasSavedNameError`는 오류 객체만 판정한다. 정상 문자열 `"#NAME?"`와 다른 오류는 제외한다.
- XLSX/XLSB 가져오기에서 원본 이름 오류는 새 미지원 계산 경고에 합산하지 않는다. 수식 원문·저장 오류는 보존하며, 수식 형태 메모와 별개로 셀마다 저장값을 검사한다.
- 계산 상태에 `source-error`를 추가했다. 원본 저장 오류·현재 이름 오류·미지원/미해결 진단이 함께 있고 아직 수정되지 않은 경우에만 적용한다. 계산 상태 창과 상태 표시줄은 ‘원본 오류’로 표시하며 해당 셀로 이동할 수 있다.
- 입력 변경 후에는 기존 `stale`/`blocked` 처리로 진행하므로 저장된 과거 숫자가 현재 합계로 혼입되지 않는다. 원본 오류가 있는 수식을 지원하는 수식으로 수정하거나 정의된 함수를 추가하면 정상 재계산한다. Undo/Redo도 기존 트랜잭션을 사용한다.
- `unknownFunctions`는 미등록 후보가 있고 LET/LAMBDA가 쓰인 경우에만 AST를 읽는다. LET의 순차 바인딩, LAMBDA 매개변수, 부모·자식 범위를 적용하며 형제나 외부 호출로 지역 이름을 누출하지 않는다. 해석 실패 시 기존 미등록 후보를 유지한다. 수백만 개 일반 수식에는 추가 AST 검사를 하지 않는다.
- 실제 미지원 함수의 숫자·정상 문자·다른 오류 저장값 경고는 유지한다. 이 변경은 미지원 함수 전부를 구현하거나 원본 파일의 오류를 정정한 것이 아니다.
