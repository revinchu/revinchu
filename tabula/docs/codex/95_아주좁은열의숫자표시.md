# 아주 좁은 열의 숫자 표시

2026-10-06. 수정 전 기준: `ff60c83`.

## 원인과 표시 규칙

숫자가 셀 내용 폭에 들어가지 않으면 General 형식의 소수 자릿수 축소·지수 표시를 먼저 시도한다. 그 다음에는 현재 셀 글꼴로 측정한 `#`의 폭과 셀 내용 폭을 비교하여 완전한 글자가 들어가는 개수만 표시한다. 기존 `fitNumber`는 최소 1개를 강제했으므로 `#` 한 글자도 들어가지 않는 아주 좁은 열에 불필요한 기호가 남았다.

최소 개수를 0으로 수정했다. 열 너비, 셀 값·수식·숫자 형식은 바꾸지 않는다. 글자가 들어갈 폭이면 기존 숫자 또는 `###` 표시를 유지한다. 텍스트·오류 값과 숫자의 줄바꿈 규칙은 기존 경로를 따른다. 특정 시트나 0.69라는 너비를 예외로 처리하지 않으며 글꼴의 실제 측정 폭으로 결정한다.

[Microsoft 공식 설명](https://support.microsoft.com/en-us/excel/how-to-correct-a-error)은 숫자·날짜를 표시하기에 좁은 열에서 `#####`가 나타날 수 있다고 설명한다. 아주 좁은 폭에서 빈칸이 되는 임계값은 공개 문서에 명시되어 있지 않다. 이번 수정은 사용자 Excel 관찰과 실제 원본의 타입·글꼴·너비를 근거로 한 표시 동작 보완이다.

## 원본 확인과 회귀 검사

사용자가 지정한 XLSX는 읽기만 했다. `구글` 시트의 C106:C129는 General 숫자 0~23이며, 원본 XML의 열 너비는 1.125, 가져온 시트 너비는 9px이다. Normal 글꼴은 맑은 고딕 11pt, 해당 셀은 10pt다. Excel 열 너비 표시 0.69와 원본의 픽셀 너비가 대응한다. 숫자 값이나 열 너비를 잘못 읽은 문제는 아니다.

`tools/narrow-column-layout.mjs`는 합성 XLSX에서 0~20px 및 일반 너비의 숫자·날짜·음수 날짜·백분율·General 소수/지수·텍스트·오류를 확인한다. 완전한 `#`의 실제 폭, 인접 열 침범, 숫자 줄바꿈 방지와 여러 배율을 검사한다. 선택한 실제 원본은 로컬에서만 열고 숫자 보존·열 확대·실행 취소를 확인한다.

- `WIXEL_URL`: 소스 또는 번들 서버 URL.
- `NARROW_COLUMN_BASELINE=ff60c83`: Git에서 수정 전 `view.js`만 메모리에 읽어 소스 요청에 제공한다.
- `REAL_WORKBOOK`: 실제 원본 경로. 로컬 서버에서만 사용할 수 있다.
- `NARROW_COLUMN_OUTPUT`: 결과 폴더. 기본은 저장소의 무시된 `.local/narrow-column`이다.
- 공개 합성 검사에는 `WIXEL_ALLOWED_TEST_URL`에 `WIXEL_URL`과 같은 정확한 URL을 지정한다.

브라우저는 격리하고 API·외부 요청·쓰기 요청을 차단한다. 원본과 실제 화면·데이터는 Git에 포함하지 않는다. 네이티브 Excel의 직접 화면 비교는 computer-use 런타임 초기화의 `apply deny-read ACLs` 오류로 완료하지 못했다. Excel의 비공개 내부 알고리즘 전체나 모든 글꼴의 픽셀 일치를 검증했다고 주장하지 않는다.
