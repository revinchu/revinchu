# 18. 파일 저장 창 — 2026-10-01

## 변경한 동작

- 저장 버튼과 Ctrl+S는 현재 파일 핸들에 곧바로 쓰지 않고 매번 시스템 저장 창을 엽니다. 파일 이름과 폴더를 바꿀 수 있습니다. 기억한 핸들은 시작 폴더 힌트로만 사용합니다.
- 예전 저장 위치 생략/덮어쓰기 확인 생략 설정을 적용하지 않습니다. Excel 다운로드·공유 내보내기·CSV/ODS/WIXEL 내보내기·복구키·보관함 백업도 같은 선택 경로를 사용합니다.
- 저장 창을 취소하면 파일 쓰기/다운로드/문서명 변경을 하지 않습니다. 파일 선택 권한 오류도 자동 다운로드로 바꾸지 않습니다. 쓰기 실패 시 미완료 스트림을 폐기합니다.
- 셀 또는 수식 입력줄을 편집하는 중 Ctrl+S도 입력을 검증·확정한 뒤 저장 창을 엽니다.
- 시스템 저장 창 미지원 환경에서는 파일 이름과 다운로드 여부를 먼저 확인합니다. 앱이 폴더 선택을 강제할 수 없어 브라우저 다운로드 설정과 Chrome/Edge 사용을 안내합니다.
- 브라우저 자동 보관은 별도로 계속 동작합니다. 온라인 저장 위치 카드는 폴더·문서 이름을 먼저 묻습니다. 기존 문서는 확인한 revision으로만 덮어쓰며, 목록 대기·폼 제출·덮어쓰기 확인 중 문서나 연결이 바뀌면 취소합니다.

## 검증 범위

- 전체 단위 테스트: 437/437.
- 일반 빌드와 Cloudflare 빌드 성공.
- 배포 번들: 파일 저장 검사 12/12 (브라우저 자동 보관의 선택창 호출 0 포함), 단축키 114/114, 리본 스모크 300개 bad 0.
- 배포 번들: 온라인 저장 창 9/9 (성공·취소·문서 전환·연결 해제·목록 실패·버전 충돌).
- 소스: 브라우저 원자 저장 16/16, 기존 저장/온라인 충돌/UI 검사 10/10.
- 파일 저장 검사는 메모리 File System Access 핸들에 실제 XLSX를 쓰고 다시 읽어 값과 수식을 검사합니다. 실제 사용자 업무 파일은 사용하지 않습니다.
- 네이티브 OS 창 외형·사용자별 시스템 권한 동작은 이 자동 검증에 포함되지 않습니다.

## 수동 확인

Chrome 또는 Edge에서 새 탭으로 배포 주소를 열고, 테스트 문서에서 Ctrl+S를 두 번 눌러 매번 파일 이름/폴더 창이 열리는지 확인합니다. 첫 파일과 다른 이름을 선택하면 사본이 생기며, 같은 기존 파일을 고른 경우 운영체제 저장 창에서 교체 여부를 결정합니다. 취소하면 파일을 만들거나 덮어쓰지 않습니다.

API 제약: [Chrome File System Access 공식 문서](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access).
