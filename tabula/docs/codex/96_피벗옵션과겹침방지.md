# 피벗 옵션 보존과 겹침 방지

## 원본 옵션과 입출력

XLSB의 `BrtBeginSXView.fAutoFormat`이 0일 때 XML 변환에서 `useAutoFormatting`을 생략하여 WIXEL의 기본값인 켜짐으로 바뀌었다. 이제 0도 명시한다. `fSingleFilterPerField`와 `fDontUseCustomLists`도 다중 필터·사용자 지정 목록 설정으로 변환하며, XLSX 저장에서 `multipleFieldFilters`를 0으로 강제하지 않는다. XLSX의 표준 boolean `false`/`true` 표기도 같은 의미로 읽는다.

사용자가 지정한 원본 XLSB의 14개 피벗은 모두 자동 맞춤 해제 상태다. 수정 전 모델은 모두 켜짐으로 해석했으며, 수정 후에는 원본의 9개 지원 옵션과 일치한다. 검색어 시트의 주 피벗은 B22:O1118, 옆 피벗은 Q22:AD28이다. 옵션을 해제한 피벗의 정렬·필터·새로 고침은 기존 열 너비를 유지한다.

근거: [MS-XLSB BrtBeginSXView](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xlsb/f6cbfd44-775f-44f6-8ba8-fac46d7a445c), [Microsoft 피벗 레이아웃·서식과 열 너비 옵션](https://support.microsoft.com/en-us/excel/design-the-layout-and-format-of-a-pivottable). 모든 Excel 옵션을 새로 구현했다는 의미는 아니며 이번 범위는 위에 적은 옵션 손실과 결과 범위 보호다.

## 결과 범위와 적용 순서

`pivot-area.js`는 필터·머리글·빈 구분 행·본문·총합계를 포함하는 예상 셀 범위를 구한다. 같은 시트의 다른 피벗과 한 셀이라도 겹치면 이름을 포함한 안내를 표시하고 적용을 중단한다. 교체하는 피벗은 이름 대신 실제 정의의 동일성으로 구분하여 이름이 같은 다른 정의도 보호한다. 결과가 없는 피벗은 명시된 시작 셀을 예약한다.

`preparePivotWrite`와 `preparePivotChanges`는 결과를 먼저 계산하며 기존 셀·병합·서식·열 너비·정의를 변경하지 않는다. 저장 원본 조회와 필드 항목 조회의 `preserveSnapshot` 옵션은 캐시의 등록·버전·추적 메타데이터를 보존한다. 정렬·끌기·보고서 연결·그룹·계산 항목의 준비 조회와 거절 뒤 필요한 필드 창 원복도 이 옵션을 사용한다. 일반 표시 조회의 기존 stale 캐시 무효화 동작은 유지한다. 모든 범위 검사가 통과해야 `applyPivotChanges`가 결과와 정의를 같은 Undo 단계에 적용한다. 거절된 필드 추가·정렬·필터·새로 고침은 이전 결과와 옵션, Undo 기록을 유지한다.

여러 연결 피벗의 슬라이서 선택·새로 고침·보고서 연결, 같은 원본의 계산 필드 변경, 전체·자동 새로 고침과 스타일 일괄 변경도 전체 계획을 확인한다. 한 대상이 충돌하면 다른 대상이나 슬라이서 연결·스타일 목록을 먼저 저장하지 않는다. 중복된 연결은 같은 피벗 슬롯을 한 번만 적용한다. 자동 갱신 실패는 성공한 원본 버전으로 기록하지 않아 공간을 확보한 후 재시도할 수 있다.

현재 검사는 다른 대상의 기존 영역과 예상 새 영역을 함께 보호한다. 한 일괄 변경에서 다른 대상이 축소해 비울 영역을 즉시 차지하는 요청도 보수적으로 거절할 수 있다. 이를 완화하려면 모든 이전 영역 정리와 모든 새 결과 작성을 분리해야 한다. 일반 셀의 덮어쓰기·표·동적 배열 전체 충돌 정책은 이번 변경 범위와 구분한다.

최신 Microsoft 365는 피벗 확장 충돌을 [피벗 #SPILL! 오류](https://support.microsoft.com/en-us/excel/how-to-correct-a-pivottable-spill-error)로 표시하기도 한다. 이번 구현은 사용자가 요청한 기존 피벗 보존과 변경 거절을 따르며 모든 Excel 버전의 안내 화면이 동일하다고 주장하지 않는다.
