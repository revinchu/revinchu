# 72. 파일 전환 후 이전 문서로 돌아가는 오류 방지

## 확인된 문제

사용자는 iPad Safari에서 A 파일을 연 뒤 B 파일을 열고 작업하면 로딩 없이 A의 내용으로 바뀐다고 보고했다. 기존 배포 번들 `wixel-5a510e744d7ab024.js`에서 합성 파일·응답을 지연시켜 Chromium과 WebKit 양쪽에서 재현했다. 실제 사용자 문서를 변경하거나 원격 서비스에 올리지 않았다.

- `openFileObject`가 비동기 읽기 뒤 전역 `fileMode`를 사용하고 열기 요청 순서를 검사하지 않았다. 늦은 A 읽기·셀 준비가 B 또는 새 문서를 덮었다. 늦은 실패도 B 위에 오류 창을 띄웠다.
- `loadWorkbookAsync`가 피벗 준비 전에 전역 `wb`를 교체한 뒤 여러 번 양보했다. 문서 데이터와 이름·복원 ID가 확정되는 시점이 달랐다.
- 게시 보기의 30초 갱신 타이머가 편집용 사본·다른 파일로 전환한 뒤에도 살아 있었고, 요청 중이던 응답도 다시 원본을 열었다.
- 시작 시 서버 확인이나 URL 문서 응답이 늦어지면 그동안 사용자가 연 파일을 시작 링크 문서로 교체했다.
- 게시본의 편집용 사본 버튼이 최초 응답을 캡처하여, 갱신된 화면 대신 처음 내용으로 사본을 만들었다.

## 수정 구조

`document-session.js`는 열기 요청마다 토큰을 발급하며 이후 요청이 시작되면 이전 토큰을 영구 무효화한다. 파일 읽기·형식 파싱·셀 준비·피벗 준비 뒤와 최종 반영 직전에 동일 토큰을 검사한다. 뒤늦은 성공·실패는 현재 문서에 적용하지 않는다. XLSX/XLS/ODS/텍스트/WIXEL, 새 문서·템플릿, 보관함, 온라인 문서 및 시작 링크가 같은 순서를 사용한다.

새 Workbook은 화면과 자동 저장의 현재 문서가 아닌 준비 대상으로 유지한다. 기존 전역 피벗 함수를 부르는 짧은 동기 구간에만 준비 문서와 문서별 피벗 캐시를 연결하고 즉시 복원한다. `await` 중에는 항상 원래 문서가 유지된다. 모든 준비를 마친 최신 요청만 Workbook·이름·문서 ID·시트와 실행 취소 이력을 함께 전환한다. 피벗 서식 캐시는 준비 문서별로 격리하고 최종 반영 시 승계한다.

이전 문서의 읽기 진행창은 새 요청이 시작되면 제거하여 새 파일의 마우스 조작을 가리지 않는다. 저장 진행창은 이 취소 대상이 아니다. 문서 교체 시 이전 자동 저장·피벗 타이머와 변경 알림을 분리한다. 이전 문서의 지연 의존 그래프 계산도 현재 문서를 갱신하지 않는다.

게시본 갱신은 타이머 해제뿐 아니라 응답 후 현재 보기·문서·요청을 재검사한다. 현재 게시본의 정상 갱신은 유지하며 편집용 사본은 현재 화면의 내용을 사용한다. 다른 파일을 성공적으로 열면 이전 `?view`, `?doc`, `#view` 주소도 제거하여 다음 재열기에서 옛 링크를 다시 적용하지 않는다.

## 검증과 한계

- 토큰의 지연 완료·실패·무효화·독립성 단위 검사 7개.
- `tools/document-switch.mjs`: 실제 파일 입력으로 순차 열기, 지연 읽기·준비·실패, 다른 형식 교체, 새 문서, A→B→C, 동일 파일명, 편집·실행 취소·다시 실행·시트 변경·자동 저장·재열기 및 오래된 진행창 제거를 확인한다.
- `tools/document-published-switch.mjs`: 게시본 정상 갱신, 보기 종료 후 타이머, 요청 중 응답, 늦은 시작 URL/서버 확인, 최신 게시본 사본을 확인한다. 네트워크는 합성 응답으로 격리한다.
- 실제 iPad 하드웨어와 사용자 오류 당시의 정확한 응답 순서를 기록한 것은 아니다. WebKit 재현과 수정 검증을 실제 장치 검증으로 표현하지 않는다.

추가 재열기 검사에서 WebKit이 페이지 종료 중 `libraryFlush`가 새로 시작한 gzip Blob 읽기를 차단하는 오류를 재현했다. 비동기 보관은 백그라운드 전환 시 시도하고, 종료가 시작되었으면 새 압축을 시작하지 않는다. `beforeunload`에서는 동기적으로 끝나는 작은 복원 사본만 저장한다. 예약된 브라우저 저장 타이머와 idle 콜백에도 종료 상태를 확인한다. 종료를 취소하면 저장을 다시 예약하고 화면 복귀 시 종료 상태를 해제한다. 자동 저장을 끈 문서의 종료 확인은 저장 전의 미저장 상태로 판단한다. 큰 문서의 비동기 저장은 종료 순간의 완료를 보장하지 않으며 기존 자동 저장·파일 저장이 필요하다.

실제 업무 파일 2개(각 약 93만 셀)의 계산 1,337개 수식 불일치 0, XLSX 왕복 문제 0, 기준/수정본의 시트·도형·링크 개수 동일을 확인했다. 두 파일은 인식된 피벗이 없어 피벗 서식은 별도 합성 XLSX로 Chromium/WebKit 기준/수정본 12개 사례·72개 판정을 확인했다. 원본 파일은 수정·복사·업로드하지 않았다.
