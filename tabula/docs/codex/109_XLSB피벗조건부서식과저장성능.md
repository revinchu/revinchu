# XLSB 피벗 조건부 서식과 대용량 저장

2026-10-12에 전달받은 XLSB와 WIXEL에서 저장한 XLSX를 비교했다. 기준 코드는 `4ad3958`이며, 업무 파일과 진단 출력은 Git 밖의 D: 임시 폴더에서만 처리한다. 원본과 사용자가 편집해 저장한 파일은 덮어쓰지 않는다.

## 원인과 변경

XLSB의 시트 조건부 서식에는 피벗 여부가, 피벗 정의에는 규칙 우선순위와 값·행·열 필드의 연결이 별도로 저장된다. 기존 변환은 색상 눈금과 범위만 가져오고 이 연결을 놓쳤다. 따라서 저장된 XLSX의 XML에 색상 눈금이 있어도 Excel에서 열면 해당 규칙이 사라졌다.

`xlsb.js`에서 BrtBeginConditionalFormatting의 피벗 표시와 BrtBeginSXCondFmt / PRuleHeaderData / PRFilter 레코드를 변환한다. 기존 자동 정렬 참조와 조건부 서식 참조를 구분한다. `xlsx.js`의 기존 규칙 연결과 저장 경로에는 열 필드도 연결하여 값·행·열 필드 범위를 보존한다. 시트의 규칙 순서와 피벗의 규칙 순서가 달라도 우선순위로 연결한다.

성능 검사의 입력은 약 25.8 MB지만, 압축을 풀면 약 522 MB이고 344만 셀·339만 수식·14개 피벗이 있다. 다음 처리를 줄였다.

- XLSB에서 이미 디코딩한 독립 문자열을 XML 부분 문자열처럼 JSON 왕복 복사하지 않는다.
- 반복되는 표 수식의 XML은 AST별 최근 변환 결과를 최대 4,096개 재사용한다. 원문·표 이름·동적 배열 여부까지 일치해야 재사용한다.
- 스트리밍 저장 시 매 셀마다 ZIP 반복자에 전달하던 XML을 행 단위로 묶는다. 큰 행은 약 64 KiB마다 나누므로 전체 시트나 큰 행 전체를 한 번에 합치지 않는다.
- 일반 A1 수식은 같은 AST와 상대 참조 원점이 일치할 때만 최대 4,096행씩 공유 수식으로 저장한다. 빈칸·다른 수식·배열 수식·해석 오류·표 참조·외부 참조는 공유 대상에서 제외한다. 원본 셀과 AST는 변경하지 않는다.

표 참조 수식의 공유 저장은 최종 구현에서 제외했다. 실험 파일은 WIXEL 자체 왕복 검사를 통과했지만 Native Excel에서 실제 대용량 파일 열기가 실패했다. 최종 구현은 표 수식을 각 셀에 명시적으로 저장한다. 해당 실험의 저장 속도와 용량 감소 수치는 최종 결과에 사용하지 않는다. 초기 작은 합성 파일의 참조 오류는 잘못된 표 모델(`headers` 대신 `header` 필요)에서도 발생하므로 공유 저장의 오류 근거로 사용하지 않는다. 합성 검사는 표 모델을 바로잡고 실제 기대 숫자와 대조한다.

## 실제 파일 검증

Microsoft Excel 16.0의 별도 인스턴스로 링크 갱신 없이 읽기 전용으로 열어 비교했다. 원본의 O134:O140, O166:O172에는 피벗 조건부 서식 2개가 있었고, 사용자가 전달한 기존 저장본에서는 0개였다. 수정한 조건부 서식 저장본은 규칙 2개, 피벗 적용 범위, 대상 14개 셀의 `DisplayFormat.Interior.Color`가 원본과 일치했다.

Node 24.19의 동일 프로파일 도구로 D:에 복사한 동일 XLSB를 측정한 값이다. 각 1회 측정이며 프로파일러 오버헤드를 포함한다. 사용자 브라우저의 파일 선택·자동 보관·네트워크 드라이브·디스크 저장 대화상자 시간과는 다르다.

| 구간 | 기준 코드 | 최종 코드 |
|---|---:|---:|
| 읽기 | 13.031초 | 12.717초 |
| Workbook 생성 | 5.634초 | 5.629초 |
| XLSX Blob 생성 | 54.741초 | 40.817초 |

이 측정에서 저장 구간은 약 25% 감소했다. 열기 개선은 작으며, 대량의 셀·수식 해석 비용은 남는다. 최종 XLSX 용량도 약 47 MB로, 표 수식 생략이나 값 전용 변환으로 줄이지 않는다.
