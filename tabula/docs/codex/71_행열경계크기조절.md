# 71. 행·열 머리글 경계 크기 조절

## 재현과 수정

기존 위셀에도 머리글 경계의 드래그 및 더블클릭 처리기가 있었지만 경계 감지 폭을 시트 좌표로 계산해 55% 배율에서는 마우스가 잡을 수 있는 폭이 1~3 화면 픽셀로 줄었다. 틀 고정 이후 스크롤한 경계에서는 고정된 마지막 열 대신 뒤에 가린 열이 선택되었으며, 다중 행 더블클릭은 한 행만 맞췄다.

- `header-resize.js`는 보이는 행·열 경계의 양쪽 5 CSS 픽셀을 확대 배율에 맞춰 판정한다. 고정/스크롤 창을 각각 검사하여 가려진 경계와 숨긴 행·열을 제외한다. 행/열 개요 영역과 셀 본문은 크기 조절 대상이 아니다.
- 마우스를 경계에 올리면 좌우/상하 크기 조절 커서를 사용한다. 모바일 마우스 환경은 방향·현재 크기 안내를 함께 표시하여 시스템 커서 모양에만 의존하지 않는다. 드래그 중에는 크기와 안내선을 표시하며 커서를 격자 밖으로 옮겨도 드래그 방향을 유지한다.
- 드래그는 원본 크기를 보관한 미리 보기이고 놓을 때 선택한 행·열에 한 번의 실행 취소로 반영한다. Esc, 창 포커스 상실, 포인터 취소, 문서/시트/보호 변경은 미리 보기를 복원한다. 이동 없는 클릭은 실행 취소 이력을 만들지 않는다. 외부 명령이 같은 크기를 이미 바꾼 경우 그 값을 덮어쓰지 않는다.
- 여러 행·열 선택 후 경계를 두 번 클릭하면 선택 전체에 기존 리본 자동 맞춤 경로를 사용한다. 기존 머리글의 201열/단일 행 제한을 제거하고 공통 선택 범위 한도(20,000개)를 적용한다. 행 자동 맞춤은 수동 높이 플래그도 해제한다.
- 편집 중인 값 확정, 읽기 전용·최종본·시트 서식 권한 검사를 연결했다. 모든 행/열을 크기 0으로 바꿔 숨기는 요청은 차단한다. 표준 XLSX 너비·높이·수동 행 높이 저장 구조는 변경하지 않는다.

## 검증 범위와 한계

`test/header-resize.test.js`는 25~400% 배율, 양쪽 경계, 숨김·0 크기, 틀 고정과 저장된 시작 위치, 스크롤, 개요, 임의 좌표의 기하 비교와 대량 숨김 행의 제한된 조회를 검사한다.

`tools/header-resize.mjs`는 합성 문서에서 실제 마우스 이동·누름·드래그·더블클릭으로 데스크톱, 모바일 최적화 390px, iPad 형태 사용자 에이전트, 55/100/150%, 틀 고정과 스크롤, 다중 선택, 취소·권한·실행 취소와 XLSX 저장·재열기를 확인한다. 외부 쓰기는 차단한다.

실제 iPad Bluetooth 하드웨어나 Microsoft Excel 앱의 시스템 커서 픽셀 모양을 직접 검증한 것은 아니다. 자동 맞춤은 기존 텍스트 측정기를 사용하며 병합 셀의 내용과 대용량 데이터 전체 측정 등 기존 제한까지 제거했다고 보지 않는다.

## 최종 빌드 검증

- 전체 단위 검사 1,258/1,258 통과. 독립 HTML·Cloudflare 빌드 성공.
- 최종 `wixel-5a510e744d7ab024.js`에서 스모크 387개 명령, 오류 0.
- Chromium·WebKit의 50개 브라우저 사례, 총 1,094개 판정 통과. 초기 전체 실행에서 두 브라우저의 첫 화면 탐색만 10초 제한에 걸려 48개가 통과했고, 탐색 제한을 60초로 조정한 동일 번들 재검사에서 나머지 2개도 통과했다.
- 실제 장치 검증은 별도로 남아 있으며 위 결과는 로컬 브라우저 자동화 결과다.
