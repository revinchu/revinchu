# 숨긴 열과 셀 텍스트 넘침

약 5.3MB·12시트의 익명 업무 검체에서 B열의 긴 텍스트가 숨긴 C열을 지나 값이 있는 D열을 덮는 문제가 보고됐다. 원본 XML에서 해당 조건을 20개 행에 확인했다. 공개 기록에는 검체의 파일명·금융 값·원본 경로·화면·해시를 포함하지 않는다. 실제 원본의 수정 전후 화면 검사도 아래에 함께 기록한다.

기존 표시는 바로 다음 논리 열의 빈 상태만 확인하고 넘친 글자를 제한 없이 그렸다. C열이 숨겨져 있고 비어 있으면 D열의 값을 만나도 표시 폭을 제한하지 못했다. 오른쪽 빈 열이 여러 개 이어지고 그 뒤에 값이 있을 때도 같은 경계 문제가 있었다.

## 표시 경계

`cell-text-overflow.js`는 글자 측정 폭이 도달하는 만큼만 표시 열을 탐색한다. 숨긴 열은 내용 조회 없이 건너뛰고, 표시되는 빈 열의 너비를 더하다가 첫 차단 셀 또는 시트 끝에서 멈춘다. 왼쪽 정렬은 오른쪽, 오른쪽 정렬은 왼쪽을 검사한다. 가운데 정렬은 두 방향을 독립적으로 계산하므로 한쪽에 값이 있어도 반대쪽 빈 공간으로는 글자가 이어질 수 있다.

- 표시 열의 값과 수식은 넘침을 차단한다. 숫자 0·FALSE·빈 문자열을 반환하는 수식도 빈 셀로 취급하지 않는다.
- 배열 수식의 자식 셀은 저장 raw가 없어도 실제 값이 있으면 차단한다.
- 병합 이웃은 차단 경계다. 병합 원본 셀은 기존 병합 영역 표시를 사용한다.
- 빈 셀의 배경색만으로 넘침을 차단하지 않는다. 글자는 빈 이웃의 채우기 위에 표시한다.
- 숨긴 열에 실제 값이 있어도 그 값은 표시 넘침을 차단하지 않는다. 다음 표시 열의 경계를 사용한다.

셀의 원래 좌표·너비·높이·맞춤을 유지한 채 가로 clip-path로 넘친 글자의 끝만 제한한다. 기존 채우기와 테두리의 독립된 표시 층을 사용한다. 회전·세로 쓰기·줄 바꿈·셀에 맞춤·병합과 선택 영역 가운데 맞춤(centerContinuous)은 각각의 기존 전용 표시 경로를 유지한다. 이번 변경은 셀 값·수식·저장 모델·XLSX 입출력의 변경이 아니다.

글자가 짧을 때도 기존 채우기 층의 조건을 유지하되 방향마다 최대 한 이웃만 확인한다. 백만 개 연속 숨김을 건너뛰는 단위 검사에서는 표시 셀 조회가 두 번이며, 행 전체를 순회하거나 입력의 크기·숨김·셀 값을 수정하지 않았다.

## Excel 기준 확인

기존 사용자 Excel 인스턴스에 연결하지 않고 새 PID·실행 경로·시작 시각·Hwnd·빈 Workbooks를 확인한 합성 인스턴스에서 11가지 조건의 PDF를 만들었다. 숨긴 빈/실제값 열, 다음 표시 값, 가운데 한쪽 차단, 오른쪽 정렬, 빈 배경색, 빈 문자열 수식, 병합 이웃과 병합 원본을 비교했다. 소유 인스턴스의 상태를 재검사한 뒤 해당 합성 통합 문서만 닫고 종료했다. 기존 사용자 인스턴스는 유지했다.

합성 PDF의 실제 렌더링에서 숨긴 열의 값은 무시하고 다음 표시 값 경계에서 잘리는 동작, 가운데 양방향의 독립 차단, 빈 배경 위의 글자와 수식/병합 이웃의 차단을 확인했다. PDF의 텍스트 추출에는 잘린 글자도 남을 수 있어 렌더된 이미지로 경계를 확인했다. 이는 Excel의 합성 인쇄 표시 근거이며 모든 대화형 화면 픽셀의 동등성 검증은 아니다. 병합 원본 B:C의 다음 D열이 비어 있을 때의 넘침은 이 표본에 없으므로 별도 일반화하지 않는다.

공식 Microsoft 문서의 [Hidden](https://learn.microsoft.com/en-us/office/vba/api/excel.range.hidden), [HasFormula](https://learn.microsoft.com/en-us/office/vba/api/excel.range.hasformula), [MergeArea](https://learn.microsoft.com/en-us/office/vba/api/excel.range.mergearea), [WrapText](https://learn.microsoft.com/en-us/office/vba/api/excel.range.wraptext), [ShrinkToFit](https://learn.microsoft.com/en-us/office/vba/api/excel.range.shrinktofit)는 속성의 뜻을 확인하는 근거다. 위 넘침의 상세 경계는 이 문서들이 알고리즘 전체를 명시한다고 주장하지 않고 합성 native 결과로 구분한다.

실제 검체·화면·소유 인스턴스 기록과 상세 결과는 D:의 무시된 비공개 작업 경로에만 보관한다. 이 문서와 코드는 금융 원문을 포함하지 않는다. 이번 경계 수정과 열거한 검사로 모든 Excel 파일·글꼴·배율·플랫폼의 동일 화면을 보증하지 않는다.
