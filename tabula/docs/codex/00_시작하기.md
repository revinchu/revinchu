## 시작하기 (Windows PowerShell)
기존 체크아웃이 있으면 그 경로를 유지합니다. 새 작업의 기본 위치는 `D:\Codex\Workspaces`,
임시 파일은 `D:\Codex\Temp`, 의존성 캐시는 `D:\Codex\Caches`입니다.
아래는 체크아웃이 준비된 경우의 실행 예입니다. 새로 clone할 때는 `06_검증결과.md`의
푸시 상태와 실제 원격 브랜치를 먼저 확인하세요. 로컬 브랜치 이름만으로 원격 게시가 확인되는 것은 아닙니다.

```powershell
Set-Location D:\Codex\Workspaces\wixel\tabula
node -v
npm test
npm run build
$env:HOST = '127.0.0.1'
npm start
```
Node 18 이상이 필요합니다. Node 버전과 실제 테스트 통과·실패·건너뜀 개수를 기록하세요.
`http://localhost:5178`에 접속해 파일 › 새로 만들기에서 템플릿을 열 수 있습니다.
ZIP 스냅숏에는 Git 이력이 없으므로 커밋·푸시는 Git 체크아웃에서 진행합니다.
브라우저 검증 도구의 설치와 실행은 [`tools/README.md`](../../tools/README.md)를 따르세요.

브라우저 콘솔에서 `window.tabula` 로 내부에 접근할 수 있습니다 (테스트 스크립트가 사용):
`tabula.wb()`(통합 문서), `tabula.run('명령')`, `tabula.selectCell(r,c)`, `tabula.selectRange(rg,'cells',active)`,
`tabula.switchSheet(i)`, `tabula.commands()`(명령 목록), `tabula.menus()`, `tabula.gv()`(격자 뷰), `tabula.sel`, `tabula.si`, `tabula.active`, `tabula.chartSel`, `tabula.exportXlsx`, `tabula.templates`.

## 작업 방식 (지금까지 지켜 온 것)
1. 엑셀 동작을 정답으로 봅니다. 애매하면 "한국어판 엑셀 365에서 어떻게 보이는가"로 결정합니다.
2. 계산 · 파일 형식 로직은 DOM 없는 모듈에 두고 Node 테스트로 고정합니다. `app.js` 에는 UI 연결만.
3. 사용자 실제 파일로 수정 전/후 비교(`tools/`)를 돌려 나빠진 파일이 없을 때만 커밋합니다.
4. 기능을 하나 마칠 때마다: 필요한 기술 노트·`WHATS_NEW` 갱신 → 테스트 → 해당 검증 도구 → 빌드 → 결과 검토 → 커밋 · 푸시.
5. 커밋 메시지는 영어 요약 + 목록 (기존 로그 형식 참고: `git log --oneline`).
