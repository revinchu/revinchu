# 모바일 마우스 작업과 축소 표시

2026-10-03. 기준은 모바일 한 줄 도구 수정 커밋 `23fa44e65e533053572d1388cb29bf1b6828eb66`이다.

## 바뀐 동작

- 모바일 리본 그룹 캡션을 숨기고 높이를 촘촘하게 32px, 여유롭게 36px로 줄였다. 그룹 실행기는 유지한다.
- 수식 입력줄과 시트/배율 하단은 각각 24px다. 이름 상자는 46px이고 수식/이름 입력은 실제 16px 입력 요소를 0.6875배로 표시해 시각적으로 11px다. iOS의 작은 입력 글꼴 자동 확대 조건을 피하면서 사용자 pinch zoom은 제한하지 않는다. 확장 수식줄은 별도로 유지한다.
- 하단 safe area는 행 자체 높이를 제외한 남는 부분만 여백에 더한다. 메뉴와 본문 글꼴 자동 확대는 명시적인 표시 비율을 유지한다.
- 미니/리본의 글꼴·크기에 아래 화살표와 사용자 목록을 연결했다. 기본 글꼴, 문서 사용 글꼴, 감지된 설치 글꼴을 표시한다. 설치되지 않은 글꼴의 실제 모양은 브라우저의 대체 글꼴에 따른다. 크기는 16개 표준 크기와 직접 입력을 제공하며 소수도 허용한다. 모바일에서 목록을 열기만 하면 입력기를 호출하지 않는다. 직접 입력·검색은 16px, 데스크톱의 직접 입력과 Alt 키 경로는 유지한다.
- 모바일 리본·탭·시트·빠른 실행 도구를 마우스 왼쪽 버튼으로 잡아 좌우로 끌 수 있다. 휠/터치 이동도 유지한다. 4px 넘게 끌 때 클릭을 억제하고 시트 탭의 mousedown 선택도 보류한다. 입력 내용 드래그는 가로 이동으로 가로채지 않는다.
- 모바일 본문에서 마우스 왼쪽·오른쪽 버튼을 함께 누르고 끌면 손바닥 커서로 상하좌우 이동한다. 첫 버튼의 셀 동작을 보류해 양쪽 버튼 확인 전 셀 선택·체크박스·그리기·서식이 바뀌지 않는다. 한쪽 버튼을 놓거나 Escape/포커스 이탈/pointercancel/시트 변경 시 중단한다. 일반 왼쪽 드래그를 이미 시작한 뒤 누른 오른쪽 버튼은 팬으로 전환하지 않는다.

## 축소 시 글자 잘림 원인

기존 `gridView.style.zoom`은 축소된 크기에서 브라우저가 글자 폭과 줄바꿈을 다시 결정했다. 돋움 9pt의 `정산내역 ABC123`은 100% 한 줄에서 25~55% 두 줄로 바뀌며 고정 행 높이에서 아래 줄이 잘렸다. 맑은 고딕도 일부 작은 배율에서 같은 문제가 나타났다.

`GridView.setZoom`을 100% 레이아웃에 `transform:scale(z)`를 적용하는 방식으로 바꿨다. 셀 폭·높이·hitTest·편집 위치는 기존 뷰 배율 계약을 사용한다. 셀 글꼴 크기, 행/열 크기, 문서 저장 배율, 수식 및 XLSX 모델은 변경하지 않는다. 배율별 선 두께·픽셀 정렬 재렌더는 유지한다.
