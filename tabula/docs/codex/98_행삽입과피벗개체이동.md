# 행 삽입과 피벗·개체 이동

2026-10-07, 기준 `316020f`, 작업 브랜치 `codex/pivot-row-insert`.

## 원인과 처리

전체 행·열을 삽입하거나 삭제하면 기존 셀은 이동했지만 피벗의 `top`/`left`, 출력 `area`, 필터 `buttons`의 절대 좌표는 남아 있었다. 이후 새로 고침이 이전 위치를 사용하면 옮겨진 셀과 필터 단추가 분리되고 표가 다른 개체와 겹친다. `Workbook.shiftAxis`가 출력 범위·시작 좌표·단추 좌표를 셀과 함께 조정한다. 삭제된 단추는 제거하고 출력 전체가 삭제된 피벗 정의도 제거한다. 원본 데이터 범위와 다른 시트의 소비자 정의를 조정하던 기존 처리는 유지한다.

`pivot-structure-cache.js`는 렌더 역할 배열, 행 깊이와 마지막 생성 서식의 `CellMap` 좌표를 함께 이동한다. 전체 이동은 불변 역할/서식을 공유하고 내부 삽입·삭제는 필요한 배열을 복사한다. 실행 취소 메타에 변경 전·후 캐시와 슬롯을 기록하여 복제된 시트/정의에 다시 연결한다. 일반 피벗 필드 변경도 같은 전·후 렌더 스냅샷을 기록하여 필드 Undo 뒤 삽입·새로 고침에서 현재 수동 서식을 보존한다. 원본 변경에 따른 자동 새로 고침이 `joinPrev`로 합쳐지면 변경 후 캐시도 갱신한다. 스냅샷은 큰 시트나 정의 객체를 강하게 참조하지 않는다. 이전 필드 변경의 Undo로 오래된 정의를 가리키는 캐시는 현재 캐시로 승격하지 않는다. `cellFmt`는 절대 셀 좌표가 아닌 피벗 역할 키이므로 이동시키지 않는다.

그림·도형·차트·슬라이서는 기존 `captureDrawingAnchors`/`reflowDrawingAnchors`를 같은 구조 변경 트랜잭션 안에서 적용한다. Excel의 `oneCell`은 위치만, `twoCell`은 위치와 크기, `absolute`는 고정 배치를 유지한다. 실제 그림 이동 자체는 기준 코드의 합성 검사에서도 작동했으며, 이번 변경은 피벗 좌표 및 새로 고침과 일관되게 연결한다. 이동을 무조건 적용하도록 개체 설정을 덮어쓰지 않는다.

## 조작과 안내

- 행 머리글 크기 조절 판정은 3 CSS 픽셀과 해당 행 높이의 20% 중 작은 값으로 제한한다. 짧은 행과 낮은 배율에서도 가운데 60%를 선택에 사용할 수 있다. 열 머리글은 기존 기준을 유지한다.
- 삽입 탭의 실제 행 삽입과 F4 반복 동안 선택한 행을 유지한다. 리본/일반 버튼/시트 탭에 초점이 있어도 F4를 처리하며 셀 편집의 참조 `$` 전환, 팝업·입력·보호 거절은 기존 경로를 따른다.
- 다른 피벗과 겹치는 변경은 전체 예상 범위를 먼저 검사하고 원자적으로 거절한다. 겹침 안내는 8초간 표시한다. 실제 결과가 기존 공간보다 커지는 경우는 계속 차단한다.

## 제공 파일의 근거

업무 원본과 저장본은 읽기만 했고 Git 및 공개 브라우저 검사에 포함하지 않는다. 상세 XML·모델·로그는 D:의 무시된 `.local/pivot-row-insert` 아래에 보관한다.

두 파일 모두 16개 시트/19개 피벗이며 `DA_소재별`에 12개가 있다. 원본과 저장본의 12개 피벗 시작 좌표는 동일하고 6개는 마지막 행만 다르다. drawing3.xml에는 각각 43개의 앵커(그림20, 도형22, 슬라이서1)가 있다. 그림20개와 슬라이서는 모두 `oneCell`, 도형22개는 `twoCell`이고 absolute는 없다. 이름별 그림20개 모두 저장본에서 from/to 행이 +43이며 열은 같다. 해당 시트 dimension도 A1:W314에서 A1:W357로 늘었다. 시트 구조·개체 위치와 피벗 시작 기록이 어긋났다는 근거다.

두 파일의 전체 셀 데이터도 다르므로 저장본을 동일 데이터에 행만 삽입한 복사로 간주하거나 정확한 편집 순서를 단정하지 않는다. 원본 2,222,672 cells, 저장본 2,143,389 cells이며 수식은 각각18,380개다. 수동으로 저장본의 피벗 시작 행을 추정해서 고치거나 원본 파일을 덮어쓰지 않았다.
