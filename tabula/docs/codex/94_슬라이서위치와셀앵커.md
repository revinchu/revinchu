# 슬라이서 위치와 셀 앵커 보존

2026-10-06. 기준: `79a0f97`.

## 위치 계산과 변경

Excel의 drawing 좌표는 보기 배율과 독립적인 시트 좌표다. 셀 앵커는 행·열 번호와 셀 안의 EMU 오프셋으로 저장된다. `twoCell`은 셀 변화에 따라 이동·크기를 조정하고, `oneCell`은 위치만 이동하며, `absolute`는 위치와 크기를 유지한다. 슬라이서의 기본 배치는 이동만이다.

- `drawing-anchor.js`로 캡처·재배치를 공통화하고, 소수 픽셀을 반올림하지 않는다. 다른 종류 개체의 ID가 같아도 분리하여 처리한다.
- 파일을 열 때 자동 높이를 적용하기 전에 모든 해당 시트의 앵커를 캡처한다. 사용자가 지정한 행 높이는 유지한다.
- 셀 입력·서식의 자동 높이/너비, 높이·너비 대화상자, 기본 열 너비, 열 너비 붙여넣기, 전체 행·열 서식 복사, 필터 단추 자동 너비와 피벗 자동 너비에서도 앵커를 적용한다. 피벗의 대상 시트가 활성 시트와 달라도 해당 시트의 축을 사용한다.
- 배치 속성에 따른 개체 변경은 셀 크기 변경과 같은 실행 취소 기록에 포함한다.
- 숨긴 앵커 셀은 같은 화면 좌표를 가진 다음 셀과 구분하여 _hiddenCellAnchor 메타데이터로 보존한다. 현재 좌표와 일치할 때만 재사용하고 보이는 축으로 복원하면 제거한다. JSON 저장과 실행 취소의 복제 후에도 숨김 취소로 원래 위치를 복원한다. 표준 XLSX 저장 후 다시 여는 경우의 숨긴 셀 정체성까지 완전 보존한다는 보장은 이 검증에 포함하지 않는다.
- 명시된 열 너비의 1px 차이를 customWidth 유무와 관계없이 읽고, AlternateContent의 슬라이서 그룹을 그룹 좌표로 변환한다.
- 확대·축소는 격자와 개체에 공통 보기 변환만 적용한다. 표를 피하려고 임의로 개체를 이동시키지 않는다.

근거: [Excel XlPlacement](https://learn.microsoft.com/en-us/office/vba/api/excel.xlplacement), [Open XML TwoCellAnchor](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.spreadsheet.twocellanchor?view=openxml-3.0.1). 이 변경은 공개 문서의 위치 규칙과 파일 앵커에 대한 구현이며 Excel의 비공개 내부 알고리즘을 복제했다는 의미는 아니다.

## 사용자 원본 검증

사용자가 지정한 XLSB 원본은 읽기만 하고 실제 업무 데이터와 검증 화면은 Git에 포함하지 않는다. 대시보드·키워드·검색어 시트의 슬라이서 22개를 25/55/70/100/150/200/400%로 표시해 DOM과 모델의 좌표를 확인한다.

대시보드의 상단 정보표 B2:C5는 시트 좌표에서 오른쪽이361px, 아래쪽이90px다. 캠페인 슬라이서는 x370.999895px로 약10px 간격을 유지하고, 년월·캠페인유형의 y97.176378px는 정보표 아래에서 약7.176px 간격을 유지한다. 확대율을 바꿔도 시트 좌표로 정규화한 간격은 유지한다. 해당 원본을 열기 전후의 행 높이와 열 너비는 변하지 않았다.

원본의 호환용 Fallback 도형에는 현재 셀 앵커와 다른 크기·행 높이가 기록되어 있었다. 일부 슬라이서 높이는 Fallback235px, 앵커126.6px로 서로 크게 달라 오래된 호환 정보일 수 있다. Fallback 값을 일괄 적용하는 수정은 하지 않는다. 네이티브 Excel 실제 좌표의 별도 확인은 새 인스턴스에서 읽기 전용 통합 문서 검증이 성립하지 않아 미확인으로 기록했다.

수정 전 파서에서도 해당 원본의 앵커 좌표는 동일했다. 따라서 원본에서 이번 문제의 정확한 이전 UI 조작 순서까지 재현했다고 주장하지 않는다. 자동 높이 적용 누락과 반복 편집의 소수 좌표 손실은 별도의 합성 XLSX에서 수정 전 HEAD로 재현했다.
