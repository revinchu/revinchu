# 111. 외곽 테두리 모서리 연결 (2026-10-14)

## 수정

가로·세로 실선은 셀 경계의 위/왼쪽에 선 두께만큼 놓이지만, 선의 시작점은 셀 경계에서 시작했다. 따라서 왼쪽 위 접점에 가로선 두께 × 세로선 두께의 빈 사각형이 남았다. 남색 머리글·내부 점선·병합 셀을 가진 합성 표에서 재현했다.

`gridBorderJoins`는 공유 경계 중복 제거 뒤, 실제로 만나는 다른 축의 실선 두께까지 끝점을 연결한다. 배율/DPR에 맞춘 기존 두께와 강한 선을 나중에 그리는 순서를 유지한다. 원점은 클리핑을 피하는 기존 안쪽 배치를 따르며, 독립 선·점선·이중선 간격은 연장하지 않는다. 축별 인덱스와 이진 탐색을 사용하며 원본 경계 객체는 변경하지 않는다.

검증 중 소스 서버의 시작 실패도 확인했다. `src/ai-ui.js`가 공개하지 않는 `server/ai-provider.js`를 가져와 HTTP 403이 발생했다. 공급자 설정을 `src/ai-providers.js`로 분리하여 UI와 서버가 공유한다. 서버 전용 경로 접근 차단과 API 키 처리 정책은 유지한다. 이전 공개 번들은 이 의존성을 포함했으므로 해당 시작 실패는 로컬 소스 실행의 문제였다.

## 검증 방식

- `tools/grid-border-corners.mjs`: 실제 PNG에서 표의 네 변 중간의 검정 띠를 찾고, 교차 사각형의 빈 픽셀을 검사한다. 렌더러의 좌표 계산 함수를 기대값으로 재사용하지 않는다. thin/medium/thick와 서로 다른 두께, 남색 머리글 병합, 내부 점선, 숨긴 행/열, 틀 고정, 분수 스크롤을 포함한다.
- DPR 1/1.25/1.5/2 × 배율 50/75/80/100/125/200% × 일반/숨김·고정·스크롤. 수정 전 Chromium 48조건·1,538검사에서 왼쪽 위 접점 192개가 실패했다.
- 기존 `grid-rendering.mjs`: 40조건·2,247검사 통과. 가는 선·중간/굵은 선·이중선·점선·채우기·교차점·병합·선택·편집·필터 회귀를 확인했다.
- 새 Node 검사: 실선 접점, 독립 끝점, 점선/이중선, 배율/DPR, 긴 병합 T 접점, 원점, 원본 불변, 실제 AI UI 의존성의 HTTP 접근 및 서버 소스 차단.

계산·피벗 집계·XLSX 입출력 코드는 변경하지 않는다. 합성 화면의 표시 검증이며 모든 Excel 문서의 모든 서식에 대한 픽셀 일치 판정은 아니다. 이중선끼리의 모서리 모양은 이번 실선 보정 범위 밖이다. 사용자 원본 파일과 업무 캡처는 커밋하지 않는다.
