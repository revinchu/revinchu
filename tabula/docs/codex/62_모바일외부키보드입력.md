# 62. 모바일 외부 키보드 입력

기준: `8fee9e8`. 사용자 환경은 iPhone 홈 화면으로 등록한 위셀, Bluetooth 마우스·키보드, 모바일 작업 모드다. 입력할 때 화면 키보드가 올라와 작업 공간을 가리는 문제를 다룬다.

## 입력 정책

`src/mobile-keyboard.js`는 문서와 분리된 기기 설정 `wixel.mobile-keyboard.v1`에 `auto`/`hardware`/`screen`을 저장한다. 모바일 작업 도구의 **키보드 → 외부 키보드**는 입력창을 편집 가능한 상태로 유지하며 `inputmode="none"`만 적용한다. **화면 키보드**는 원래 입력 모드를 복원하고, **자동 감지**는 새 감지 세션을 시작한다. 모바일 작업 모드를 끄면 기존 속성을 복원한다.

자동 감지는 연결된 Bluetooth 장치 목록을 읽는 기능이 아니다. 비입력 대상에서 도착한 신뢰된 키 입력을 작업 방식의 신호로 사용한다. 가상 키보드도 KeyboardEvent를 만들 수 있으므로 물리 연결 여부를 확정하거나 연결 해제를 탐지했다고 표현하지 않는다. 조합 중 이벤트, 229·Dead·Process·Unidentified, modifier 단독은 자동 감지에 사용하지 않는다. 첫 한글 조합부터 사용하려면 명시적 외부 키보드 모드가 가장 확실하다.

## 포커스와 편집

모바일 기본 상태의 비편집 격자에 포커스가 있을 때 일반 문자가 실제 입력란으로 전달되지 않는 기존 경로를 WebKit에서 재현했다. 외부 키보드 정책에서는 idle 상태도 기존 `cellEditor`를 포커스하므로 native beforeinput/input/composition 처리를 그대로 사용한다. keydown으로 문자를 직접 합성하거나 readonly/disabled로 키보드를 막지 않는다.

`ui.el()`은 새 입력란이 포커스를 받기 전에 정책을 적용한다. 기존 입력란과 동적으로 추가된 입력란, 수식줄·검색·대화상자에도 같은 정책을 적용하고 원래 inputmode의 없음/빈값/명시값을 구별해 복원한다. 키보드 설정은 모바일 도구를 닫기 전에 바꿔 포커스 복원 순간에 옛 정책이 적용되지 않게 한다. 조합 중에는 정책 변경을 보류하고 native 조합·입력값을 유지한다.

## 플랫폼 범위

- [HTML inputmode 표준](https://html.spec.whatwg.org/multipage/interaction.html#attr-inputmode)은 none을 가상 키보드를 표시하지 않는 힌트로 정의한다.
- [WebKit iOS 구현](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/ios/WKContentViewInteraction.mm)은 InputMode::None의 자동 키보드 표시를 제한한다. 현재 소스의 지원과 사용자의 설치 iOS 버전 실측은 구분한다.
- [UI Events](https://www.w3.org/TR/uievents/#code-virtual-keyboards)는 가상 키보드의 키 이벤트도 설명한다.
- [Apple AssistiveTouch 안내](https://support.apple.com/ko-kr/guide/iphone/iph96b21954/ios)의 **설정 → 손쉬운 사용 → 터치 → AssistiveTouch → 화면 키보드 보기**는 별도 OS 설정이다. 앱에서 이 설정을 바꾸지 않으며 이번 원인이라고 단정하지 않는다.

실제 iPhone의 화면 키보드 표시 여부와 Bluetooth 한/영 전환·후보창은 이 개발 환경에서 직접 확인할 수 없다. 브라우저 모사는 입력 정책·native 입력 이벤트·문서 보존을 검증하며 iOS 시스템 키보드를 재현하지 않는다.

## 검증

최종 JavaScript `wixel-fedb36b08a086f7a.js`:

| 검사 | 결과 |
|---|---|
| 전체 Node (입력 정책 신규 13개 포함) | 1,147/1,147 |
| 단일 HTML·Cloudflare 빌드 | 모두 성공 |
| 최종 전체 리본 명령 | 386개, bad 0 |
| 외부 키보드 UI Chromium·WebKit | 각각 14/14·164검사, 총 28시나리오·328검사 |
| 모바일 마우스·터치 회귀 Chromium | 26/26·271검사 |

외부 키보드 UI는 첫 ASCII 자동 전환, 연속 입력 중복 없음, Enter/Tab/Escape, Undo/Redo, 수식줄, 찾기·글꼴 검색·크기 입력, 화면 입력 모드 복원, 합성 한글 조합, auto 초기→UI hardware 선택→reload 설정 유지, 데스크톱 비활성, 터치 셀 선택 후 외부 입력을 검사했다. 페이지 오류·원격 쓰기는 0이다. IME는 native composition 이벤트 순서의 합성이며 실제 iPhone 언어 전환 검사가 아니다.

독립 리뷰에서 compositionend 없이 조합 대상이 DOM에서 제거되면 정책 복원이 영구 보류되는 문제를 찾아 수정했다. 살아 있는 조합은 유지하고 제거된 대상은 정리한다. Chromium·WebKit 독립 DOM 검사 및 Node 회귀로 확인했다.

도구는 `tools/mobile-hardware-keyboard.mjs`, 단위 검사는 `test/mobile-keyboard.test.js`다. 로그는 `.local/mobile-keyboard-*.log`, `.local/mobile-hardware-keyboard-compiled-final-*.log`, 결과/캡처는 `D:/Codex/Temp/wixel-mobile-hardware-keyboard/compiled-final-*/`에 있다. 배포 식별자와 공개 자산 바이트 검증은 `.local/mobile-keyboard-release.json`에 기록한다.

마우스·터치 회귀는 동일 입력 정책을 포함한 직전 번들 `wixel-45ed2f6267f3d10b.js`에서 실행했다. 최종 번들은 메뉴·대화상자 첫 포커스 전에 정책을 한 번 더 적용하는 보완과 선택 버튼 색상만 추가했고, 키보드 전체 28시나리오와 리본 386명령을 다시 검사했다.
