# 피벗 보고서 필터 (2026-10-03)

## 확인한 문제와 수정

새 피벗에서 보고서 필터만 배치하면 `computePivot`이 기본 제공 스타일 처리 전에 반환했다. 본문을 추가하면 필터 채움·테두리가 바뀌었으며 새 시트의 가운데 정렬도 상속했다. 가져온 파일은 셀 서식을 캡처하므로 같은 피벗인데 다른 모양으로 보였다.

- 필터 전용/본문 포함의 캡션·항목·스타일 계산을 통일하고 일반 정렬을 명시했다. 파일·사용자 지정 서식은 우선 보존한다.
- `pivotPageLayout(def)`가 행 우선/열 우선, `pageWrap`, 필드 이름/값 좌표를 계산한다. 필터 사이에는 빈 열 하나, 본문 앞에는 빈 행 하나를 둔다. `meta.pageFields`와 셀 `field`로 가로 배치에서도 필터 단추와 우클릭이 실제 필드를 가리킨다. 본문 폭과 필터 폭을 분리했다.
- 새 피벗 A3에 첫 보고서 필터를 추가하면 A1/B1에 필터를 배치하고 본문 기준 위치는 A3을 유지한다. 위쪽 공간이 부족하면 필요한 만큼 본문을 내리며 위쪽 사용자 입력이 있으면 기존 시작 행을 유지한다.
- 갱신 시 이전 피벗이 사용한 셀만 정리한다. 필터 사이 열·미배치 칸·본문 앞 빈 줄·오른쪽의 사용자 내용은 보존하며 재배치 후 이전 필터가 남지 않는다.
- 셀 안 드롭다운의 공간을 텍스트와 분리해 가운데·오른쪽 정렬에서도 겹치지 않게 했다. 보고서 필터만 있을 때의 자동 너비 맞춤도 연결했다.
- 표시 옵션을 `showHeaders`로 저장해 `fieldCaptions` 사용자 이름 사전을 덮어쓰지 않는다. 행·열 머리글 표시와 보고서 필터는 구분한다. 줄바꿈 입력은 0~255 정수로 검증하며 배치 방향에 맞는 설명을 표시한다.
- XLSX는 필터 전용 피벗도 실제 피벗 정의로 저장한다. 표준 `pageOverThenDown`, `pageWrap`, `rowPageCount`, `colPageCount`와 필터를 제외한 본문 `location`을 읽고 쓴다. 빈 본문 앵커, 필터 전체 너비, 필드 이름과 선택 모드를 보존한다.

- XLSB의 `BrtBeginSXView`에서 `fAcrossPageLay`와 `cWrapPage`를 읽어 같은 보고서 필터 배치로 전달한다. [MS-XLSB 2.4.278](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xlsb/f6cbfd44-775f-44f6-8ba8-fac46d7a445c)에 맞춰 기존에 건너뛰던 필드만 복원했다.

## Excel 기준 확인

별도 숨김 Excel 16.0(build 14334) 인스턴스에서 개인 자료 없는 예제를 생성했다. 필터 전용/본문 포함, 행·열 우선과 wrap 0/2, 머리글 표시 해제, A3의 첫 필터 배치를 비교했다. 필터 간 간격은 세 열 단위이며 `location`은 보고서 필터를 제외한 본문이다.

피벗 스타일의 실제 색은 `Range.Interior`가 아닌 `DisplayFormat`으로 확인해야 한다. Light16·Medium9·Dark1 각각 필터 전용/본문 포함의 실제 채움·글자·테두리를 비교했으며, 원래 셀 서식이 흰색이어도 피벗 스타일은 화면에 적용된다.

## 검증

- 전체 Node 테스트 1,036/1,036 통과, 두 빌드 완료.
- 실제 UI 신규 생성·보고서 필터 회귀: 소스/최종 번들 각각 16/16, 153검사 통과. 320/390px, Undo 후 다른 배치, 사용자 빈 열 병합 보존, 실제 XLSX 다운로드와 재열기 포함.
- 기존 필터 검색·선택 회귀: 소스/번들 각각 29/29, 181검사. 피벗 우클릭 16/16·73검사, 번들 표시 옵션 8/8·226검사 통과.
- 최종 번들 리본 385명령 bad 0. 브라우저 검사의 페이지 오류·원격 쓰기 0.
- Excel 합성 9개를 WIXEL 저장 → 실제 Excel 일반 열기·새로 고침·저장 → WIXEL 재읽기: 9/9, 162검사 통과. 필터 전용 피벗에 빈 dataFields를 쓰면 Excel이 거절하는 문제도 발견해 실제 필드가 있을 때만 출력하도록 수정했다.
- Excel 합성 9개의 XLSB 저장 → WIXEL 읽기 → XLSX 재읽기: 9/9·1,125검사. 가로/세로·wrap 0/2의 값과 필터 좌표·범위를 비교했다. 브라우저에서 직접 생성해 내려받은 XLSX도 실제 Excel 열기·새로 고침·재저장 및 재읽기 44검사 통과.
- 클래식 피벗 실제 끌기 13회·61검사 통과.
- 실제 업무 파일 2개: 수식 8,545개/698개 각각 수정 전후 불일치 0·왕복 오류 0, 79/29시트 로드, 원본 SHA 동일. 두 실제 파일에 피벗은 없으므로 pvcmp 0/0을 피벗 호환 증거로 세지 않으며 피벗 근거는 별도 Excel 합성 파일이다.
- 새 필터 1개와 가로 줄바꿈 화면 PNG를 직접 확인했다. 수정 전/후 캡처와 로그를 분리 보관했다.

구형 XLS는 저장된 셀 값과 서식만 읽으며 피벗 정의를 편집 가능한 형태로 복원하지 못하는 기존 제한이 있다.

실제 Excel의 일부 테마색과 기존 WIXEL tint 계산에는 1~2 RGB 반올림 차이가 남는다. 이번 스타일 검증은 선택한 스타일의 채움·테두리·글자 강조와 생성/가져오기 일관성을 확인한 것이다.

 실제 업무 파일은 커밋하지 않는다. 합성 파일·캡처·로그는 D:/Codex/Temp/wixel-pivot-report/ 및 D:/Codex/Temp/wixel-pivot-report-layout/에 보관한다. 이 검증은 보고서 필터의 생성·표시·배치·선택·저장 경로에 대한 것으로 Excel의 모든 피벗 기능에 대한 100% 동등성을 의미하지 않는다.
