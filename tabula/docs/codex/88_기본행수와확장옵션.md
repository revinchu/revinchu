# Excel 기본 행 수와 선택적 확장

## 동작과 설정

기본 작업 범위는 1,048,576행이다. [파일 → 옵션 → 일반]의 **위셀 행수 확장**을 명시적으로 켜면 20,000,000행까지 표시·이동·편집한다. 열 한도는 기존 16,384열이다. Excel 행·열 기준은 [Microsoft의 사양과 제한](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits)을 따랐다.

설정은 브라우저의 wixel.options.extendedRows에 저장하며 통합 문서 데이터와 분리한다. 기존 옵션에 값이 없거나 true가 아니면 기본 모드다. 확인 전 체크 변경과 취소는 화면 한도에 영향을 주지 않는다. 파일·시트를 바꾸거나 다시 접속해도 확인한 설정을 유지한다. 행수 옵션만 바꾸는 경우 문서 버전·수정 내용·Undo 기록을 만들지 않는다.

## 구현과 데이터 보존

- row-limits.js가 표시 한도를 결정한다. 계산·파일 파서의 MAX_ROWS는 바꾸지 않는다.
- GridView의 행 축, 스크롤 끝, 가상 범위, 틀 고정, 병합 표시, ARIA 행 수를 표시 한도에 맞춘다. 해제 시 늘어난 extR과 화면 캐시를 줄인다.
- 셀/전체 열 선택, Ctrl+방향키·End·Enter·Tab, 이름 상자와 범위 이동, 채우기, 붙여넣기, 분석 결과 출력을 현재 작업 범위에서 처리한다.
- 경계 초과 붙여넣기·자동합계·행 삽입을 부분 적용하지 않는다. 경계를 가로지르는 병합과 숨은 확장 데이터·행 서식이 구조 변경으로 영향을 받는 경우 확장 옵션을 안내한다. 확장 영역을 포함한 잘라내기는 해제 시 취소하고 원본을 유지한다.
- 기본 모드의 찾기/바꾸기는 표시 행 안으로 제한한다. 전체 행 높이 변경으로 확장 영역의 높이·숨김 서식을 덮어쓰지 않는다.
- 확장 해제는 셀·수식·병합·행 높이·인쇄 설정을 삭제하지 않는다. 수식에서 이미 참조하는 확장 셀의 값도 계산한다. 가져온 CSV/WIXEL/Excel 원본 데이터를 화면 한도로 잘라내지 않는다.
- 실제 인쇄, HTML 내보내기, 개체 앵커 계산은 별도의 전체 문서 축을 사용한다. 화면 모드가 출력 범위나 개체 좌표를 잘못 바꾸지 않도록 한다. 인쇄 제목의 기존 확장 행 참조도 보존한다.
- WIXEL 저장은 확장 데이터까지 보존한다. XLSX의 실제 규격 밖 데이터는 기존처럼 저장을 중단하고 WIXEL 저장/범위 분할을 안내하며 조용히 삭제하지 않는다.

빈 행 100만/2천만 개를 생성하는 구현이 아니다. 기존 희소 셀·열 블록·가상 화면 처리를 유지한다. 이번 변경은 일반 작업의 화면·편집 한도를 낮추는 것이며, 실제 값이 들어 있는 파일의 모든 데이터를 덜 읽거나 파일 크기와 관계없이 메모리를 일정하게 유지한다는 보장은 아니다.
