# 24. 자유곡선과 도형 서식 (2026-10-02)

## 그리기와 점 편집

삽입 → 도형 → 선 갤러리에 곡선, 자유형: 도형, 자유형: 자유곡선과 양쪽 화살표 연결선을 추가했다. 기존 직선·꺾인 연결선·곡선 연결선은 유지한다. 곡선은 지정한 점을 통과하는 cubic Bezier 경로를 만들고, 자유형/자유곡선은 클릭하거나 끌어서 얻은 점열을 선분으로 보존한다. 닫힌 경로는 채우기를 사용할 수 있다.

`shape-path.js`의 `shapeFromPoints(kind, points, {closed})`는 시트 좌표를 도형의 `x/y/w/h`와 정규화 경로로 변환한다. 한 경로의 점 입력은 최대9,998개로 제한하며 초과·비수치·서로 다른 점이 없는 입력을 조용히 잘라내지 않고 오류로 알린다. 이동·크기 변경 시 원래 점 배열은 수정하지 않는다.

공통 모델은 다음과 같다. Bezier 제어점은 경계 밖에 있을 수 있으며, 경계 계산은 제어점의 바깥 사각형이 아니라 실제 곡선의 극값을 사용한다.

```js
shape.path = { paths: [{
  commands: [['M', 0, 0], ['C', 0.2, 0.6, 0.8, 0.4, 1, 1]],
  fill: false,
  stroke: true,
}] };
```

M(이동), L(직선), C(3차 곡선), Q(2차 곡선), Z(닫기), 여러 하위 경로를 지원한다. SVG와 편집점은 같은 `0..w`, `0..h` 좌표를 사용한다. 기존 `flip/flipV/rot`로 대칭·회전을 처리한다. `shape-edit.js`는 꼭짓점/제어점 이동·추가·삭제, 곡선 분할과 편집 뒤 경계 정규화를 담당하고, 문서 변경·선택·Undo는 앱의 트랜잭션에서 처리한다.

Microsoft가 설명하는 자유형/자유곡선 그리기와 점 편집 동작을 기준으로 삼았다. WIXEL의 곡선 보간 알고리즘과 모든 편집 제스처가 Excel의 내부 구현과 동일하다는 뜻은 아니다. [Microsoft 자유형 도형 그리기 및 편집](https://support.microsoft.com/en-us/office/graphics-visuals/draw-or-edit-a-freeform-shape)

## 도형 서식

독립 `shape-format-ui.js` 패널은 도형의 현재 모델을 읽고 변경 콜백을 통해 적용한다. 단색·그라데이션·무늬 채우기, 윤곽선, 효과, 텍스트, 크기·위치·대체 텍스트 옵션을 실제 렌더와 저장 모델에 연결한다.

| 항목 | 이번 지원 범위 |
|---|---|
| 선 끝 | 없음·삼각형·오목 화살표·마름모·원형·열린 화살표, 시작/끝 각각 너비·길이 3단계 |
| 선 모양 | 실선 및 점선/파선 계열, 끝 모양 flat/rnd/sq, 이음 round/bevel/miter |
| 겹선 | 단일·이중·삼중, SVG 마스크로 선 사이를 비운다 |
| 무늬 | 5%·25%·50% 점/격자, 가로·세로·십자·양방향 대각선·대각선 격자 9종 |
| 효과 | 기존 그림자·네온·부드러운 가장자리를 일반 도형뿐 아니라 선·자유 경로에도 적용 |
| 텍스트/크기 | 기존 글꼴·맞춤·여백, 텍스트 축소 맞춤, 0/90/270도 텍스트 회전, 가로세로 비율 잠금 |

내부 필드는 `headEnd/tailEnd: {type,w,len}`, `lineCap`, `lineJoin`, `compound`, `pattern: {preset,fg,bg}`, `textFit`, `textRot`, `lockAspect`, `alt`다. 기존 `arrow: start/end/both`도 읽는다. 화살표 시작점만 있는 파일을 가져올 때 도형을 뒤집어 대체하던 처리를 없애고 실제 시작 화살표로 보존한다.

## XLSX 표준 저장

자유 경로는 `a:custGeom`의 `a:pathLst`, `moveTo/lnTo/cubicBezTo/quadBezTo/close`로 저장한다. 경로 기하를 복구하는 데 WIXEL 전용 확장이 필요하지 않다. 크기·회전·대칭, 선 끝·대시·겹선·끝/이음 모양, 패턴 색/공통 투명도, 비율 잠금, 대체 텍스트, 텍스트 회전·축소 설정도 DrawingML 표준 요소에 기록한다. [Microsoft DrawingML CustomGeometry](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.customgeometry?view=openxml-3.0.1)

리더는 숫자 좌표와 간단한 `val` 가이드, 기본 w/h/r/b 등의 좌표 이름을 해석한다. 복잡한 가이드 수식과 `arcTo` 사용자 지정 경로는 아직 화면에서 해석하지 못한다. 이 경우 경고하며 가져온 `customGeometry` 트리를 표준 DrawingML로 다시 저장한다. 화면의 대체 사각형이 원래 기하와 같다는 뜻은 아니다. 해당 도형의 점 편집은 지원 대상으로 취급하지 않으며, 알 수 없는 원본 요소를 저장할 수 없으면 조용히 버리지 않고 오류로 알린다.

가져오기 경고를 모으던 `Set`을 배열 전용 `pushAll`에 넘겨 경고가 사라지던 문제도 수정했다. 새 경로 호환 경고가 실제 `readXlsx().warnings`에 포함되는 회귀 검사를 추가했다.

Excel 전체 도형 서식과 100% 동등하지 않다. 도형 간 연결점에 붙어 따라가는 연결선, 모든 기본 도형의 조절점, 모든 DrawingML 가이드/호, 3D 재질·조명·회전, 비대칭 겹선의 동일한 SVG 표현은 이번 범위에 포함하지 않는다. 가져온 `thickThin/thinThick` 겹선 값은 저장 시 보존하지만 화면에서는 단일선으로 표시하며 새 선택 항목으로 제공하지 않는다. 무늬의 미세한 픽셀 배치, 글꼴 측정·축소율, 그림자·네온의 모양은 브라우저와 Excel에서 차이 날 수 있다. 실제 사용자 업무 파일은 이 검증에 사용하지 않았다.
