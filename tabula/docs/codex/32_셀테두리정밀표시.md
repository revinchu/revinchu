# 32. 셀 테두리 정밀 표시 (2026-10-02)

## 확인한 차이

사용자가 제공한 Excel/WIXEL 화면과 같은 원본의 같은 표를 비교했다. 원본에서 주요 세로선은 검정 thin, 가로선은 회색 `#D0CECE` thin이며 머리글 아래에 medium과 double이 있다.

| 첨부 화면의 실제 픽셀 | Excel | 수정 전 WIXEL |
|---|---:|---:|
| 검정 세로 thin | 1px | 2px |
| 회색 가로 thin | 1px | 2px |
| 머리글 medium | 2px | 2px |
| 머리글 double | 1px + 간격 1px + 1px | 1px + 간격 2px + 2px |
| 검정 세로·회색 가로 교차점 | 검정 연속 | 회색 가로선에 의해 단절 |

회색선과 교차하는 내부 세로선 7곳, 이중선의 빈 구간 5곳을 확인했다. 가로선 색 `#D0CECE`와 채움색 `#F2F2F2`는 양쪽이 같았다. 색을 바꾸지 않고 두께와 겹치는 순서를 수정했다. 원본의 업무 내용·파일·캡처는 커밋하지 않는다.

## 변경

- `gridLineWidth`: 화면의 thin은 1 장치 픽셀, double은 각 획과 간격이 1픽셀인 3픽셀로 유지한다. medium/thick의 기존 배율 계산은 유지한다. XLSX의 서식과 실제 인쇄용 모델을 변경하지 않는다.
- `gridBorderPaintOrder`: 같은 경계의 중복 제거 뒤, 굵은 선·이중선·어두운 선이 교차점에서 우선하도록 그린다. 공유 경계 자체의 충돌 선택 규칙은 유지한다.
- `view.js`: 실선과 이중선을 중심선 SVG stroke로 그린다. 사각형 양끝이 각각 반올림되면 특정 배율에서 2픽셀이 1픽셀이 되는 문제를 피한다. 미세하게 폭을 늘리는 임시 보정은 넣지 않았다.
- 분수 스크롤에서는 창 원점과 선의 끝점을 장치 픽셀에 정렬하여 한 픽셀 선이 두 픽셀로 번지는 것을 막는다. 창 원점의 위치 보정은 최대 반 장치 픽셀이며 문서의 셀·개체 좌표는 바꾸지 않는다. 채움 셀 네 면의 눈금선 가림도 보정한다.
- `.cell-fill`: 넘치는 글자의 배경을 별도 층에 두어 셀 채우기가 테두리를 덮지 않게 한다. 글자·체크박스·필터의 조작 위치는 유지한다.
- 가는 점선·점쇄선·이점쇄선과 중간 굵기 변형의 dash 패턴을 구분한다. 연속 구간이 나뉘어도 시트 좌표 기준으로 패턴 위상을 유지한다. 사선 점쇄선의 완전한 Excel 도안 일치까지 확인한 것은 아니다.

## 검증

- Node 전체 707개 통과. 테두리 단위 검사는 두께·공유 경계·교차점 우선순위·색 표기·원본 불변을 검사한다.
- `tools/grid-rendering.mjs`는 PNG 장치 픽셀을 직접 읽는다. 기대값은 thin 1px, double 1+1+1px이며 제품의 두께 함수를 재호출하여 기대값을 만들지 않는다. DPR 1/1.25/1.5/2와 배율 50/75/80/100/125%, 흰색/검정 테마를 포함한다.
- 별도 반올림 재현에서는 DPR 1.5의 배율 80/125% × 분수 스크롤 20단계 × 1/2/3/4픽셀 × 가로/세로를 비교했다. 중심선 SVG 경로는 320개 폭 검사에서 정확했다.
- 실제 원본(약 55.7MB, 79시트)을 격리된 로컬 브라우저에서 읽었다. 수식 8,545개 비교와 XLSX 저장 왕복 차이는 수정 전후 모두 0이다. 원본 SHA256도 동일하다. 피벗이 없는 문서이므로 피벗 호환성 검증으로 계산하지 않는다.
- 실제 표에서 DPR 1의 배율 100/75/60%, DPR 1.5/2의 배율 100/80/50%를 비교했다. 원본 파일이나 사용자 브라우저를 수정하거나 서버에 업로드하지 않았다.

소스 화면의 40조건·2,247개 확인 항목이 모두 통과했다. 페이지 오류·원격 쓰기 0, 현재 PC의 단일 실행에서 renderAll 중앙값 11.5ms(최소 9.6ms, 최대 14.7ms)였다. 이 시간은 합성 화면의 관측값이며 모든 파일에 대한 속도 보장은 아니다. 그룹 개체 6개, 모바일 터치 10개, 차트 직접 편집 및 겹친 필터 회귀 검사도 통과했다. 최종 Cloudflare 번들도 같은 40조건·2,247개 검사에서 모두 통과했다. 리본 명령 324개 오류 0, 단축키 114개 오류 0을 확인했다. 최종 번들에서 실제 원본의 DPR 1.5·100/125% 캡처도 thin 1px, double 1+1+1px, 교차점 끊김 0으로 확인했으며 원본 해시와 문서 크기는 유지됐다.

## 범위

이번 결과는 첨부 표의 선 두께·이중선·교차점 및 명시한 합성 조건에 대한 검증이다. 전체 Excel 화면을 모든 OS·브라우저·폰트·DPI에서 픽셀 단위로 완전히 동일하게 구현했다는 의미는 아니다. 인쇄/PDF와 숨김 Excel의 CopyPicture 결과는 화면 스크린샷과 다른 경로이므로 화면 픽셀 기준으로 사용하지 않았다.

선 종류의 파일 의미는 [Open XML BorderStyleValues](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.borderstylevalues?view=openxml-3.0.1)를 참고한다. 화면 두께의 판정 근거는 위의 실제 캡처와 원본 XML이다.
