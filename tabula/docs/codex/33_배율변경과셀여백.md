# 33. 배율 변경과 셀 여백 (2026-10-02)

## 확인한 원인

- 같은 XLSX의 일반 행은 100%에서 양쪽 22px, 400%에서 88px였다. B~E 열과 같은 문구의 글자 크기도 같았다. 캡처 원본 크기가 달라 대화창에서 달리 축소된 영향과 실제 표시 결함을 구분했다.
- `GridView.setZoom`은 기존 창의 셀 범위가 새 범위를 포함하면 DOM을 재사용했다. 100%에서 그린 1px 선이 슬라이더로 400% 변경 시 4px가 됐다. 이전 `grid-rendering.mjs`의 강제 `renderAll()`은 이 전환 결함을 드러내지 못했다.
- 첫 행·열의 원점 테두리에 불필요한 1 장치 픽셀 간격이 있었다. 확대된 기존 DOM에서는 이 간격도 4px로 커졌다.
- 머리글의 CSS 테두리도 배율에 따라 굵어졌다. CSS border의 최소 폭 때문에 단순히 배율의 역수를 넣어도 높은 DPR에서 2px가 남았다.
- 세로 가운데 맞춤에 비대칭 상하 패딩(0/2px)이 적용되어 글자가 1 CSS px 위에 있었다. 일반 왼쪽 맞춤은 1 CSS px 더 안쪽이었다.
- XLS의 ROW 높이를 수동 높이 플래그가 있을 때만 읽어, 자동 높이로 저장된 제목 행 25px를 기본 18px로 표시했다. SCL 비율은 모델의 백분율 계약과 달리 0.9로 저장되어 90%를 복원하지 못했다.

## 수정

- 배율을 바꾸면 모든 창의 범위 캐시를 무효화하여 선·배경 마스크·개체 화면을 새 배율로 다시 그린다.
- 첫 경계의 추가 간격을 제거한다. 창과 맞닿는 원점은 장치 픽셀 안쪽으로 올림 정렬하여 분수 배율의 클립이 선을 자르지 않게 한다. 문서의 셀 좌표·행 높이·열 너비는 바꾸지 않는다.
- 머리글 구분선은 화면 좌표를 맞춘 SVG로 1 장치 픽셀, 선택 강조는 2 장치 픽셀로 그린다. 머리글 배경·글자·클릭 영역과 셀 선택은 유지한다.
- 가운데 맞춤 상하 패딩을 1/1px로 균등하게 하여 전체 내용 높이를 보존한다. 일반 왼쪽 패딩만 3→2px로 조정하고, 가운데/오른쪽의 가로 위치·들여쓰기·피벗 확장 버튼·조건부 아이콘의 공간은 유지한다.
- XLS는 저장된 ROW 높이를 수동 여부와 무관하게 읽고 `rowManual`에만 수동 플래그를 반영한다. SCL은 90/115/400 같은 백분율로 읽는다.

- XLS XFExt의 명시적 불투명 RGB 전경·무늬 배경·글자·테두리 색을 보존한다. XFCRC의 XF 개수와 체크섬이 맞을 때만 적용하며, 손상된 길이·낡은 확장·미지원 자동/인덱스/테마/틴트/알파는 기존 XF 색을 유지한다. 실제 파일에서 주황색 `#ffc000`이 근사 팔레트 `#ffcc00`으로 바뀌던 문제를 확인했다. [XFExt 원본 명세](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/8a198485-3609-4bcb-87e7-41894d48b76a)를 참고했다.

## 검증

- Node 전체 714개 통과, 일반/Cloudflare 빌드 성공. XLS 합성 BIFF 회귀는 ROW 자동/수동/숨김 높이, SCL 비율·잘못된 값, XFExt 실제 색·체크섬·미지원/손상 데이터와 XLSX 왕복을 검사한다.
- 실제 XLS의 283셀 원문·저장값·기타 메타는 수정 전후 동일하며 XLSX 왕복 값도 유지된다. 모델 차이는 첫 행 높이, 백분율 확대, 머리글 6셀 색뿐이다. 소스와 최종 번들의 115%에서 제목 위쪽 잘림이 없어졌고 원본 두 사본의 SHA256도 같다. 이 파일에는 수식이 없으므로 계산 정확성 검증으로 계산하지 않는다.

- `tools/grid-zoom.mjs`: 실제 확대 슬라이더의 input 이벤트로 100→400→100→200→50→115%를 바꾼다. 중간에 `renderAll()` 또는 `update(true)`를 호출하지 않는다. DPR 1/1.25/1.5/2 × 틀 고정 없음/행/열/둘 다, 총 96조건·3,266개 검사 통과. 가는 선·이중선·원점·머리글·글자 위치를 실제 PNG 장치 픽셀과 DOM 좌표로 확인했다.
- 기존 `grid-rendering.mjs`의 40조건·2,247개 검사도 통과했다. 최종 Cloudflare 번들에서도 두 도구의 96/40조건을 각각 재확인해 모두 통과했다.
- 실제 XLSX에서 셀 크기·글자 크기를 보존했다. 100% 왼쪽 글자의 x−1/y+1, 400% x−4/y+4 이동을 확인했고 가운데/오른쪽의 x는 변하지 않았다. 100%의 측정 문구 여백은 제공된 Excel 캡처와 일치했다. 400%에서는 브라우저와 Excel의 글리프·기준선에 약 1px 잔차가 있다.
- 원본 업무 파일과 캡처는 로컬 격리 검증에만 사용하며 저장소·공개 사이트에 포함하지 않는다. 완성 화면과 실제 배율 변경 경로를 별도로 검증한다.

## 적용 범위

중간/굵은 테두리의 기존 두께 정책, 문서의 행·열 크기, 수식 값과 인쇄용 모델은 유지한다. 모든 OS·글꼴·브라우저가 Excel과 완전히 같은 래스터를 만든다는 의미는 아니다. 이전 버전에서 이미 가져와 브라우저 문서에 저장한 XLS의 잃어버린 행 높이는 원본을 다시 열어야 복원된다.
