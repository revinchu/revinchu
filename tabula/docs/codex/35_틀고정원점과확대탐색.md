# 틀 고정 원점과 확대 탐색

## 재현 원인

330%에서 고정된 14개 행이 화면 높이를 넘으면 본문 높이가 0이 되어 방향키로 선택을 옮겨도 선택 셀이 보이지 않았다. 별도로 XLSX의 고정 원점과 본문 시작 위치를 혼동하여 화면의 행 번호가 달라졌다.

사용자 원본은 로컬에서만 비교했다. 숨김 33개 행(295–306, 309–329)은 수정 전에도 정확히 보존되어 있었다. `sheetView.topLeftCell=A295`, `ySplit=14`인 고정 구간에서 실제 보이는 행은 307·308행이며, 그 다음 숨기지 않은 행은 330행이다. 본문 `pane.topLeftCell=A884`와 해당 창의 활성 셀 E886도 별도로 저장되어 있다. 이전 구현은 1–14행을 고정하고 다른 창의 활성 셀을 사용했다.

## 구현

- `freeze.rows/cols`는 구간 길이, 선택적인 `freeze.top/left`는 고정 원점이다. `view.top/left`는 본문 시작 위치이며 `view.r/c/activePane`은 활성 창의 선택이다.
- 렌더러는 절대 셀/개체 좌표를 유지한다. 화면 좌표에서 원점을 빼고 본문에만 스크롤을 뺀다. 머리글·클릭·핀치·피벗 드롭 영역·개체 가시 범위에도 같은 규칙을 적용한다.
- 고정 영역 뒤에 본문 셀 하나를 표시할 공간이 없으면 해당 축만 보기에서 잠시 고정을 해제한다. 한국어 안내를 표시하고 공간이 생기면 복원한다. 원본의 고정·숨김 설정은 변경하지 않는다. 이는 접근성 보완이며 Excel의 고정 영역 초과 처리와 완전히 같다고 주장하지 않는다.
- 저장된 고정 원점 앞의 셀로 이동할 때도 해당 셀에 접근할 수 있도록 보기만 조정한다. 시트 전환은 절대 본문 위치와 이 일시적 보기 상태를 복원한다.
- 행·열 삽입/삭제는 고정 구간의 양 끝과 보기 위치를 함께 이동하며 XLSX 왕복 시 보존한다.

## 기존 브라우저 사본

이전 가져오기에서 버린 고정 원점을 브라우저 사본만으로 확실히 추정할 수는 없다. 저장하지 않은 편집은 파일로 보관한 뒤 새 버전을 불러오고 원본 XLSX를 다시 열어야 원본의 창 설정이 복원된다. 사용자의 숨김 행을 임의로 바꾸지 않는다.

## 검증

`tools/freeze-navigation.mjs`는 합성 문서에서 저장 창 복원, 330% 키보드 탐색, 숨김 행/열, 양 축 고정, 축소·창 크기 변경·시트 전환, 편집·되돌리기와 실제 DOM 좌표/클릭을 검사한다. 사용자 파일 내용과 캡처는 저장소 및 서버에 올리지 않는다. 전체 결과는 배포 시 검증 기록에 남긴다.

검증 결과: 단위 테스트 726/726, 틀 고정 UI 시나리오 12/12(소스·Cloudflare 번들), 배율 전환 96개 조합·3,266개 검사 통과. 실제 XLSX는 100%·330%·400%에서 방향키로 선택 셀이 화면 안에 유지되는 것을 확인했고, 수식 8,545개 및 XLSX 왕복 불일치 0이었다. 고정/보기 이외의 79개 시트 모델과 원본 SHA-256은 변경 전후 같았다.
