# 30. 재평가와 품질 개선

작성: 2026-10-02. 재평가 기준은 `a6db8e5`의 코드와 [09](09_WIXEL3_구현과검증.md)~[29](29_홈화면아이콘.md)의 검증 기록이다. 아래 수정 결과는 이 기준 이후의 작업으로 구분한다. 실제 사용자 문서나 열려 있는 작업 화면을 이번 합성 검사에 사용하지 않았다.

이 문서는 기능의 존재와 완성도를 구분하는 **엔지니어링 추정**이다. 기능 지원률, 전체 속도 점수, 통계적 신뢰구간 또는 독립 품질 인증이 아니다. 제품 전체를 같은 업무·자료·장치에서 Excel/Google Sheets와 비교한 사용자 연구도 아니다. 점수는 개별 수정 몇 건이나 테스트 개수에 비례하여 올리지 않는다.

## 1. 평가 범위와 10개 항목

Excel 기준은 Windows 데스크톱에서의 개인 표·계산·분석·파일 편집 업무이고, Google Sheets 기준은 웹 공동 작업 중심 업무다. 동일한 역량 범위에 용도별 중요도만 다르게 적용했다. 웹 Excel과 데스크톱 Excel, 설치 버전별 지원 범위까지 같다고 가정하지 않는다. 비교 범위는 [Microsoft의 데스크톱/웹 차이 안내](https://support.microsoft.com/en-us/excel/differences-between-using-a-workbook-in-the-browser-and-in-excel), [Google의 공유·댓글·버전 안내](https://support.google.com/docs/answer/9331169?hl=en), [Sheets 매크로와 Apps Script 안내](https://developers.google.com/apps-script/guides/sheets/macros)를 참고했다.

역량 0은 없음, 0.25는 좁은 일부, 0.5는 대표 과제 지원, 0.75는 폭넓은 지원과 남은 제한의 명시, 1.0은 정의한 필수 과제를 복수 환경·파일·장애 조건에서 입증한 상태다. 비교 제품이 모든 항목에서 자동으로 1.0이라는 뜻은 아니다. 미검증은 결함으로 단정하지 않고 추정 범위에 반영했다.

### CSV 큰 행 수·인코딩 — 완료

작은 CSV의 행 너비 계산에서 데이터 배열 전체를 함수 인수로 펼치던 경로를 [csv.js](../../src/csv.js)의 `delimitedRowWidth` 순회로 교체했다. [app.js](../../src/app.js)의 `writeRows`에서 16만 행의 선택 계산이 스택 한도를 넘지 않는다.

8MiB 초과 CSV는 기존에 UTF-8로만 해석했다. [text-file.js](../../src/text-file.js)의 `detectTextFileEncoding` / `readDecodedChunks`와 `openBigCsv`를 연결하여 UTF-16 BOM을 인식하고, BOM 없는 입력은 UTF-8을 스트림으로 검증한 뒤 CP949/EUC-KR로 전환한다. 첫 64KiB가 ASCII여도 뒤의 한글을 확인하며, 전체 디코딩 문자열을 한 번에 보관하지 않는다. BOM 없는 UTF-8 파일은 검증과 디코딩의 두 번 스트림 읽기가 필요하다. 메모리 복제를 줄이지만 모든 파일의 처리 속도가 더 빨라진다는 뜻은 아니다.

[tools/csv-import-quality.mjs](../../tools/csv-import-quality.mjs)는 새 브라우저에서 실제 `#fileInput`으로 합성 CSV를 연다. 기존 번들 `:8787`과 수정 소스 `:5191`을 비교했다.

### 겹친 표 필터의 행 좌표 — 완료

교차 리뷰에서 기존 `Axis.bitsBefore`가 여러 표의 필터가 숨긴 같은 행을 중복 차감함을 재현했다. 예를 들어 0부터 센 1·2행과 2·3행을 각각 숨기면, 높이 20px의 행 위치가 역행하고 `indexAt(20)`이 4행 대신 5행을 반환했다.

겹치는 비트맵 구간만 합집합으로 준비하여 한 행을 한 번 차감한다. 떨어진 작은 구간 사이의 공백을 할당하거나 원본 필터를 수정하지 않는다. 좌표·사용자 크기·희소 숨김·35개 고정 난수 합성 조합을 포함한 축 Node **11/11**과 [tools/axis-overlap.mjs](../../tools/axis-overlap.mjs)의 두 표 필터·스크롤·Undo/Redo **4시나리오, 4,833개 assertion**이 소스와 최종 번들 `:8789`에서 통과했다.

정합성을 위한 비용도 있다. 이 장치의 15회 생성 중앙값에서 단일 100만 비트맵은 0.805→0.816ms, 떨어진 50만×2개는 0.723→0.730ms로 추가 비트맵 할당이 없었다. 겹치는 100만×2개는 1.446→5.329ms이며 합집합 150만 바이트를 추가로 사용한다. 기존의 잘못된 좌표보다 정확성을 우선한 비용이다.

### 큰 CSV의 빈 행·줄바꿈 — 완료

추가 리뷰에서 `CsvStream`이 중간 빈 행을 삭제하고 CR 단독 줄바꿈을 한 행으로 합치는 기존 결함을 재현했다. 파일 크기에 따라 데이터의 행 번호가 달라지는 문제였다. 스트리밍 상태를 조각 사이에 유지하고, CR/CRLF를 작은 파일의 `parseDelimited`와 동일하게 인용 안팎 모두 LF로 정규화한다. 빈 행과 마지막 레코드 의미를 보존하고, CRLF와 겹따옴표가 조각 경계에 걸려도 같은 결과를 낸다. CR 헤더의 구분 기호 추정도 수정했다.

[test/csv-stream-boundaries.test.js](../../test/csv-stream-boundaries.test.js)의 경계 8개에는 5,000개 고정 난수 문자열과 비정상 인용 입력의 기존 느슨한 해석을 비교하는 검사가 포함된다. 디코더 5개와 함께 **13/13 통과**했다. [tools/csv-row-boundaries.mjs](../../tools/csv-row-boundaries.mjs)는 LF·CR·CRLF 각각을 작은 UTF-8 파일과 8MiB 초과 UTF-16 파일로 열어 같은 5,006행 전체 값의 SHA-256을 비교하며 소스와 최종 번들 `:8789`에서 **6/6 통과**했다. 비인용 완성 줄은 native split 빠른 경로를 유지한다. 동일 합성 입력의 Node 파서 시간은 긴 필드 35.9→44.8ms, 다열 245.5→242.0ms, 인용문 88.0→57.7ms(3회 중앙값)로, 모든 경우의 속도 개선을 주장하지 않는다.

## 6. 재현 명령과 결과 기록

작업 폴더는 `tabula/`이며 기존 Playwright 런타임과 브라우저 캐시를 사용한다. 브라우저 도구는 로컬 서버·새 격리 컨텍스트를 사용하며, 사용자 문서·공개 보관함 쓰기는 금지한다.

$env:WIXEL_URL='http://127.0.0.1:5191/'
node tools/mobile-layout.mjs
$env:CSV_RESULT_PATH='D:/Codex/Temp/csv-quality-after.json'
node tools/csv-import-quality.mjs
node tools/hidden-grid-performance.mjs
node tools/server-open-guard.mjs

`mobile-layout.mjs`의 전체 리본 카탈로그는 소스 모듈을 사용한다. 번들의 실제 앱 검사만 할 때는 `MOBILE_LAYOUT_CATALOG=0`으로 실행한다. 숨김 렌더의 기준 비교는 소스 서버에서 `WIXEL_PERF_BASELINE_REF=a6db8e5`를 설정하며, 수정본 검사는 이를 해제한다.
