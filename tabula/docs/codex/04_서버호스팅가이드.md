# 04. 서버 · 호스팅 가이드

WIXEL 은 두 가지 방식으로 배포할 수 있습니다.

| 방식 | 무엇이 되나 | 무엇이 안 되나 | 추천 용도 |
|------|-------------|----------------|-----------|
| **A. 정적 배포** (`dist/index.html`) | 모든 편집 · 계산 · 파일 열기/저장(내 PC), 브라우저 자동 저장 · 보관함, 읽기 전용 링크(`#view=` 문서를 URL 에 압축) | 다른 기기와 문서 공유, IMPORT* 웹 함수(대부분 CORS 로 막힘), 네이버 검색광고 API, 서버 게시 링크 | 개인용, 데모, 사내 배포 |
| **B. Node 서버** (`server.js`) | A 전부 + 서버 문서 저장/공유, `?doc=` 공동 보기, 게시 링크(`?view=id`), 웹 함수 중계, 네이버 API 중계 | (실시간 동시 편집은 아직 없음) | 팀 사용, 마케팅 리포트 자동화 |

---

## 1. 정적 배포 (A)
```bash
cd tabula && npm test && npm run build
# 결과: dist/index.html (약 2.7MB, CSS·JS 모두 포함) + dist/assets/ (아이콘 라이브러리, 템플릿 파일)
```
- **반드시 `dist/assets/` 도 함께 올리세요** (삽입 › 아이콘, 일부 템플릿이 사용).
- GitHub Pages: 저장소 Settings → Pages → Source = **GitHub Actions**. `.github/workflows/tabula-pages.yml` 이 `tabula/**` 변경 시 테스트 → 빌드 → 배포. 주소 `https://<계정>.github.io/<저장소>/`.
- Netlify / Cloudflare Pages / Vercel / S3+CloudFront: 빌드 명령 `cd tabula && npm run build`, 게시 폴더 `tabula/dist`.
- 캐시: `index.html` 은 짧게(no-cache), `assets/` 는 길게.

## 2. Node 서버 (B)
### 2.1 실행
기본 실행은 **이 컴퓨터에서만 접속하는 `127.0.0.1`**입니다. 로컬 무암호 저장 흐름은 유지합니다.
같은 네트워크의 다른 기기나 인터넷에서 접속할 수 있게 하려면 수신 주소와 토큰을 함께 설정하세요.
루프백이 아닌 `HOST`에서 `TABULA_TOKEN`이 비어 있거나 공백뿐이면 서버가 시작을 거부합니다.

Windows PowerShell 로컬 실행:
```powershell
Set-Location D:\Codex\Workspaces\wixel\tabula
$env:HOST = '127.0.0.1'
$env:TABULA_DATA = 'D:\Codex\Workspaces\wixel-data'
node server.js
```

외부 접속용 Linux 실행 예:
```bash
cd tabula
PORT=5178 HOST=0.0.0.0 TABULA_DATA=/var/lib/wixel TABULA_TOKEN='긴-무작위-값' node server.js
```
| 환경 변수 | 기본값 | 설명 |
|-----------|--------|------|
| `PORT` | 5178 | 수신 포트 |
| `HOST` | 127.0.0.1 | 로컬 전용 기본값. `localhost`는 `127.0.0.1`로 고정. `0.0.0.0`/`::` 등 외부 주소에는 토큰 필수 |
| `TABULA_DATA` | `tabula/data` | 문서 저장 폴더 (`<이름>.tabula.json`, 게시본 `published/<id>.json`) |
| `TABULA_TOKEN` | (없음) | 설정하면 문서 읽기·쓰기·삭제, 게시 변경, 웹·네이버 중계에 `X-Tabula-Token` 필요. 외부 수신 주소에서는 미설정 시 시작 거부 |
| `TABULA_PROXY_RATE_LIMIT` | 120 | 연결 IP별 1분 동안 허용하는 웹·네이버 중계 요청 합계. 1 이상의 정수 |

- Node 18 이상(22 권장), npm 패키지 설치 없음. 서버는 정적 파일도 같이 제공하므로 **빌드 없이 `src/` 를 그대로** 서비스합니다(개발 모드와 동일). 배포 서버에서 빌드본을 쓰려면 `dist/` 를 정적으로 따로 서비스해도 됩니다.
- 토큰 없는 로컬 모드는 실제 연결 IP와 Host가 루프백/localhost일 때만 보호 API를 허용합니다. 브라우저의 다른 Origin에서 보낸 보호 API 요청도 거부합니다.
- 리버스 프록시 뒤에서는 `HOST=127.0.0.1`이어도 **`TABULA_TOKEN`을 설정**하세요. 설정 없이 외부 도메인의 Host를 전달하면 보호 API가 거부됩니다.
- `server.js`는 실행 진입점, `server/app.js`는 서버 생성·인증·저장·정적 경로, `server/network.js`는 외부 요청 보안입니다. import만으로 포트를 열지 않으며 junction 경로 실행도 지원합니다.

### 2.2 API 목록 (`server.js`)
| 메서드 · 경로 | 인증 | 설명 |
|---------------|------|------|
| `GET /api/health` | 없음 | `{ ok, auth, publish }` — 앱이 서버 존재 확인 |
| `GET /api/published/:id` | 없음 | 게시된 문서(읽기 전용 보기) |
| `GET /api/naver/keywordstool?hintKeywords=&month=&event=` | 보호 API | 인증 후 헤더 `X-Customer`, `X-API-KEY`, `X-Secret`로 HMAC-SHA256 서명해 네이버 호출. 비밀 키 원문 미전송, 리디렉션 금지, 15초·5MB |
| `GET /api/fetch?url=` | 보호 API | 웹 함수 중계. DNS 전체 검사·연결 IP 고정, 포트 80/443, 리디렉션 5회, 전체 15초·스트리밍 5MB, 문자셋 변환 |
| `POST /api/publish` | 토큰 | 문서 게시 → `{ id }` |
| `PUT/DELETE /api/published/:id` | 토큰 | 게시본 갱신 / 중지 |
| `GET /api/files` | 토큰 | 문서 목록 (이름 · 크기 · 수정 시각) |
| `GET/PUT/DELETE /api/files/:이름` | 토큰 | 문서 읽기 · 저장(원자적 rename) · 삭제. 본문은 앱의 JSON 스냅숏 (최대 50MB) |
| 정적 프런트엔드 경로 | 없음 | `index.html`, `styles.css`, `src/*.js`, `assets/`, `dist/index.html`·`dist/assets/`만 허용. 숨김 파일·서버 소스·데이터·실경로 이탈 차단 |

표의 보호 API/토큰 표시는 `TABULA_TOKEN` 설정 시 인증 필수라는 뜻입니다. 토큰이 없는 로컬 전용 모드는 위 연결 IP·Host·Origin 검사를 적용합니다.
게시된 문서를 읽는 `GET /api/published/:id`와 상태 확인은 의도적으로 공개되어 있습니다.

외부 가져오기는 URL의 모든 DNS 주소를 검사하고, 검사한 IP를 실제 연결의 `lookup`에 고정합니다.
HTTPS의 원래 호스트 이름·SNI·인증서 검증은 유지하며 리디렉션 목적지는 요청 전에 다시 검사합니다.
사설·루프백·링크로컬·CGNAT·메타데이터·문서용·멀티캐스트와 IPv6 전환용/특수 대역은 거부합니다.
DNS, 연결, 리디렉션, 본문 전체에 총 15초를 적용하고 압축 전후 모두 5MB를 초과하면 중단합니다.
주소 차단은 400, 크기 초과는 413, 요청 빈도 초과는 429, 외부 연결 오류는 502, 시간 초과는 504입니다.

### 2.3 리눅스 서버 예 (systemd + Caddy/nginx, HTTPS)
```ini
# /etc/systemd/system/wixel.service
[Unit]
Description=WIXEL
After=network.target
[Service]
WorkingDirectory=/opt/wixel/tabula
ExecStart=/usr/bin/node server.js
Environment=PORT=5178 HOST=127.0.0.1 TABULA_DATA=/var/lib/wixel
# TABULA_TOKEN=… 을 담은 파일 (권한 600)
EnvironmentFile=/etc/wixel.env
User=wixel
Restart=always
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/var/lib/wixel
[Install]
WantedBy=multi-user.target
```
```
# Caddyfile (자동 HTTPS)
wixel.example.com {
  encode gzip
  request_body { max_size 50MB }
  reverse_proxy 127.0.0.1:5178
  header {
    Strict-Transport-Security "max-age=31536000"
    X-Content-Type-Options nosniff
    Referrer-Policy strict-origin-when-cross-origin
  }
}
```
nginx 를 쓰면 `client_max_body_size 50m;`, `proxy_pass http://127.0.0.1:5178;`, `limit_req` 로 `/api/fetch`, `/api/naver/` 속도 제한을 거세요.
앱의 속도 제한은 실제 연결 IP 기준이며 `X-Forwarded-For`를 신뢰하지 않습니다. 프록시 뒤에서는 모든 사용자가
같은 연결 IP로 보일 수 있으므로 프록시에서 실제 클라이언트별 한도를 적용하고 앱의 합산 한도를 조정하세요.

### 2.4 Docker 예
```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY tabula/ ./
RUN mkdir -p /data && chown node:node /data
ENV PORT=5178 HOST=0.0.0.0 TABULA_DATA=/data
VOLUME /data
EXPOSE 5178
USER node
CMD ["node", "server.js"]
```
```bash
docker build -t wixel . && docker run -d -p 127.0.0.1:5178:5178 -v wixel-data:/data -e TABULA_TOKEN=… wixel
```

### 2.5 PaaS (Render / Railway / Fly.io 등)
- 시작 명령 `node server.js`, 루트 디렉터리 `tabula`, 포트는 플랫폼의 `PORT` 사용, `HOST=0.0.0.0`.
- **디스크가 영구적인지 확인** (`TABULA_DATA` 를 영구 볼륨에). 영구 디스크가 없으면 재배포 때 문서가 사라집니다.

## 3. 백업 · 운영
- 백업 대상: `TABULA_DATA` 폴더 전체(문서 `*.tabula.json`, `published/`). 파일 단위 원자적 저장이라 그대로 복사(rsync/스냅숏)해도 됩니다.
- 저장은 문서별로 직렬화하고 요청별 임시 파일을 사용합니다. 같은 문서의 동시 저장이 Windows에서 임시 파일/rename 충돌을 일으키지 않게 했습니다. 실시간 공동 편집이나 충돌 병합을 제공하는 것은 아닙니다.
- 로그: 표준 출력. 오류는 `서버 오류` 500 으로 응답(상세는 숨김) — 필요하면 `console.error` 추가.
- 용량: 서버 저장 본문은 최대 50MB(JSON)이며 수동 저장도 이 한도를 넘으면 413으로 거부됩니다. 별도로 앱은 30만 칸 초과 문서의 서버 자동 저장을 생략하고 브라우저 IndexedDB에 보관합니다. 셀 수와 JSON 바이트 크기는 서로 다른 기준입니다.

## 4. 보안 체크리스트 (공개 전)
| 항목 | 현재 | 조치 |
|------|------|------|
| 저장 API 인증 | 기본 루프백. 외부 수신+토큰 없음은 시작 거부 | 외부 공개와 리버스 프록시에 `TABULA_TOKEN` 설정 |
| 네이버 API 중계 | 인증 후 실행, 리디렉션 금지 | 앱의 서버 암호와 광고 계정 키는 별도 값 |
| `/api/fetch` SSRF | DNS 전체 검사·검사 IP 연결 고정·수동 리디렉션·포트·크기·시간 제한 | 배포 환경의 egress 방화벽을 함께 적용할 수 있음 |
| HTTPS | 없음 | 리버스 프록시에서 |
| 속도 제한 | 웹·네이버 중계에 연결 IP별 기본 120회/분, 429+Retry-After | 프록시에서 실제 사용자 IP별 제한 보완 |
| 보안 헤더/CSP | nosniff, same-origin Referrer-Policy, SAMEORIGIN 프레임, CSP의 frame-ancestors/object-src/base-uri | HTTPS/HSTS는 프록시에서. 스크립트 CSP는 빌드본의 인라인 코드와 외부 기능을 고려해 별도 설계 |
| 정적 파일 노출 | 프런트엔드 경로만 허용, 실제 경로에도 허용 목록 적용 | 비밀 설정과 데이터는 `assets/`에 넣지 않음 |
| 게시 링크 | 추측 어려운 18자리 hex id | 그대로 (만료 기능은 없음) |
| 사용자 데이터 | 광고 계정 키(X-Secret)는 서버에 저장하지 않음(요청마다 헤더) | 로그에 헤더를 남기지 말 것 |

## 5. 앱 쪽 설정 연결
- 앱은 시작 시 `/api/health` 로 서버를 감지(`src/storage.js` `server.init()`). 서버가 있으면 파일 › 열기에 "다른 기기에서 열기", 자동 저장이 서버로.
- 토큰: 앱은 `X-Tabula-Token` 헤더를 보냅니다(`storage.js`, localStorage `tabula.serverToken`). 서버가 401 을 주면 `askServerToken()`(app.js)이 '서버 암호' 대화상자를 띄웁니다.
- 웹 함수는 서버가 있으면 `/api/fetch`, 없으면 브라우저 직접 fetch(대부분 CORS 실패 → `#N/A`).

## 6. 서버 회귀 검증

```bash
cd tabula
node --test test/server.test.js test/server-network.test.js
```

테스트는 외부 DNS나 실제 광고 키에 의존하지 않습니다. DNS/응답을 제어해 사설·혼합 응답, 주소 표현 우회,
DNS 재조회, 리디렉션, 시간·크기·압축 제한을 검사하고, 실제 로컬 HTTP 소켓으로 인증·저장·공개 게시·속도 제한을 확인합니다.
서버 진입점의 자식 프로세스와 junction 실행, 정적 경로의 심볼릭 링크 우회, 동시 저장도 검증합니다.
실제 외부 사이트나 배포 서버의 HTTPS 인증서·방화벽 구성이 검증되었다는 뜻은 아닙니다.

[IANA IPv4 특수 대역](https://www.iana.org/assignments/iana-ipv4-special-registry),
[IANA IPv6 특수 대역](https://www.iana.org/assignments/iana-ipv6-special-registry).
추가로 Azure의 플랫폼 통신용 가상 주소 `168.63.129.16`을 차단합니다.
해당 주소의 용도는 [Microsoft 공식 설명](https://learn.microsoft.com/en-us/azure/virtual-network/what-is-ip-address-168-63-129-16)을 참고하세요.
