# 04. 서버 · 호스팅 가이드

WIXEL 은 두 가지 방식으로 배포할 수 있습니다.

| 방식 | 무엇이 되나 | 무엇이 안 되나 | 추천 용도 |
|------|-------------|----------------|-----------|
| **A. 정적 배포** (`dist/index.html`) | 모든 편집 · 계산 · 파일 열기/저장(내 PC), 브라우저 자동 저장 · 보관함, 읽기 전용 링크(`#view=` 문서를 URL 에 압축) | 다른 기기와 문서 공유, IMPORT* 웹 함수(대부분 CORS 로 막힘), 네이버 검색광고 API, 서버 게시 링크 | 개인용, 데모, 사내 배포 |
| **B. Node 서버** (`server.js`) | A 전부 + 서버 문서 저장/공유, `?doc=` 공동 보기, 게시 링크(`?view=id`), 웹 함수 중계, 네이버 API 중계 | (실시간 동시 편집은 아직 없음) | 팀 사용, 마케팅 리포트 자동화 |

---

## 1. 정적 배포 (A)
```bash
cd tabula && npm test && npm run build
# 결과: dist/index.html (약 2.7MB, CSS·JS 모두 포함) + dist/assets/ (아이콘 라이브러리, 템플릿 파일)
```
- **반드시 `dist/assets/` 도 함께 올리세요** (삽입 › 아이콘, 일부 템플릿이 사용).
- GitHub Pages: 저장소 Settings → Pages → Source = **GitHub Actions**. `.github/workflows/tabula-pages.yml` 이 `tabula/**` 변경 시 테스트 → 빌드 → 배포. 주소 `https://<계정>.github.io/<저장소>/`.
- Netlify / Cloudflare Pages / Vercel / S3+CloudFront: 빌드 명령 `cd tabula && npm run build`, 게시 폴더 `tabula/dist`.
- 캐시: `index.html` 은 짧게(no-cache), `assets/` 는 길게.

## 2. Node 서버 (B)
### 2.1 실행
```bash
cd tabula
PORT=5178 HOST=0.0.0.0 TABULA_DATA=/var/lib/wixel TABULA_TOKEN='긴-무작위-값' node server.js
```
| 환경 변수 | 기본값 | 설명 |
|-----------|--------|------|
| `PORT` | 5178 | 수신 포트 |
| `HOST` | 0.0.0.0 | 수신 주소. `127.0.0.1` 이면 이 컴퓨터에서만 (리버스 프록시 뒤에 둘 때 권장) |
| `TABULA_DATA` | `tabula/data` | 문서 저장 폴더 (`<이름>.tabula.json`, 게시본 `published/<id>.json`) |
| `TABULA_TOKEN` | (없음) | 설정하면 저장 · 게시 · 웹 중계 API 에 `X-Tabula-Token` 헤더 필요. **인터넷 공개 시 필수** |

- Node 18 이상(22 권장), npm 패키지 설치 없음. 서버는 정적 파일도 같이 제공하므로 **빌드 없이 `src/` 를 그대로** 서비스합니다(개발 모드와 동일). 배포 서버에서 빌드본을 쓰려면 `dist/` 를 정적으로 따로 서비스해도 됩니다.

### 2.2 API 목록 (`server.js`)
| 메서드 · 경로 | 인증 | 설명 |
|---------------|------|------|
| `GET /api/health` | 없음 | `{ ok, auth, publish }` — 앱이 서버 존재 확인 |
| `GET /api/published/:id` | 없음 | 게시된 문서(읽기 전용 보기) |
| `GET /api/naver/keywordstool?hintKeywords=&month=&event=` | **없음(⚠ P0-2)** | 네이버 검색광고 키워드 도구 중계. 헤더 `X-Customer`, `X-API-KEY`, `X-Secret` 를 받아 HMAC-SHA256 서명 후 `api.searchad.naver.com` 호출 |
| `GET /api/fetch?url=` | 토큰 | 웹 함수(IMPORTXML/HTML/DATA/FEED, GOOGLEFINANCE …) 중계. 공개 http(s)만, 15초 · 5MB, 문자셋 변환 |
| `POST /api/publish` | 토큰 | 문서 게시 → `{ id }` |
| `PUT/DELETE /api/published/:id` | 토큰 | 게시본 갱신 / 중지 |
| `GET /api/files` | 토큰 | 문서 목록 (이름 · 크기 · 수정 시각) |
| `GET/PUT/DELETE /api/files/:이름` | 토큰 | 문서 읽기 · 저장(원자적 rename) · 삭제. 본문은 앱의 JSON 스냅숏 (최대 50MB) |
| 그 밖의 경로 | 없음 | `tabula/` 아래 정적 파일 (`data/` 는 차단) |

### 2.3 리눅스 서버 예 (systemd + Caddy/nginx, HTTPS)
```ini
# /etc/systemd/system/wixel.service
[Unit]
Description=WIXEL
After=network.target
[Service]
WorkingDirectory=/opt/wixel/tabula
ExecStart=/usr/bin/node server.js
Environment=PORT=5178 HOST=127.0.0.1 TABULA_DATA=/var/lib/wixel
EnvironmentFile=/etc/wixel.env          # TABULA_TOKEN=… (권한 600)
User=wixel
Restart=always
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/var/lib/wixel
[Install]
WantedBy=multi-user.target
```
```
# Caddyfile (자동 HTTPS)
wixel.example.com {
  encode gzip
  request_body { max_size 50MB }
  reverse_proxy 127.0.0.1:5178
  header {
    Strict-Transport-Security "max-age=31536000"
    X-Content-Type-Options nosniff
    Referrer-Policy strict-origin-when-cross-origin
  }
}
```
nginx 를 쓰면 `client_max_body_size 50m;`, `proxy_pass http://127.0.0.1:5178;`, `limit_req` 로 `/api/fetch`, `/api/naver/` 속도 제한을 거세요.

### 2.4 Docker 예
```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY tabula/ ./
ENV PORT=5178 HOST=0.0.0.0 TABULA_DATA=/data
VOLUME /data
EXPOSE 5178
USER node
CMD ["node", "server.js"]
```
```bash
docker build -t wixel . && docker run -d -p 127.0.0.1:5178:5178 -v wixel-data:/data -e TABULA_TOKEN=… wixel
```

### 2.5 PaaS (Render / Railway / Fly.io 등)
- 시작 명령 `node server.js`, 루트 디렉터리 `tabula`, 포트는 플랫폼의 `PORT` 사용, `HOST=0.0.0.0`.
- **디스크가 영구적인지 확인** (`TABULA_DATA` 를 영구 볼륨에). 영구 디스크가 없으면 재배포 때 문서가 사라집니다.

## 3. 백업 · 운영
- 백업 대상: `TABULA_DATA` 폴더 전체(문서 `*.tabula.json`, `published/`). 파일 단위 원자적 저장이라 그대로 복사(rsync/스냅숏)해도 됩니다.
- 로그: 표준 출력. 오류는 `서버 오류` 500 으로 응답(상세는 숨김) — 필요하면 `console.error` 추가.
- 용량: 문서 하나 최대 50MB(JSON). 그보다 큰 통합 문서는 브라우저 IndexedDB 에만 저장되고 서버에는 [저장] 시에만 올라갑니다(30만 칸 초과).

## 4. 보안 체크리스트 (공개 전)
| 항목 | 현재 | 조치 |
|------|------|------|
| 저장 API 인증 | 토큰 없으면 전부 공개 | `TABULA_TOKEN` 설정 필수 (P0-2: 미설정 시 차단으로 변경 권장) |
| 네이버 API 중계 | 인증 전 위치 → 공개 중계기 | 인증 뒤로 이동 (P0-2) |
| `/api/fetch` SSRF | 호스트 이름 문자열만 검사 | DNS 해석 IP 검사 · 수동 리디렉션 · 포트 제한 (P0-1) |
| HTTPS | 없음 | 리버스 프록시에서 |
| 속도 제한 | 없음 | 프록시 `limit_req` 또는 서버 미들웨어 (P0-3) |
| 보안 헤더/CSP | 없음 | 프록시에서 추가. 앱은 인라인 스크립트가 없으나 빌드본은 한 파일 인라인 → 빌드본에는 `script-src 'unsafe-inline'` 필요 |
| 게시 링크 | 추측 어려운 18자리 hex id | 그대로 (만료 기능은 없음) |
| 사용자 데이터 | 광고 계정 키(X-Secret)는 서버에 저장하지 않음(요청마다 헤더) | 로그에 헤더를 남기지 말 것 |

## 5. 앱 쪽 설정 연결
- 앱은 시작 시 `/api/health` 로 서버를 감지(`src/storage.js` `server.init()`). 서버가 있으면 파일 › 열기에 "다른 기기에서 열기", 자동 저장이 서버로.
- 토큰: 앱은 `X-Tabula-Token` 헤더를 보냅니다(`storage.js`, localStorage `tabula.serverToken`). 서버가 401 을 주면 `askServerToken()`(app.js)이 '서버 암호' 대화상자를 띄웁니다.
- 웹 함수는 서버가 있으면 `/api/fetch`, 없으면 브라우저 직접 fetch(대부분 CORS 실패 → `#N/A`).
