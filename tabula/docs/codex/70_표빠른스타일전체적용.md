# 70. 표 빠른 스타일 전체 적용

## 요구와 원인

사용자는 빠른 스타일을 바꾸면 선 색만 일부 바뀌고 표 전체 색이 바뀌지 않는다고 보고했고, 기존 개별 셀 강조색도 함께 바꾸기를 명시했다. 직접 서식이 표 스타일보다 우선하는 일반적인 가져오기 동작은 보존하되, 빠른 스타일 선택에 명시적 시각 서식 초기화를 연결했다.

기본 통합 문서 서식의 흰색/검정색을 직접 서식처럼 표 위에 합성한 문제와 사용자 지정 스타일의 빈 셀을 렌더링에서 제외한 문제도 재현했다.

## 구현

- 빠른 스타일 선택과 새 표 스타일 선택은 직접 채우기·글자색·굵기·기울임·밑줄·취소선·테두리를 초기화하고 새 스타일을 한 트랜잭션으로 적용한다. 같은 스타일을 다시 선택해도 추가 강조색을 초기화한다. 데이터·수식·저장된 수식 결과·숫자/날짜 형식·글꼴/크기·정렬·보호·메모·링크·필터를 유지한다.
- `table-format.js`는 기본 서식 < 표 스타일 < 직접 서식 순서로 합성한다. 화면, 연결된 그림, 범위 그림 저장, 인쇄, 셀 복사·붙여넣기, 서식 복사와 일반 범위 전환이 같은 합성을 사용한다. 조건부 서식은 기존처럼 마지막에 적용한다.
- 행/열/시트 전체에서 내려오는 색은 표 내부 셀에서만 중립화한다. 표 밖의 직접 서식은 변경하지 않는다. 후속 직접 채우기나 테두리 작업은 다시 우선한다. 표 옵션 변경과 사용자 지정 스타일 정의 수정은 일괄 초기화를 호출하지 않는다.
- 대용량 블록 전체 열은 배열·순열을 복제하지 않고 열 서식만 바꾼다. 부분 블록은 해당 표 범위만 변경한다. 100만 셀을 초과하는 희소 표는 사용 영역 밖의 빈 셀을 실체화하지 않는다. 따라서 그 밖의 빈 영역에 내려오는 행/열 색 초기화는 제한된다.
- XLSX는 표준 표 스타일 정보와 중립 셀 XF를 기록한다. XF 확장에 `tableStyleInherit`를 저장하여 위셀 재열기에서도 행/열 상속 차단을 유지한다. 다른 편집기에서 새로 지정한 네이티브 색은 과거 확장보다 우선한다. 기본 스타일 선택 자체만으로 원본 문서를 강제 재서식하지 않는다.

## 검증

`test/table-format.test.js`, `test/table-style-apply.test.js`, `test/table-style-xlsx.test.js`와 `tools/table-quick-style.mjs`를 사용한다. UI 검사는 Chromium 및 WebKit의 실제 리본 클릭, 배경층을 포함한 셀 색상, 숫자 형식·필터·표 밖 셀 보존, 실행 취소/다시 실행, 두 번의 XLSX 재열기, 사용자 지정 빈 셀 및 모바일 390px을 확인한다. 합성 문서만 사용하며 외부 API 쓰기를 차단한다.

실제 iPad Bluetooth 하드웨어와 Microsoft Excel 데스크톱 실행 결과를 직접 검증한 것은 아니다. 조건부 서식 색은 표 스타일보다 우선하며 이 작업에서 삭제하지 않는다.
