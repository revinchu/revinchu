# iPad 포인터·개체 메뉴·온라인 사진 검색 (2026-10-03)

## 범위와 확인한 공백

기준 커밋은 `e5f194ebc5e4f518c8cde7865cf1906bfc421807`이다. 사용자 요청은 iPad Ctrl+휠 배율, Ctrl+슬라이서 항목 추가 선택, 다른 개체에 가려지는 차트 편집 단추, 너무 작은 온라인 사진 검색 미리보기, 슬라이서에 잘못 나타나는 셀 메뉴다.

- 직접 `ctrlKey=true`인 휠과 슬라이서 클릭은 기존 자동화 환경에서 정상이다. 실제 iPad 키 전달 문제를 이 결과만으로 해결됐다고 판정하지 않는다.
- 기존 휠 처리는 Meta를 확대 키로 보지 않았고 세로 이동량이 0인 수평 휠까지 축소했다. WebKit 초기 12개 조건 중 6개 실패했다.
- 슬라이서는 Ctrl/Meta가 실제 mousedown에 있으면 정상이나, Ctrl keydown 뒤 flags 없는 mousedown 및 modifier가 pointerdown에만 남은 호환 mousedown에서 단일 선택으로 바뀌었다.
- 표/피벗 슬라이서가 재표시된 뒤 contextmenu 대상이 gridView가 되는 합성 경로에서 셀 메뉴로 잘못 연결됐다.
- 차트 우측 단추는 개체 z순서 안에서 특별한 표시 우선순위가 없어 뒤에 생성된 앞쪽 개체에 가려졌다.
- 온라인 검색은 기본 최소 110px, 모바일 최소 120px 열을 사용하고 높이 86px로 사진을 잘라 표시했다. 추가 캡처 점검에서는 결과 수가 많을 때 grid 행이 최대 높이 안으로 압축되어 사진과 카드 내용이 잘리는 문제도 확인했다.

## 설계와 구현

`pointer-modifiers.js`는 Ctrl/Meta 직접 flags를 우선한다. Apple 터치 기기에서는 실제 키보드의 held 상태와 같은 primary 포인터 제스처의 보조키 정보를 보완한다. mousedown은 원본 Event별로 값을 기억해 모바일 손바닥 이동 판별 후 지연 전달되어도 해당 클릭의 키 상태를 사용한다. 다른 클릭으로 이월하지 않는다. 키 해제·다음 키 이벤트·window blur·숨김·pagehide/pageshow에서 상태를 정리한다. 일반 마우스 우클릭을 Ctrl+추가 선택으로 바꾸지 않는다.

격자의 `onWheel`은 Ctrl/Command를 공통으로 처리하고 슬라이서 목록 위에서도 배율 변경을 우선한다. 세로 이동이 없는 휠은 배율을 변경하지 않는다. 일반 스크롤·배율 한도·원래 보기 모델은 유지한다.

슬라이서 선택은 기존 `slicerPick`과 보호/Undo 경로를 사용한다. 개체 메뉴는 이벤트 target에서 개체를 찾지 못하면 현재 화면 좌표 아래의 실제 개체를 확인한다. 저장된 선택 개체로 대신 판단하지 않으므로 셀에서 우클릭하면 셀 메뉴를 유지한다.

차트 `.ch-side`에만 z-index 3을 설정한다. 실제 차트·그림·도형·슬라이서의 앞뒤 순서, 저장된 z, Undo, 개체 본문은 바꾸지 않는다. 틀 고정 pane 경계 자체의 overflow 잘림은 이번 수정 범위가 아니다.

온라인 그림 창 너비는 1,000px를 기준으로 화면에 맞추며 검색 카드는 최소 180px를 확보한다. 좁은 화면에서는 열 수를 줄이고 4:3 미리보기 안에 전체 사진을 담는다. grid 행은 max-content 높이를 유지하고 결과 영역을 세로 스크롤해 사진·제목·미리보기 단추가 눌리지 않게 한다. 더 큰 원본 미리보기와 복수 선택·출처 확인·삽입은 유지한다. 이미지/검색 API, 라이선스 정책, 파일 입출력 모델은 바꾸지 않는다.
