# 단축키 점검과 리본 키팁 보강

2026-10-01 사용자 제보인 Alt → W → V → G를 재현했습니다. 기존 등록은 WG뿐이어서 WV에서 키팁이 닫히고 마지막 G가 셀 입력으로 들어갔습니다. F10은 시작 키로 처리하지 않았고, Backspace는 키팁 중에도 셀 편집을 시작했습니다.

## 수정

- WVG 눈금선, WVH 머리글, WVF 수식 입력줄 표시 전환. 기존 WG도 유지합니다.
- Alt 또는 F10으로 시작하고 Alt 재입력으로 종료합니다. Esc/Backspace는 한 단계 위로 이동하며, 루트의 Esc는 종료합니다.
- 잘못 누른 글자는 현재 단계를 유지하며 셀에 입력하지 않습니다. 키팁 밖의 마우스 클릭이나 창 포커스 이탈 시 키팁을 닫습니다.
- 리본 탭과 실제 버튼 옆에 작은 Alt 키 배지를 표시하며, 빠른 실행 도구 모음 번호는 현재 명령 순서를 따릅니다. 사용자 요청에 따라 리본 아래의 큰 바로 가기 키 안내판과 상태 표시줄의 긴 키 목록은 제거했습니다.
- 홈의 테두리 HB는 하위 키를 기다립니다. HBA 모든 테두리, HBN 없음, HBS 바깥쪽 등을 지원합니다.
- HEC 내용 지우기, HEM 메모 지우기, HEH 하이퍼링크 지우기, HMU 셀 분할 등 기존 기능의 키 순서를 보강했습니다. 시트 보호 규칙은 명령 실행 경로에서 동일하게 적용합니다.
- Ctrl 글자 키도 물리 code를 사용해 한글 입력 상태를 지원합니다. AltGr 입력은 가로채지 않으며 등록하지 않은 Ctrl+Alt 글자 조합을 일반 Ctrl 명령으로 실행하지 않습니다.
- 도움말의 바로 가기 키 대화상자에 등록된 전체 리본 키 순서를 표시합니다.

## 실제 리본 버튼 옆 키 표시

Alt → H에서 테두리의 B, 병합의 M, 지우기의 E와 맞춤의 AL·AC·AR을 각 실제 버튼 옆에 표시합니다. 굵게·기울임꼴·밑줄은 H1·H2·H3, 복사·잘라내기는 HC·HX로 실행하며 해당 버튼에도 작은 키 배지가 붙습니다. Alt → W → V에서는 눈금선 G, 머리글 H, 수식 입력줄 F를 각 체크박스 오른쪽에 표시합니다. 배지를 클릭해도 같은 명령 경로로 실행합니다.

HB·HE·HM·HV·HO·HL·HI·HD·WF·AV는 해당 리본 버튼 아래에 하위 명령 메뉴를 엽니다. 메뉴 행마다 남은 키를 표시하며 키 입력·마우스 클릭·방향키와 Enter로 고를 수 있습니다. Esc/Backspace는 상위 키팁 단계로 돌아갑니다. 리본을 가로로 스크롤하거나 창 크기를 바꾸면 배지 위치도 갱신됩니다. 빠른 실행의 눈금선에는 실제 격자 SVG 아이콘을 사용합니다.

이 배지는 아래 등록표에 있는 명령을 대상으로 합니다. 리본의 모든 버튼이나 표·차트·피벗 등 모든 상황별 탭에 Excel의 전체 접근 키를 구현한 것은 아닙니다. 글꼴 입력 상자 포커스 등 미등록 키도 포함하지 않습니다.

## 보이는 셀만 선택할 때 숨긴 열 보존

Alt+;가 숨긴 행만 제외하고 숨긴 열을 포함하여 Delete에 숨긴 값이 사라지는 결함을 재현했습니다. specialCells의 hidden 콜백에 행·열을 모두 전달하고 격자의 실제 행·열 크기로 숨김을 확인합니다. 단위 테스트는 행/열 교차·빈 셀·선택 한도·전부 숨김·다른 특수 셀 옵션 보존을 검사하며, 브라우저는 Alt+; 후 삭제와 실행 취소의 결과를 확인합니다.

## 검증 방법

`node tools/keys.mjs`는 직접 Ctrl/Shift/Alt 단축키의 실제 선택·서식·계산·대화상자·QAT 상태를 확인합니다. 이전 검사의 Ctrl/Shift+Space는 한 축만 보아 전체 선택도 통과할 수 있었으므로 전체 사각형과 활성 셀을 비교하도록 바꿨습니다.

`node tools/keytips.mjs`는 등록표 중복·접두 충돌·명령 연결, 전 중간 입력 경로와 대표 명령의 실제 결과를 구분해 확인합니다. 각 시나리오는 새 브라우저 컨텍스트와 합성 문서만 사용하고 원격 쓰기 요청을 차단합니다. 등록표 검사 통과를 모든 Excel 명령의 동작 검증으로 간주하지 않습니다.

한글 물리 키·AltGr 검사는 KeyboardEvent 시뮬레이션을 포함합니다. OS의 실제 IME 조합 전환이나 브라우저가 먼저 소비하는 예약 키까지 보장하는 검사는 아닙니다. 브라우저가 Ctrl+T/Ctrl+L을 소비하면 표 만들기는 Alt → N → T 또는 리본을 사용합니다.

[Microsoft Excel 단축키 공식 안내](https://support.microsoft.com/en-us/accessibility/excel/keyboard-shortcuts-in-excel)를 참고하되, 이 제품에서 지원하는 명령과 검증 범위는 아래 등록표 및 실제 테스트 결과를 기준으로 합니다. Excel 모든 버전·언어의 전체 단축키와 일치한다고 주장하지 않습니다.

Alt HFC/HH 뒤 실제 화살표 이동과 적용을 별도 검증한다. Alt를 유지한 입력, 자동/견본/하단 명령 경계, 검색 결과와 표·피벗·슬라이서·조건부 서식 등의 갤러리도 포함한다. 새 도구와 기존 한글 조합입력 fixture 정정 근거는 [84번 문서](84_색상표와갤러리키보드.md)를 참조한다.

## 2026-10-07 브라우저 행·열 삽입과 삭제

사용자 지정에 따라 Ctrl+Shift++(주 키보드 Ctrl+Shift+=)는 선택한 행·열 삽입, Ctrl+Shift+-는 선택한 행·열 삭제로 통일한다. 일반 셀 선택에서는 기존 삽입·삭제 옵션이 열린다. 숫자패드도 Shift를 포함한 Ctrl+Shift++/-를 사용한다. Shift 없는 Ctrl+=/-와 Ctrl+숫자패드 +/-는 브라우저에 전달하며 위셀 문서와 시트 배율을 바꾸지 않는다. 기존 Ctrl+Alt+=/- 시트 배율은 유지한다.

이전 Ctrl+Shift+-/Ctrl+Shift+_의 테두리 없음 매핑을 제거했으며, 해당 기능은 리본 또는 Alt → H → B → N으로 실행한다. 기존 키 감사 도구의 테두리 검사도 이 경로로 바꿨다. 리본·빠른 실행 버튼의 초점, 편집·IME·개체·대화상자 격리 및 시트 보호는 별도로 검사한다. 변경 세부와 검증 결과는 [103번 문서](103_브라우저행열단축키.md)를 참조한다.

## 2026-10-07 연속 삭제의 선택 유지

전체 행·열에서 Ctrl+Shift+-로 삭제한 뒤에도 같은 범위·개수·활성 셀을 유지하여 재선택 없이 단축키와 F4로 반복한다. Undo/Redo에서도 병합된 셀 때문에 저장된 전체 행·열 범위가 확장되지 않도록 맞췄다. 검증은 [104번 문서](104_행열연속삭제와선택유지.md)에 기록한다.
