# 피벗 필드 이동과 연관 UI 검수 (2026-10-03)

## 확인한 문제

기존 데스크톱 HTML Drag and Drop 경로는 목록→네 영역 추가가 작동했다. 반면 HTML DragEvent 없이 전달되는 터치 Pointer 경로 네 가지는 정의가 바뀌지 않았고, 같은 영역에서 아래로 옮길 때 제거 전 인덱스를 써 원하는 위치 다음에 삽입했다. 수정 전 전용 브라우저 검사 9개 중 4개 통과·5개 실패로 재현했다.

## 수정 범위

- `pivot-field-drag.js`는 마우스·펜·터치를 하나의 이동 상태로 다루고 5px 이동 후 시작한다. 항목 이름과 삽입선, 대상 강조, 가장자리 자동 스크롤을 제공한다. 체크박스·설정 버튼의 클릭과 이동 후 목록의 스크롤 위치는 유지한다.
- 네 영역 사이 이동, 같은 영역 내 순서 변경, Σ 값의 행/열 전환과 열 안의 위치 이동을 공통 적용 경로로 연결한다. 위치가 바뀌지 않으면 Undo를 만들지 않고 정상 이동은 한 번만 기록한다.
- 축 필드를 옮겨도 같은 원본의 값 필드 복사본은 유지한다. 값 복사본 한 개를 옮길 때는 해당 항목의 집계·이름·숫자 서식을 그대로 옮기며 다른 복사본은 보존한다.
- Escape, 포인터 취소, 다른 포인터, 창 초점 이탈, 시트·정의·권한·통합 문서 버전 변경 시 진행 중 이동을 취소한다. 패널 재생성 직후 후속 클릭이 체크박스를 잘못 누르지 않게 한다.
- 오래 열린 필드 창은 정상 셀 편집 후에도 사용할 수 있다. 통합 문서 버전은 창 생성 때가 아닌 드래그 시작 시점에 고정한다. 대화상자와 갤러리의 오래된 저장 요청은 별도 가드로 거절한다.
- 보호 시트의 피벗 허용 설정을 반영하고 최종본/읽기 전용의 필드·레이아웃·스타일·계산 필드 변경을 차단한다. 같은 원본의 계산 필드를 여러 피벗에 적용할 때는 모든 대상의 권한을 쓰기 전에 검사한다. 자체 저장 뒤에는 같은 계산 필드 창에서 계속 편집할 수 있다.
- Σ 값과 계산 필드의 키보드 메뉴 진입을 보완했다. 메뉴 버튼은 키보드 초점으로도 표시한다.

## 검증 방법

`tools/pivot-field-drag.mjs`는 격리된 합성 문서에서 실제 Playwright 마우스와 모의 Pointer, Chromium CDP 터치를 사용한다. 값과 서식 보존, 실행 취소, 취소·권한·버전 변경, 긴 목록 자동 스크롤, 320/390px 화면을 검사한다. WebKit의 CDP 미지원 항목은 제외 사유를 기록한다.

`tools/pivot-pane-permissions.mjs`는 필드·스타일·계산 필드의 보호, 최종본, 읽기 전용과 오래 열린 편집기, 공유 대상 전체 적용, 연속 수정/삭제와 Undo를 검사한다. 기존 클래식 격자 이동과 보고서 필터·XLSX 저장 후 재열기 검사도 함께 실행한다.

개인 업무 파일은 커밋하지 않으며 결과/로그/합성 캡처는 `D:/Codex/Temp/wixel-pivot-field-drag/`와 무시되는 `.local/`에 둔다.

## 동등성 범위와 남은 차이

[Microsoft의 필드 목록 설명](https://support.microsoft.com/en-us/excel/get-started/use-the-field-list-to-arrange-fields-in-a-pivottable)을 기준으로 영역 간 이동과 순서 변경을 확인했다. 이 검수는 전체 Excel UI·모든 피벗 기능의 100% 동등성 인증이 아니다.

- 영역 밖 드롭은 취소로 처리한다. Excel의 영역 밖 드롭으로 제거하는 동작은 아직 같지 않으며 제거 메뉴/체크박스를 사용한다.
- Σ 값을 행에 둘 때는 행 필드 뒤에 표시한다. 임의의 중첩 행 위치에 Σ 값을 삽입하는 엔진 동작은 이번에 확장하지 않았다.
- Excel 필드 창의 다섯 가지 창 배치 및 레이아웃 업데이트 연기/일괄 적용 UI는 추가 검수·구현 대상이다.
- 데스크톱 Chromium/WebKit의 모의 입력은 실제 iPhone/Bluetooth 기기 인증과 구분한다.
