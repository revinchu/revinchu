# 복사한 전체 행 삽입

2026-10-07. 기준은 `45745d9`, 작업 브랜치는 `codex/copied-row-insert`이다.

## 사용 동작

행 번호로 10행을 선택하고 Ctrl+C를 누른 뒤 대상 행을 우클릭하면 **복사한 셀 삽입**이 나타난다. 이 명령은 복사한 10행을 대상 앞에 넣고 기존 행을 10행 아래로 옮긴다. 마지막 빈 행도 복사 개수에 포함한다. 같은 명령을 다시 누르거나 F4로 반복할 수 있다.

Ctrl+V와 리본 붙여넣기는 대상 행을 덮어쓴다. 행을 추가하지 않는다. 홈의 삽입 드롭다운에는 복사한 셀 삽입을 추가했고, 전체 행 복사 중 Ctrl+Shift+=도 이 명령을 실행한다. 삽입 탭의 시트 행 삽입은 기존 빈 행 삽입을 유지한다.

## 데이터와 구조

`copySelection`은 전체 행의 선택 높이를 사용 범위로 자르지 않고 `kind: rows`를 보관한다. `snapshotPasteSource`와 `copied-lines.js`는 값·수식·서식뿐 아니라 행 높이, 수동 높이, 행 서식, 숨김 상태 및 먼 열의 희소 서식을 복사 시점에 저장한다. 전체 행의 논리 범위는 XFD까지지만 실제 작업은 사용 열과 저장된 희소 셀만 방문한다. 덮어쓰기에서는 원본의 빈 셀에 대응하는 목적지의 먼 열 값도 지운다.

`preflightPasteSpecial`은 셀 수와 희소 열 한도를 변경 전에 계산한다. 복사 삽입에는 기존 목적지 셀이 아래로 이동하므로 새 행에 적용할 원본의 작업 계획을 사용한다. 시트 마지막 행, 보호 정책, 피벗이나 병합 영역을 가르는 삽입을 먼저 검사한다.

`remapPasteSource`는 원본 clipboard를 바꾸지 않는 파생 snapshot을 만든다. 삽입에 따른 원본 행과 참조 이동을 먼저 반영하고 이후 일반 복사 상대 이동을 적용한다. 수식, 내부 링크, 병합 및 조건부 서식·유효성 검사 참조를 보정한다. 반복 삽입은 이 파생 snapshot을 이어받는다.

`shiftWorksheet`의 단일 transaction 안에서 행 이동, 피벗 렌더 캐시 이동, 붙여넣기, 복사한 높이에 따른 그림 재배치를 처리한다. Undo/Redo는 셀·피벗·개체뿐 아니라 해당 clipboard의 구조 좌표도 복구한다. 사용자가 다른 내용을 새로 복사했으면 오래된 이력이 새 clipboard를 덮지 않는다. Redo는 결과 10행의 선택도 복구한다.

실제 업무 파일은 읽기 전용 로컬 비교에만 사용하며 저장소나 공개 검증 서버에 업로드하지 않는다. 원시 결과·스크린샷은 Git 제외된 D:의 .local/copied-row-insert에 보관한다.
## 실제 문서의 복사 삽입

원본 DA_소재별의 사용 범위 아래 빈 10행(인덱스 344~353)을 복사하고 32행 앞(인덱스 31)에 컨텍스트 메뉴로 삽입한 뒤 F4로 반복했다. 323개 검사가 통과했다. 총 20행·340px가 이동했고 피벗 12개·필터 단추 41개·이미지 20개·전체 개체 43개의 위치/개수가 기대와 같았다. 한 번의 삽입은 한 Undo 단위였으며 두 단계 Undo/Redo로 셀·행 속성·수식·피벗·개체가 복구됐다. 결과 선택은 매번 10행이다.

18,380개 실제 수식의 구조 보정 결과를 비교했으며 이 파일의 해당 삽입 위치 아래를 참조하는 수식은 없어 변경 수식 수는 0이었다. 참조가 실제 바뀌는 경우는 별도 합성 상대·절대·다른 시트·반복 삽입·Undo 후 F4 사례로 검사한다. 실제 입력부터 표시 확인까지 컨텍스트 삽입 223ms, F4 반복 159ms를 기록했다. 이는 같은 로컬 환경의 단일 측정이다. 원본 SHA·수정 시간·크기 불변, 페이지 오류·API 쓰기 0건이고 테스트 브라우저를 종료했다.
