# 03. 스킬 가이드 — WIXEL 에 기능을 넣는 정해진 방법

각 레시피는 지금까지 실제로 써 온 패턴입니다. 새 기능은 가장 가까운 기존 기능을 `grep` 으로 찾아 같은 모양으로 만드세요.

---

## 1. 수식 함수 추가
1. 분류에 맞는 파일에 구현: `src/fx-math.js`(수학) · `fx-stat`(통계) · `fx-text` · `fx-date` · `fx-lookup` · `fx-logic` · `fx-fin` · `fx-web`(웹/구글 시트).
   - 이 파일들은 **`./fxcore.js` 만 import** 합니다.
   - 함수 시그니처: `(args, ctx) => 값`. 인수는 이미 평가된 값(스칼라 · `Range` · 오류 값). 오류는 **return**(throw 아님).
   - 공용 도우미: `toNum`, `toStr`, `collectNums`, `ERR.VALUE/NA/DIV0…`, `Range`, `maxOf/minOf/pushAll`(fxcore.js).
   - 배열에 칸마다 적용되는 스칼라 함수는 `lift(fn, [인수 위치])` 로 감싸면 배열을 넣었을 때 자동으로 펼쳐지고 spill 후보가 됩니다.
   - 참조 그대로 받아야 하면 `refFn`, 인수 평가를 직접 하려면 `lazy`.
2. 각 fx 파일의 내보내기 객체(`MATH` · `STAT` · `TEXT` · `DATE` · `LOOKUP` · `LOGIC` · `FIN` · `WEB`)에 이름을 대문자로 등록 → `formula.js` 의 `FUNCS` 로 모음.
3. 여러 칸 배열을 돌려주면 `formula.js` 의 `ARRAY_FUNCS`(또는 fx-web 의 `WEB_ARRAY`)에 추가 (spill 후보 판단).
4. `src/funcinfo.js` 에 `이름: F('분류', '이름(인수1, [인수2], ...)', '설명.')` 추가 (없으면 `modules.test.js` 실패). 분류는 `CATEGORIES` 참고.
5. 파일 저장 시 `src/xlfn.js` 가 엑셀 2007 기본 함수 목록(`BASE`)에 없는 함수에 `_xlfn.` 접두사를 자동으로 붙입니다(FILTER/SORT 는 `_xlws.`). 엑셀에 없는 WIXEL 전용 함수는 엑셀에서 `#NAME?` 이 되므로, 저장 파일 호환이 중요하면 설명에 적어 두세요.
6. 테스트: 엑셀에서 같은 식을 계산한 값을 정답으로 넣어 `test/*.test.js` 에.
```js
// 예: 테스트 도우미 패턴
const wb = new Workbook();
wb.transact(() => wb.setInput(0, 0, 0, '=MYFUNC(1,2)'));
assert.equal(wb.getValue(0, 0, 0), 3);
```
주의: 테스트에서 셀 키는 `'r,c'` 이고 `setInput`/`setCellData` 에는 **문자열**을 넘깁니다 (`String(v)`).

## 2. 명령(커맨드) · 리본 단추 · 단축키 추가
1. 기능 함수를 `src/app.js` 에 작성 (대화상자는 §3).
2. `COMMANDS` 객체(“`navigator: () => navigatorPane(),`” 근처)에 `이름: () => 함수()` 등록 → `run('이름')` 으로 실행, 빠른 실행 도구 모음 · 스모크 테스트에 자동 포함.
3. 리본: `src/ribbon.js` `TABS` 의 알맞은 탭/그룹에 `large('이름', '아이콘', '표시 글자', { title: '설명' })` 또는 `medium(...)`, 켜짐 상태는 `check('이름', '글자', 'stateKey')` + `ribbonState()` 에 stateKey.
4. 아이콘: `src/icons.js` 에 `이름: svg(\`<path …/>\`, 28)` (색은 `BLUE`/`ACCENT` 변수).
5. KeyTips(Alt 순서): `app.js` `KEYTIPS` 에 `afw: ['명령', '설명']` 형태 키 추가 (탭 글자 + 순서).
6. 직접 단축키: 키 처리부(`k === 'F8'` 등을 찾기)에 한 줄. 엑셀 한국어판 단축키와 충돌 확인.
7. 셀을 바꾸는 명령이면 시트 보호/피벗 잠금을 위해 `protectAction` 매핑과 `PIVOT_LOCKED` 정규식을 확인.
8. `WHATS_NEW` 에 한 줄, 스모크 `bad 0`.

## 3. 대화상자
- `openDialog({ title, body, buttons: [{label, primary, action}], width, modeless, onClose })` (`ui.js`). `action` 이 `false` 를 돌려주면 닫히지 않습니다.
- 간단한 입력 폼은 `formDialog(title, fields, onOk, { note, onChange })` — 필드 type: text/number/select/checkbox/textarea/combo.
- 범위 입력 칸: `refInput(초기값)` — 칸에 초점이 있으면 시트에서 범위를 고를 때 자동 입력(`refPick`). 이 경우 `modeless: true`, `onClose: () => { refPick = null; }`.
- DOM 은 `el(tag, attrs, ...children)`. 대화상자 안의 `input` 에서 키 이벤트가 격자로 새지 않게 `keydown` 에서 `e.stopPropagation()`.
- 결과를 셀에 쓰는 도구는 `writeAnalysis({ rows, heads }, { si, r, c } | { newSheet })` 재사용.
- CSS 는 `styles.css` 끝에 기능별 접두사(`.cons-`, `.ci-`, `.an-` …)로 추가. 여러 줄 `select` 는 `size` 속성 + `.dialog-body select.x { height }`.

## 4. 시트 속성 추가 (sheet prop)
1. `workbook.js` `SHEET_PROPS` 에 이름 추가, 수식 결과와 무관하면 `CALC_NEUTRAL` 에도.
2. 변경은 `wb.setSheetProp(si, 'prop', 값)` (실행 취소 자동, 값은 새 객체로 교체).
3. 행/열 삽입 · 삭제 시 위치가 있으면 `shiftAxis` 에서 `adjustRange` 로 조정.
4. 시트 이름을 담는다면 `renameSheet` 에서 바꿔 줌 (예: 연결된 그림 `linked.sheet`).
5. xlsx 에 엑셀 대응 요소가 있으면 `xlsx.js` 읽기/쓰기 양쪽, 없으면 WIXEL 확장(아래 §5).

## 5. xlsx 왕복 (읽기 · 쓰기)
- 읽기: `readXlsx(bytes) → { data, warnings }`, `new Workbook(data)`. 쓰기: `writeXlsx(wb) → Uint8Array`. 큰 파일은 Async 버전이 같은 제너레이터를 씀.
- 스타일은 `StylePool`(쓰기) / `readStyles`(읽기). 셀 xf 는 행/열 스타일과 섞이지 않게 `ownStyle` 규칙 준수.
- **엑셀에 없는 정보**는 해당 XML 요소의 `extLst` 에 WIXEL 확장으로:
  `<ext uri="{고유 GUID}" xmlns:wx="https://wixel.app/x"><wx:이름 …/></ext>` — 엑셀은 모르는 ext 를 무시합니다.
  기존 예: 확인란(옛 방식), 연결된 그림(`wx:linked`), 계산 항목(`wx:calcItems`), 차트 필터/피벗 연결.
- 읽기 쪽 XML 요소 이름은 접두사 없이 비교(`descendants(el, 'linked')`).
- 반드시 왕복 테스트: `const { data } = readXlsx(writeXlsx(wb)); assert…`.
- 엑셀이 만든 실제 파일과 XML 을 비교할 때: `unzip -o 파일.xlsx -d x/` 후 해당 part 를 확인.

## 6. 피벗 기능 추가
- 계산은 `pivot.js`(DOM 없음)에서: 정의 필드 추가 → `normalizeDef` 가 유지하는지 확인 → `resolvePivot`/`computePivot` 에 반영 → `pivotDefKey` 로 캐시 키에 포함(제외 목록에 넣지 말 것).
- 원본 데이터 변형(그룹 · 계산 항목 · 파생 필드)은 **큐브 변환**으로: `withDerivedFields`, `withCalcItems` 처럼 메모이즈된 새 `Cube` 를 돌려줌.
- 그리기 · UI 는 `app.js`: `pivotHere()`, `pivotDefV2(entry.def)`, `setPivotDef(entry, def)`(실행 취소 · 다시 그리기), `refreshPivotPane(true)`, 활성 필드 `pivotActiveField(entry)`, 칸의 항목 `pivotItemAt(r, c)`.
- 격자 칸의 `role` 로 위치 판단: `rowItem:d`, `rowGroup:d`, `colItem:d`, `data:i`, `grandLabel` …
- xlsx: 캐시 읽기 `readPivotCache`(+ `readCacheRecords` 스냅숏), 정의 읽기는 `xlsx.js` 에서 `pivotTableDefinition` 을 검색, 쓰기 `buildPivotCache` + 피벗 정의 XML. GETPIVOTDATA 는 `pivotLookup`.
- 검증: 단위 테스트 + 실제 파일 `tools/pvcmp.mjs` 수정 전/후.

## 7. 성능 규칙 (리뷰 때 확인)
- 데이터 크기 반복에서 `Math.max(...a)`, `push(...a)`, `[...map]` 복사, 문자열 키 `cells.get('r,c')` 금지.
- 여러 칸 쓰기는 `wb.transact` 하나로. 피벗 출력도 transact 안에서.
- 핫 경로에서 throw/catch 금지. 정규식 · 함수 객체는 반복 밖에서 만들기.
- 100만 행 시트에서 측정: 열기 시간(`tools/brcheck.mjs` 의 `loaded … ms`), 슬라이서 클릭, 정렬.

## 8. 엑셀과 다른 값 디버깅 레시피
1. `node tools/check.mjs 파일` 로 어느 시트 · 함수인지 그룹별 첫 예시를 봄.
2. 진단 스크립트(Node)로 그 칸만:
```js
import { readFileSync } from 'node:fs';
import { readXlsx } from '../src/xlsx.js';
import { Workbook } from '../src/workbook.js';
const A = new Workbook(readXlsx(new Uint8Array(readFileSync('파일.xlsx'))).data);
const si = A.sheetIndexByName('시트');
console.log(A.getCell(si, r, c).raw, A.getCell(si, r, c).cached); // 수식 · 엑셀 저장값
A.invalidate();                                                      // (진단에서만) 전부 다시 계산
console.log(A.getValue(si, r, c));
```
3. 피벗이면 `pivotSourceData(A, def)` → `resolvePivot` → `computePivot` 으로 격자를 찍어 엑셀 칸 값과 비교 (`def` 는 `A.sheets[si].pivot` / `pivotsExtra`).
4. 원인을 고친 뒤 **같은 종류의 다른 파일들**로 회귀 비교. 이전에 "맞던" 파일이 사실 파일 저장값을 보여 주고 있었을 수 있으니, 숫자가 바뀌면 이유를 확인.

## 9. 템플릿 추가
- `src/templates.js` 의 빌더 함수(`new S('시트 이름', {tab})`.title(…).row(…)…) 패턴을 복사, `TEMPLATES` 배열에 `{ id, cat, name, desc, color, build }`.
- 외부 파일 템플릿은 `file: 'assets/…xlsx'` + `build.mjs` 의 자산 복사 목록.
- 남의 템플릿 파일을 그대로 넣지 말 것(저작권). 수식은 엑셀 호환 함수만.
