# 79. 브라우저 호환성과 입력·저장 보강

기준은 공개 수정본 62aa44e이다. 이번 작업은 재현한 저장·클립보드·팝업 오류를 수정하고 Chromium·WebKit·Firefox 엔진에서 확인한다. 이전 11개 실제 업무 파일의 Excel 비교 결과와 이번 합성 브라우저 회귀의 범위를 합쳐서 주장하지 않는다.

## 수정한 문제

1. **자동 보관 읽기 완료 오판:** IndexedDB 요청 성공 뒤 트랜잭션이 중단되면 종전에는 읽기 성공으로 반환하거나 대기했다. 읽기는 트랜잭션 완료를 기다리고 중단은 오류로 반환한다. WebKit에서는 요청 오류가 먼저 발생하여 tx.error가 아직 null일 수 있어 실제 요청의 오류를 보존하고, 쓰기 실패는 abort 확인 뒤 반환한다.
2. **WebKit Blob 보관 실패:** 새 비영구 WebKit 프로필에서 Blob을 IndexedDB에 넣을 때 UnknownError가 재현됐다. 해당 Blob 준비·저장·복제 오류에만 한 번 바이트 조각으로 재시도한다. 자동 보관과 작은 문서의 보관함·버전 기록 모두 적용하며 문서·목록·이력의 원자적 확정과 기존 세대 보존은 유지한다. 할당량·취소·충돌 오류를 이 우회로 숨기지 않는다. 기존 Blob 저장본도 읽는다.
3. **파일 쓰기 준비 중 취소 지연:** createWritable 응답이 늦어도 취소를 즉시 처리한다. 뒤늦게 열린 임시 쓰기 대상은 abort하고 본문 생산을 시작하지 않는다. 실제 디스크 확정 단계의 취소 정책은 유지한다.
4. **늦은 붙여넣기가 새 작업을 덮어씀:** 클립보드 권한 응답을 기다리는 동안 같은 시작 셀에서 범위를 넓히거나 값을 편집하면 오래된 응답이 새 범위를 덮어썼다. 문서·시트·편집 버전·범위·선택 종류·복사 원본·개체/편집 상태 및 최신 요청을 확인한다. 응답 순서가 뒤집힌 두 요청도 이전 응답을 무시한다.
5. **복사 성공의 잘못된 표시:** 상태 표시줄 합계와 공유 링크 등이 클립보드 권한 거절에도 복사 성공으로 표시되던 경로를 수정했다. 실제 완료 후 성공을 알리고, 거절·API 부재 시 읽기 전용 선택 영역으로 수동 복사한다. 코드·경로 복사도 연결했다. 재시도 execCommand가 false이거나 예외이면 성공으로 세지 않는다.
6. **모바일 최적화 OFF의 팝업 잘림:** 화면 키보드나 핀치 확대로 보이는 영역이 줄어도 일반 레이아웃의 메뉴는 전체 화면 크기를 사용했다. 모든 밀도 모드에서 visualViewport 경계를 적용하며 하위 메뉴·추적 팝업도 제한한다. 화면을 다시 넓히면 작성된 원래 크기 제한으로 복원한다. 필터 최소 너비는 배치 계산 전에 전달한다.

## 검증 원칙

새 프로필과 합성 문서를 사용하고 외부 API 쓰기를 차단한다. 클립보드 권한과 일부 API 부재는 명시적으로 모의한다. 파일 다운로드는 실제 anchor 다운로드 이벤트의 바이트를 독립 파서와 같은 브라우저의 파일 열기로 확인한다. 가상 파일 핸들·합성 취소와 실제 OS 저장 창은 구분한다. 작은 화면과 visualViewport 변화는 모의 환경이며 물리 iPad·iPhone·Android의 OS 키보드나 Bluetooth 검증이 아니다.

초기 실패 기록을 남긴 뒤 같은 검사로 재확인한다. 최초 손바닥 검사의 잘못된 #view 선택자는 검증 도구 오류이며 제품 결함으로 세지 않는다. 최종 수치와 배포 결과는 검증 완료 뒤 아래에 기록한다.

## 한계와 다음 검수

- 메모리 절감은 구간 저장·읽기와 특정 중복을 줄인 것이다. 보관함의 1MiB 조각 배열도 전체 스냅샷 바이트 합계는 메모리에 있으며, 임의 20GB 문서 지원을 보장하지 않는다.
- DecompressionStream이 없는 구형 환경은 새 비압축 저장을 지원하지만, 과거 gzip 보관본은 최신 브라우저 안내와 함께 중단한다. 압축 바이트를 JSON 원문으로 오인해 읽지 않는다.
- 실제 iPad/Safari, iPhone과 Android 기기, OS 파일 선택기·다운로드 보관 위치·Bluetooth 입력은 별도 실기 검수가 필요하다.
- 이전 검수의 피벗 일부 표시·순서, 자동 행높이·여백 정밀도 차이는 이 브라우저 수정으로 해결했다고 표시하지 않는다.

## 참고한 브라우저 문서

클립보드의 권한·사용자 동작 제한은 [WebKit Async Clipboard API](https://webkit.org/blog/10855/async-clipboard-api/)를 참고했다. 키보드·핀치 확대가 레이아웃 영역과 별도로 보이는 영역을 줄이는 특성은 [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)에서 확인했다. 이번 오류의 판정 근거는 위 문서만이 아니라 아래 로컬 재현 결과다.
