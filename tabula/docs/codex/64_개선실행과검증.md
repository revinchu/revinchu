# 64. 개선 실행과 검증

2026-10-03. [63번 기획·설계](63_개선기획과설계.md)를 제품 변경 전에 작성한 뒤 첫 배치를 실행했다. 기준은 `31bc900`. 조사 중 사용자가 추가로 보고한 iPhone Safari의 **위셀 셀→셀 Ctrl+C/V 실패**를 UX-03으로 포함했다. 실제 OS 홈 화면 이탈은 원인 확정·해결 완료로 표시하지 않는다.

## 구현 결과

복사 후 다른 앱으로 이동하거나 문서를 바꾸면 내부 사본의 자동 우선권을 해제한다. 셀 편집/한글 조합/대화상자의 텍스트 복사는 native 경로를 유지한다. 외부 앱의 붙여넣기는 실제 clipboard event의 내용을 사용한다. 모바일 Ctrl+C/V 검사에서는 사용자 OS 클립보드를 읽거나 쓰지 않았다.

## 자동 보관 비용 비교

`tools/snapshot-memory.mjs`는 합성 300,000셀, 같은 PC의 별도 Node 프로세스에서 경로별 3회 실행한다. 소스의 실제 `serialize()` 경로와 새 Blob 경로를 비교하며 JSON 바이트 SHA-256이 모두 같다. 날짜/스타일/수식 저장값/개체/한글·이모지/정렬 블록은 별도 내용 검사로 대조한다.

| 지표(3회 중앙값) | 기존 전체 복제 | 새 Blob |
|---|---:|---:|
| 직렬화 | 1,425ms | 999ms |
| 추가 관측 JS heap | 128.8MiB | 37.4MiB |
| 동일 JSON 바이트 | 34,578,241 | 34,578,241 |

heap은 4,096셀마다와 완료 시 관측한 값이며 진정한 최대 메모리가 아니다. Blob의 native 메모리/array buffer와 RSS는 별도 기록했고 이를 JS heap에서 빠졌다는 이유로 0이라고 계산하지 않았다. 실제 iPhone 메모리·p95 입력 지연·OS 종료 해결의 근거가 아니다. 첫 시도에서 시간 회귀가 보여 임시 셀 사전 생성도 제거한 뒤 재측정했다.

## 검증 방법과 범위

- `test/snapshot-blob.test.js`: 기존 직렬화와 byte 동일, 모델/Undo 불변, 스냅숏 뒤 문서 교체, ID만 교체한 사본, JSON 블록 복원/Undo, 서로게이트 경계, gzip 없음, 스트림 경계·실패.
- `tools/library-atomic.mjs`: 실제 격리 IDB의 실패/이력/CAS/Blob·기존 JSON 복원. Chromium/WebKit 각각 70검사 통과.
- Windows WebKit의 임시 프로필은 앱 코드 없는 `IDB.put(new Blob(['abc']))`도 error=null로 실패했다. 같은 최소 검사가 새 persistent 프로필에서는 성공하여 이 저장 검사는 **D:의 새 테스트 전용 프로필**로 실행했다. 임시 프로필 실패를 성공으로 기록하거나 사용자 Safari 문제로 일반화하지 않는다.
- `tools/library-recovery.mjs`: 기존 UI 충돌 사본 복구 4사례·25검사 통과.
- `tools/command-recovery.mjs`: F4 정상/보호/서식·Undo, 저장 실패/직렬화 실패/창·저장·온라인 응답 중 문서 전환. 기준 소스는 보호 시트 추가와 실패 후 값 42→777 교체를 재현했다. 수정 소스 양 엔진 각각 12사례 통과.
- `test/xlsx-preflight.test.js`, `tools/xlsx-safety-fixtures.mjs`: 표준 logBase 및 TABLE 값 전환 이력·블록 한도. 실제 Excel 별도 인스턴스의 합성 로그 축 5종과 값 변환 1종으로 표준 재열기·재저장 검사. 이는 로그 축의 위셀 화면 정확성 검사가 아니다.
- `tools/mobile-clipboard.mjs`: 권한 거절/브라우저 native 이벤트 부재에도 내부 셀 복사, Control/Meta, 화면/자동/외부 키보드, cut/Undo, 이벤트 중복, 시트/문서 전환, 보호/최종본/읽기 전용, 텍스트 편집/IME, 외부 자료. 물리 Bluetooth 이벤트와 OS 시스템 화면은 미검증.
- 실제 업무 파일 2개와 실제 Excel 피벗 합성 1개는 원본을 수정하지 않고 수정 전후 `check`로 수식/왕복을 비교했다. 개별 원본 이름이나 내용을 저장소에 포함하지 않는다.

전체 Node·최종 배포 번들·공개 자산 검증 결과는 아래 확정 기록에 추가한다. 소스 모듈 주입 검사는 최종 번들 검사로 세지 않는다. 저장 문제에 대한 폭넓은 기존 근거는 54~62번 문서와 구분한다.
