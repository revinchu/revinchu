# 병합 제목의 행 높이와 글꼴별 세로 위치

## 확인한 원인

- 185% 사용자 캡처에서 첫 행은 WIXEL 33장치 픽셀, Excel 46장치 픽셀이었다. 각각 모델 높이 18px와 25px에 대응한다. 다음 행들은 같은 높이여서 전체 확대 비율의 차이가 아니다.
- 원본 XLS의 첫 행 높이는 18.75pt(25px)이다. 현행 가져오기는 이를 보존하고, 새로 가져온 문서의 브라우저 저장·복원도 25px를 유지한다.
- 병합 제목을 F2로 편집하면 이전 자동 높이 계산은 병합 셀을 제외하고 기본 높이 18px로 줄였다. 행 경계 더블클릭과 리본 서식 메뉴는 측정 전에 높이를 초기화하기도 했다.
- 문서 기본 글꼴의 세로 보정값이 모든 셀에 적용됐다. 검증 PC에서 맑은 고딕은 −0.045em, 돋움은 +0.025em으로 달랐다. 돋움 14pt 제목에서는 185% 기준 약 2.42 CSS px 차이다.

## 변경

- 병합 범위와 겹치는 모든 행의 기존 높이를 자동 계산의 하한으로 유지한다. 같은 행의 비병합 큰 글자에 필요한 증가는 허용한다. 병합하지 않은 행은 일반 자동 증가·축소를 유지한다.
- 자동 편집은 수동 행 높이를 보존한다. 명시적 자동 맞춤은 수동 플래그를 해제하면서 기존 높이를 측정에 사용한다. 리본 서식 메뉴는 공통 자동 맞춤 명령으로 연결한다.
- 셀의 글꼴별 세로 보정값을 계산·캐시한다. 글꼴 준비가 끝나면 캐시와 화면을 갱신한다. 글꼴 크기·행 높이·저장 서식은 화면 보정을 위해 변경하지 않는다.

## 기존 브라우저 문서

구버전 가져오기 또는 이전 자동 맞춤에서 이미 없어진 높이는 저장본만으로 정확히 복원할 수 없다. 임의로 모든 병합 행을 늘리지 않는다. 현재 편집 내용을 먼저 별도 저장하고 원본을 다시 열거나, 이 문서는 첫 행의 **행 높이(포인트)를 18.75**로 설정하면 편집 내용을 유지하며 높이를 복원할 수 있다.

## 검증

- 전체 단위 테스트 714/714, 일반·Cloudflare 빌드 통과. 최초 무제한 병렬 실행은 빌드 자식 프로세스의 60초 제한에 걸린 1건 외 713건 통과했고, 동시 실행 수 2로 제한한 전체 재실행은 모두 통과했다.
- 최종 번들 리본 스모크 324명령, 오류 0. 확대 전환 96조합·3,266검사 통과.
- 소스와 최종 번들에서 신규 9/9검사 통과, 페이지 오류·원격 쓰기 0건. `tools/merged-row-layout.mjs`는 115·185·400%의 글꼴별 보정, F2 편집·실행 취소·다시 실행, 자동 맞춤 명령·리본·행 경계 더블클릭, 일반 행 증가/축소, 수동 높이, 여러 행 병합, 내보내기 모델 불변을 확인한다.
- 실제 XLS를 다시 연 소스 화면의 DPR1/185%에서 첫 행 경계는 46px, 제목 글자 높이는 31px로 참조 Excel 캡처와 같다. 위 여백은 8px로 Excel의 9px보다 1px 작고, 아래 여백은 6px로 Excel의 5px보다 1px 크다. 이전 캡처의 위 0px·아래 2px 잘림이 해결됐다. 모든 글꼴/환경의 픽셀 완전 일치를 주장하지 않는다.
- 개인 업무 파일·사용자 캡처는 저장소와 공개 서버에 포함하지 않는다.
