# 52. 모바일 한 줄 도구와 우클릭 서식 (2026-10-03)

기준: `codex/pivot-report-filters`의 `14a18625a034e420c59dc45e810ae31eea838cab`. 작업 브랜치: `codex/mobile-compact-ui`.

## 표시와 입력 계약

- `app-header`는 데스크톱에서 `display:contents`, 모바일에서 한 줄 flex다. 기존 titlebar/ribbonTabs ID와 명령 바인딩을 보존하며 제목·브랜드·저장 상태는 모바일에서 숨긴다. 모드/작업 도구 버튼은 고정하고 바로 뒤 파일 메뉴부터 탭만 가로 스크롤한다.
- footer는 시트 탐색·시트 탭·추가와 보기·배율을 한 줄에 둔다. 준비·계산 상태·선택 통계는 모바일에서 숨긴다. 낮은 가로 화면에서도 배율/보기 단추가 사라지지 않는다. 계산 상태와 저장 기능은 작업 도구에서 접근한다.
- 기본 촘촘한 밀도는 상단/하단 각각 28px, 리본 제어 24px, 글꼴 입력 92px/크기 입력 36px, 글자 11px다. 여유로운 밀도도 한 줄 구성을 유지하며 제어를 28px로 제공한다. 수식 입력은 16px를 유지한다.
- 이전 compact 390×844 화면의 격자 588px가 680px로, 320×640은 384px가 476px로 늘었다. 실제 화면 캡처·동일 viewport의 수정 전/후 기하를 비교했다.
- 모바일 탭/리본/QAT/시트 탭에서 수직·수평 마우스 휠을 가로 이동으로 처리한다. line/page delta를 픽셀로 변환하고 양 끝에서 격자로 스크롤이 새지 않게 한다. 이미 처리된 wheel, Ctrl/Meta/Alt 및 초점을 가진 입력은 건드리지 않는다. 터치·트랙패드의 기본 이동은 유지한다.
- 셀 미니 서식은 폭 322px, 입력/아이콘 높이 23px의 두 줄이다. 320px에서는 viewport 안의 312px로 줄이며 작은 화면에서도 겹치지 않는다. 미니 영역의 상시 접근키 캡션과 Alt 배지는 만들지 않고 aria 라벨과 키보드 동작은 유지한다. 스크롤 밖 도구도 Tab/방향키로 접근한다.
- 하위 메뉴는 접근키 캡션을 붙인 뒤 전체 viewport 폭에서 실제 크기를 재고 배치한다. 오른쪽 가장자리의 auto-width 축소/줄바꿈 때문에 아래로 벗어나던 초기 배치를 수정했다.
- 앱 문서의 capture contextmenu는 `preventDefault`만 호출한다. 입력란·메뉴·직접 body에 붙는 팝업도 포함하고, 전파는 유지해 앱 자체 메뉴가 열린다. 기존 브라우저 메뉴 허용 체크는 제거했다.
- 모바일 모드/밀도/배치는 통합 문서 값·스타일·저장 zoom·Undo를 변경하지 않는다. 전체화면 native/fallback에서 종료 버튼이 탭을 덮지 않게 공간을 남기며, 읽기 전용 보기에는 빈 헤더가 남지 않는다.
