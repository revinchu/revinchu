# 59. 초록색 상단 메뉴의 마우스 이동

기준: `5a8a4eccc0c2ce45c8eae90517a1374148133f63`, 브랜치 `codex/mobile-header-drag`.

## 변경

기존 상단 메뉴 탐색은 모바일 작업 모드와 Pointer Events로 시작한 제스처에만 연결되어 있었습니다. Mouse Events만 전달되는 경로는 가로 이동이 시작되지 않았고, 모바일 모드를 끈 화면의 상단 메뉴는 스크롤 컨테이너가 아니었습니다.

초록색 상단 메뉴에 가로 넘침 처리를 적용하고 모바일 설정과 관계없이 좌우 드래그·휠 탐색을 연결했습니다. 모바일의 회색 리본·빠른 실행·시트 탭도 같은 Mouse Events 호환 경로를 사용합니다. 터치의 기본 스와이프는 유지합니다.

4px 미만의 누르기는 원래 메뉴 클릭으로 처리하고, 끌기는 메뉴를 실행하지 않습니다. 포인터 캡처로 메뉴 줄 밖으로 이어지는 이동을 받으며, 양 끝에서 즉시 반대로 움직일 수 있습니다. 호환 마우스 이동이 이어져도 같은 거리를 두 번 이동하지 않습니다. Escape·창 포커스 이탈·포인터 취소·창 크기 변경으로 종료합니다. 끌기가 더블클릭으로 전달되어 리본을 접지 않도록 구분합니다.

접근키나 모바일 전체 메뉴로 탭을 선택하면 해당 탭이 보이는 위치로만 스크롤합니다. 일반 목록 재생성이나 수동 드래그 때는 탐색 위치를 유지합니다.

셀·수식·서식·저장 파일·선택·Undo를 바꾸지 않는 화면 탐색입니다. Excel 파일 모델이나 입출력 코드를 변경하지 않습니다.

## 수정 전 재현

이전 커밋을 격리 브라우저에만 제공해 Chromium/WebKit 양쪽에서 확인했습니다. Mouse Events만 전달한 드래그는 이동량 0이었고, 모바일 OFF 390px에서는 `overflow:visible`이라 스크롤되지 않았습니다. 첫 클릭 뒤 두 번째 6px 드래그가 더블클릭으로 전달되면 리본이 접혔습니다. 일반 탭 선택 후 목록 재생성은 스크롤 위치를 유지했으므로 해당 경로는 변경하지 않았습니다.
