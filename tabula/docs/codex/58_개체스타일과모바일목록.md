# 58. 표·피벗·슬라이서 스타일과 모바일 시트 목록

## 문제와 변경

모바일 리본의 갤러리는 높이 24/28px 안에 이전·다음·더 보기를 세로로 배치하여 실제 메뉴 버튼을 잘랐습니다. 모바일에서만 세 버튼을 한 줄로 배치하고 메뉴 접근성 정보를 제공합니다.

사용자 지정 표 스타일은 XLSX에서 읽은 뒤 기본 스타일 이름으로 바뀌었고, 피벗은 현재 개체의 일부 서식만 보존했습니다. 슬라이서의 ‘새 스타일’은 이름 없는 개체별 색 재정의였습니다. 이제 통합 문서의 `objectStyles`가 표/피벗 공용 스타일과 슬라이서 스타일 정의·기본값을 보관하고, 개체의 `styleElements`가 실제 화면에 적용됩니다. 사용하지 않는 스타일도 표준 OOXML에 저장합니다.

세 갤러리에서 새 스타일, 사용자 지정 스타일 관리, 지우기를 제공합니다. 스타일 요소 목록에서 글꼴·채우기·테두리·표시 형식 및 줄무늬 크기를 편집합니다. 생성은 목록에 등록하며, 갤러리에서 눌러 현재 개체에 적용합니다. 수정은 같은 이름을 사용하는 개체에 함께 반영하고, 삭제는 기본 스타일로 되돌립니다. 만들기/편집/복제/삭제/적용/기본값 변경과 개체 변경은 각각 실행 취소할 수 있습니다. 보호된 사용처가 있으면 공유 스타일 수정·삭제를 차단합니다.

표 크기 조정·필터 단추·표 슬라이서 삽입은 기존 리본에서 동작하며 실제 모바일 조작으로 확인했습니다. 크기 조정과 슬라이서 삽입은 대화상자를 연 뒤 문서·권한이 바뀌면 적용하지 않습니다.

스타일 적용만으로 가져온 수식의 저장값이 다시 계산되지 않도록 표 서식 변경 경로를 분리했습니다. 같은 트랜잭션에서 표 구조까지 변경하면 정상적으로 재계산하며, 실행 취소·다시 실행에도 같은 구분을 유지합니다.

가져온 피벗은 기존 스타일의 시각 서식이 셀별 재정의로 남아 새 스타일을 가리던 문제를 수정했습니다. 생성 스타일과 같은 부분만 상속으로 돌리고 직접 지정한 색·테두리·숫자·맞춤은 보존합니다. 값 필드에 별도 숫자 서식이 없으면 사용자 스타일의 표시 형식을 사용합니다. 스타일 편집의 확인만 눌러도 상속 값이 바뀌던 경로는 변경한 속성만 기록하도록 고쳤습니다. 명시적 굵기 해제·검정·채우기 없음도 유지됩니다.

슬라이서 XLSX 스타일은 표준 `dxfs`와 x14 전용 `dxfs`를 구분합니다. 실제 Excel이 저장하는 확장 순서·URI·보조 tableStyle 요소 수와 일치시켜, 사용자 지정/지우기 파일을 복구 없이 열고 다시 저장할 수 있게 했습니다. DXF의 글꼴·채우기·무늬·그라데이션·테두리·숫자 형식과 사용하지 않는 스타일 및 기본 스타일도 보존합니다.

## 아이폰에서 시트 메뉴 사용 중 OS 홈 화면으로 이동

사용자는 Safari + Bluetooth 마우스를 사용하며, ‘홈’은 위셀 리본이 아닌 아이폰 앱 아이콘 화면이라고 확인했습니다. 이 현상 자체는 데스크톱 WebKit에서 재현되지 않았습니다. 앱 코드의 해당 경로에 창 닫기/외부 이동 명령은 없습니다.

시트 숨기기 취소와 이동/복사에 있던 `select size multiple`을 앱 내부 목록으로 교체해 iOS 네이티브 선택기 호출을 제거했습니다. 마우스·터치·방향키·Home/End·Space·Enter를 지원하고, 빈 선택을 막으며, 문서와 시트·버전·권한을 재검증합니다. 복사본을 최종 위치에 삽입하여 복사/위치/Undo/Redo를 한 트랜잭션으로 복원합니다.

이는 의심 경로를 제거한 보완이며 **아이폰 OS 홈 이탈의 원인을 확정하거나 실기기 해결을 검증한 결과가 아닙니다**. 실제 아이폰·Bluetooth 마우스에서의 재검증이 필요합니다.

## 동등성의 범위

이번 결과는 표·피벗·슬라이서 스타일과 지정한 모바일 메뉴 경로를 검증한 것입니다. Excel의 전체 기능·모든 레이아웃·모든 파일과의 100% 동등성 인증은 아닙니다. 데스크톱 WebKit 모바일 입력 검사를 실제 iPhone Safari 또는 Bluetooth 장치 검사로 표현하지 않습니다.
